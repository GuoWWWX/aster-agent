# 群聊协作规范

2026-10-18。适用于当前小团队，沿用团队可编辑的协作指令和已有工具，不增加另一套聊天或调度引擎。

## 消息怎么处理

@ 是收到消息的通知，不等于必须确认。成员先读取当前原消息，复用自己已经读过的背景，只补读必要的新讨论。Agent 基础角色说明能力，本群身份与当前明确委派确定工作范围；用户指定的回复方式优先。

| 当前情况 | 默认做法 |
| --- | --- |
| “大家好”“你们好”等面向全群的问候 | 协调者选择所有活跃成员，各自并行自然回应，不由负责人代答或汇总 |
| 点名某人的问候 | 只交给被点名的成员 |
| 普通提问或讨论需要不同专业角度 | 协调者直接选择多位相关成员，无须用户逐个 @，不固定转给负责人 |
| 用户直接提问、问候，或明确要求公开回答 | 对应成员在群里自然回答 |
| 实现细节、接口确认、内部验收材料或完成反馈 | 私下发给相关成员或负责人 |
| 关键进展、影响他人的决策或阻塞 | 在群里简短同步一次 |
| 纯信息同步，无待回答问题或新动作；已有完整公开答案 | 不再向他人发消息，私有执行简短结束 |

工具过程留在执行者的普通对话。私聊不自动广播；群通知也不自动唤醒全员。不要互发“收到”，不要重复已投递的分工，不靠轮询制造进展。只有步骤变化时才更新执行清单。

## 任务怎么完成

1. 群聊归属 Agent 负责分流，未点名的新工作默认交负责人。明确 @、引用或已有任务补充遵循既有路由与任务关联。
2. 负责人查重并维护同一任务，公开说明职责与必要分工。公开请求已经完成投递，不再私信重复派一次；需要私下交办时，公开职责说明使用通知。
3. 专业成员只完成自己的分工，可以在该范围内私下协作。独立工作并行；依赖产出的验收在产出就绪后安排。发现缺陷交原实现者修复，其他人不另造产品。
4. 内部结果沿原完成回执反馈。负责人读取实际证据，完成剩余验收后在群里交付复杂任务。成员已经公开完整回答的简单问题，不机械复述；用户明确要求负责人汇总时仍完成该项要求。

交付应给出可查看的成果、可点击的文件引用和真实验证结论。原作者先发布文件引用，负责人按来源消息转交原文件，不复制到自己的工作区。全局团队的相同相对路径不是共享文件；独立测试样本保留来源且不能作为第二份产品交付。缺少输入时公开阻塞并保留原任务，用户补充后继续；运行结束不代表验收通过。

## 工具用法

- 公开发言复用 `post_team_message`。告知进展、阻塞与共同决策用 `intent=notify`；还要继续干活时加 `continueWork=true`。仅在接收者需要行动时使用 `request` 和明确成员。
- 私下发送统一复用 `send_agent_message({conversationIds: [...], content, expectReply})`。一位成员用单元素数组，同一内容给多人用同一次调用，不同分工分别调用。最多 32 项，重复成员只投递一次；全批校验并保存后才唤醒，任一无效则整批不发。
- 需要答案或工作的交办用 `expectReply=true`；结果、进度和通知用 `false`。已有自动完成回执时，不再为相同结果另发请求。
- 接收方保持自己的对话与上下文，私信只继承同群来源定位及当前分工，不复制群历史、不接管整个用户任务。需要更多证据时按预算读取。
- 旧单接收者参数仅兼容已有调用记录；当前模型只看到数组工具。受管 WorkItem 的协作计划工具只提供给其运行中的根负责人，普通群聊不需要它。
- 自动往返保留上限：普通讨论 4 层，关联同群任务的公开及私下交接统一 12 层；不是无限循环。记录验收时使用实际消息来源，来源错误只修正引用，不重做成果。

## 参考与验证方法

[AutoGen 消息与通信](https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/framework/message-and-communication.html) 区分请求回复与单向发布；这里沿用现有 request/notify 与完成回执，避免通知形成确认循环。[Anthropic 多 Agent 实验](https://www.anthropic.com/engineering/multi-agent-research-system) 强调明确目标、输出与任务边界；这里用本群身份、独立验收和原文件交付约束重复工作。并行沿用现有成员运行机制。

后台验收覆盖：信息同步不公开确认、数组私信并发征询、缺少输入公开阻塞、补充后继续同一任务、独立验收及负责人交付。失败轮次如实保留，不计入通过；具体实验记录见[群聊实施记录](./27-任务上下文目录与团队群聊方案及推演.md#24-复杂任务的私下协作与群内可见性)。
