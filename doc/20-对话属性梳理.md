# 对话属性梳理

## 1. `conversations` 最终建议表（设计目标）

本节只列最终建议直接保存在 `conversations` 表中的业务字段。应用接口继续使用驼峰名称，SQLite 使用蛇形列名；JSON 采用 `TEXT` 保存并在读写边界进行 Schema 校验，不使用 BLOB。当前代码尚未按本表完成迁移，差异见第 5 节。

### 1.1 创建后固定的字段

| 属性 | 应用字段 | SQLite 列 | 类型 | 可空 | 规则 |
| --- | --- | --- | --- | --- | --- |
| 对话 ID | `id`；引用参数使用 `conversationId` | `id` | `TEXT PRIMARY KEY` | 否 | 系统生成后不变；改名、切换模型和返工仍是同一条对话 |
| 创建时间 | `createdAt` | `created_at` | `TEXT` | 否 | 保存 ISO 8601 时间，创建后不变 |
| 父级对话 | `parentConversationId` | `parent_conversation_id` | `TEXT`，外键到 `conversations.id` | 是 | 顶层为空；子对话创建后固定，不因其他对话给它发消息而改变父级 |
| 对话类型 | `mode` | `mode` | `TEXT` | 否 | `persistent` 表示长期对话，`subagent` 表示临时 Subagent；完成或返工不改变类型 |

### 1.2 使用过程中可变的字段

| 属性 | 应用字段 | SQLite 列 | 类型 | 可空 | 规则 |
| --- | --- | --- | --- | --- | --- |
| 对话标题 | `title` | `title` | `TEXT` | 否 | 用户改名或系统自动命名；与 Agent 配置名称分开 |
| Agent 配置引用 | `agentId` | `agent_id` | `TEXT` | 存量兼容可空；新建须解析出有效值 | 表示使用哪个已配置 Agent；切换只影响后续 Run |
| 对话头像 | `avatarIcon` | `avatar_icon` | `TEXT` | 是 | 保存对话当前视觉身份；Subagent 使用自己的像素头像，不因返工换成 Agent 配置头像 |
| 项目 | `projectId` | `project_id` | `TEXT`，外键到 `projects.id` | 是 | 无项目对话为空；项目根目录通过 `projects.root_path` 获取，不在对话表重复保存 |
| 模型选择 | `modelSelection` | `model_selection_json` | `TEXT`（JSON） | 存量兼容可空；新建须解析出有效值 | 整体保存全局唯一的 `modelId` 与 `reasoning`；供应商通过 `modelId` 解析，不在对话表重复保存 |
| 权限模式 | `permissionMode` | `permission_mode` | `TEXT` | 否 | 保存对话当前审批偏好；实际执行值仍进入 Run 快照，会话临时授权不写入该列 |
| 对话／Agent 状态 | `status` | `status` | `TEXT` | 否 | 所有对话共用一套状态字段，不为 Subagent 单设任务状态 |
| 状态更新时间 | `statusChangedAt` | `status_changed_at` | `TEXT` | 否 | 状态发生合法转换时由系统更新 |
| 结束时间 | `endedAt` | `ended_at` | `TEXT` | 是 | 进入已结束状态时写入；任务完成但仍可返工时保持为空 |
| 归档时间 | `archivedAt` | `archived_at` | `TEXT` | 是 | `NULL` 表示未归档，不再重复保存 `isArchived` |
| 置顶顺序 | `pinOrder` | `pin_order` | `INTEGER` | 是 | `NULL` 表示未置顶，不再重复保存 `isPinned` |
| 最近更新时间 | `updatedAt` | `updated_at` | `TEXT` | 否 | 任意持久属性改变时更新 |
| 最近活动时间 | `lastActivityAt` | `last_activity_at` | `TEXT` | 否 | 收发消息、执行开始或完成时更新，用于最近对话排序 |

### 1.3 不进入 `conversations` 表的相关信息

| 信息 | 表达方式 | 原因 |
| --- | --- | --- |
| 项目根目录 | `projects.root_path` | `project_id` 已能定位项目；根目录只保存一份，项目移动时无需批量修改对话 |
| 无项目对话临时工作区 | 独立工作区记录并由 ID 引用 | 不把另一个绝对根路径重新塞回对话表；未绑定工作区时不开放文件和命令工具 |
| 团队实例和职责 | 团队成员关系表中的 `team_instance_id`、`team_role` | 团队归属是关系，不是对话本体字段 |
| 未读状态 | 阅读状态记录保存 `last_read_message_id`，接口计算 `hasUnread` | 避免同时维护阅读位置和布尔值产生不一致 |
| 当前 Run 和最近执行结果 | 从 `runs` 表按对话及状态查询 | `activeRunId`、最近成功或失败是执行投影，不是对话本体字段 |
| Run 的模型、思考、权限及工具快照 | `runs.model_id`、`runs.reasoning_json` 与 `runs.execution_snapshot_json` | 前两项是本次执行的直接字段；完整解析结果和工具／权限配置仍保留为不可变快照 |
| Subagent 列表和数量 | 查询 `parent_conversation_id + mode`，活跃数量再筛选 `status` | 不存 `subagentTaskStatus` 或 `activeSubagentCount` 两套重复事实 |
| 删除及清理进度 | 可恢复的删除／清理任务 | 用户删除与后台文件清理属于独立生命周期，不混入正常对话状态 |

### 1.4 模型选择与 Run 快照的 JSON 边界

协议层使用一个 `modelSelection` 对象；目标对话表也整体保存这个对象：

```sql
model_selection_json TEXT
```

其中的 `modelId` 必须是**全局唯一的已配置模型 ID**，而不是裸的 API 模型名；由模型配置解析出 `providerId`、远端模型名、接入地址和能力。这样对话不重复保存 `providerId`。`reasoning` 保留为对象或 `null`，因此整个选择用 `TEXT` JSON 保存，不使用 BLOB。

```json
{
  "modelId": "model-config_01J...",
  "reasoning": { "kind": "effort", "value": "high" }
}
```

每次 Run 还要把最终实际使用的选择展开为可直接读取的字段：

```sql
model_id                TEXT NOT NULL,
reasoning_json          TEXT,
execution_snapshot_json TEXT NOT NULL
```

`runs.model_id` 与 `runs.reasoning_json` 是本次执行不可变的模型和思考事实；`execution_snapshot_json` 继续保存其余不可变的执行环境，例如解析出的供应商／远端模型标识、权限、工具和上下文配置。当前代码仍把对话选择拆成三列，且当前裸 `modelId` 只保证在同一供应商内唯一；上述全局 ID 是已确认的目标约束，不是已经完成的 Migration。〔FACT｜`packages/protocol/src/conversation.ts:73`、`:783`；`apps/desktop/src/main/storage/agent-database.ts:1073`、`:8582`、`:9300`〕

### 1.5 `runs` 的模型与思考字段（设计目标）

`runs` 表代表一次真实执行；它不应只把实际思考配置埋在整个快照 JSON 中。目标结构中与模型相关的字段如下：

| 字段 | 类型 | 可空 | 规则 |
| --- | --- | --- | --- |
| `id` | `TEXT PRIMARY KEY` | 否 | 一次实际执行的稳定 ID |
| `conversation_id` | `TEXT`，外键到 `conversations.id` | 否 | 本次执行属于哪条对话 |
| `model_id` | `TEXT` | 否 | 本次实际采用的全局已配置模型 ID |
| `reasoning_json` | `TEXT`（JSON） | 是 | 本次实际采用的思考配置；`NULL` 表示无思考配置 |
| `execution_snapshot_json` | `TEXT`（JSON） | 否 | 解析出的供应商／远端模型、工具、权限和上下文等不可变快照；不得写入密钥 |
| `status`、`error`、`created_at`、`updated_at` | 现有标量字段 | - | 本次执行的生命周期、错误及时间 |

对话上的 `model_selection_json` 只是下一次执行的当前偏好。每次创建 Run 时，把最终解析出来的 `model_id` 和 `reasoning_json` 复制到 Run；之后用户切换模型或思考程度，也绝不回写历史 Run。

## 2. 设计说明与已确认事项

> 状态：讨论稿 v0.4；第一部分是已确认的目标表，仍不是数据库迁移已经完成的声明。
> 更新时间：2026-09-05
> 本轮范围：明确 `conversations` 表与关联表／计算属性的边界，保留当前模型三列存储，并移除重复工作区根目录；只改文档，不改代码。

本文区分三种信息：**已确认**来自本次产品讨论，**当前实现**来自现有代码，**讨论建议〔INFER〕**用于继续梳理。讨论建议不代表已经实现或已经决定采用。

第一部分使用已确认的目标名称描述后续设计；第 5 节单独记录尚未迁移的当前字段。“可变”包括设置调整和系统更新，不等于允许 AI 任意修改。

### 2.1 已确认的基本认识

1. 对话具有自己的身份、消息历史和上下文。同一个已配置 Agent 可以用于多条对话，这些对话不因此共享同一份历史。
2. `agentId` 指设置中配置、可在对话输入区选择的 Agent；它不表示父级对话，也不表示某条实际对话的 ID。
3. 普通对话、主对话下面的长期助手、团队成员和 Subagent 复用对话能力；归属、团队关系和生命周期分别表达，不按每个场景复制一套通信机制。
4. 模型相关属性必须明确区分：**已配置模型、其所属供应商和思考程度**。对话只引用全局唯一的已配置模型 ID；供应商由该配置解析，思考程度仍需明确表达。
5. 创建对话时应明确采用的模型及思考选择：用户可以手动指定或沿用界面当前选择，AI 也可以指定；AI 未显式指定这组选择时，默认沿用创建它的当前对话的相应选择。
6. 所有对话／Agent 共用 `status` 表达当前状态，不再保留 Subagent 专属的 `subagentTaskStatus` 作为新属性设计的一部分。
7. Subagent 列表和数量通过 `parentConversationId` 与对话类型查询得到，不在父对话上单独维护 `activeSubagentCount`。如需活跃数量，再筛选统一的 `status`。
8. 对话只保存 `projectId`；项目根目录由项目表维护。无项目对话需要文件或命令能力时，引用独立工作区记录，不在对话表保存第二种绝对根路径。
9. 接口层和目标 SQLite 对话表都使用 `modelSelection`：`model_selection_json TEXT` 保存全局 `modelId` 与 `reasoning`，不使用 BLOB；供应商通过模型配置解析，不重复保存 `providerId`。
10. 当前先确定属性和存储边界；工具名称、创建参数 Schema 与数据库迁移在此基础上另行设计。

### 2.2 Subagent 查询与统一状态

以当前候选类型名 `mode` 为例：直属 Subagent 的查询条件为 `parentConversationId = 当前对话 ID` 且 `mode = subagent`；数量由查询结果统计。普通长期子对话因类型不同，不计入 Subagent 数量。

“有几个 Subagent”和“有几个正在工作”是两个查询口径。前者按父级和类型查询；后者在相同条件上按 `status` 筛选活跃状态。活跃状态是否包含排队、等待审批等，由后续统一状态枚举确定，不只凭父级和类型判断是否活跃。

Subagent 与其他对话使用同一份 `status`，不再同步两套当前状态。最近某一轮执行的结果属于 Run 记录，不另作 Subagent 当前状态。任务完成可以继续返工；显式结束与用户删除仍保留不同含义，具体状态转换及删除清理机制另行梳理。

### 2.3 阅读属性表时的边界

- `agentId`、对话标题和头像分别表达配置、名称和视觉身份。同一个“前端 Agent”配置可以用于“项目 A 前端助手”和“项目 B 前端助手”两条独立对话。
- `teamId` 是团队配置模板，`teamInstanceId` 是实际团队。团队实例引用模板，对话通过成员关系归属团队，不复制整份团队定义。
- 父级关系不等于复制父对话历史，也不等于当前消息的发送方。团队负责人／成员是团队职责，不另建生命周期类型。
- 目标设计不保留 `workspaceRootPath`；项目会话经 `projectId -> projects.root_path` 解析工作区，无项目会话经独立工作区关系解析。当前代码仍有该列，不能把目标设计误写成已经迁移。
- 供应商、模型和思考程度都是可调整的选择；每次 Run 使用的实际配置另行保留。修改当前选择不应改写历史执行记录。
- 模型密钥、接入地址、支持能力和思考选项列表属于配置层，对话不复制整份供应商配置。
- 状态共用 `status` 不代表共用同一个状态值：每条对话有自己的当前状态，父对话完成不等于子对话也完成。删除及清理的技术进度仍由删除流程维护。

## 3. 本轮重点：模型与思考程度

### 3.1 已确认的选择行为

| 场景 | 要求 |
| --- | --- |
| 用户创建并明确选择模型、思考程度 | 使用用户选择；界面可显示模型所属供应商，但由模型配置解析 |
| 用户沿用当前已选择的模型创建 | 使用界面当前确定的模型和思考选择，不要求重复配置 |
| AI 创建并明确指定模型、思考程度 | 使用所指定的全局有效模型配置，不因是 AI 创建而忽略选择 |
| AI 未指定模型和思考程度 | 默认沿用创建它的当前对话的模型及思考选择 |
| 同名远端模型配置在两个供应商中 | 为两条配置分配不同的全局 `modelId`；不能把裸 API 模型名当作目标对话表中的 ID |

“未指定”不等于“对话没有模型”。最终应能明确看出该对话使用的模型来自显式选择还是继承规则。没有有效可用配置时应表达未就绪状态，不显示为已经按某个模型开始执行。

### 3.2 需要继续确定的细则

这些是明确保留的讨论项；其中建议属于〔INFER〕，不作为本次新增的实现要求：

- **只改思考程度**：建议允许保留当前模型配置，仅选择该模型支持的另一种思考程度。
- **只改模型**：新模型可能不支持原思考选项。可考虑兼容时继承、不兼容时采用新模型默认值或要求明确选择；具体规则尚未确认。供应商变化体现为选择另一条模型配置，不单独写入对话。
- **省略、默认、不支持与关闭思考**：这些含义需要区分，不能统一用空值表示“关闭”。各模型支持的选项由配置目录给出。
- **继承的时机**：建议创建时取当前有效选择的快照，之后父子对话独立调整；用户所说“保持一致”是否还需要持续联动，尚未确认。
- **没有来源对话的手动新建**：当前存在最近用户选择和应用默认配置的规则；新统一属性设计是否原样沿用，需单独确认。
- **切换生效时机**：对话当前选择与正在运行的 Run 的实际配置分开。现有运行快照机制可继续作为基础，修改对话偏好不应使历史执行记录失真。

### 3.3 现有实现对照

当前接口把三项一起放在 `modelSelection` 中：`providerId`、`modelId`、`reasoning`；当前数据库分别使用 `selected_provider_id`、`selected_model_id`、`selected_reasoning_json` 保存。目标设计改为一个 `model_selection_json TEXT`，其中只保存全局模型配置 ID 和思考配置，供应商从模型配置解析。当前协议和 Migration 尚未切换，不能把这个目标写成现状。〔FACT｜`packages/protocol/src/conversation.ts:73`、`:783`；`apps/desktop/src/main/storage/agent-database.ts:1073`、`:9305`〕

当前思考选项支持标准程度、自定义程度和 Token 预算三种形式；并非所有模型都适合用固定的“低／中／高”枚举表达。业务界面可以继续统一称“思考程度”。〔FACT｜`packages/protocol/src/conversation.ts:52`〕

当前 `spawn_subagent` 要求显式选择时同时提供供应商和模型；仅传思考程度会被校验拒绝。这是现状限制，不作为新的属性设计结论。〔FACT｜`apps/desktop/src/main/agent/subagent-tool.ts:28`〕

## 4. 与对话关联，但不混入基础属性的信息

| 信息 | 应归属的位置 |
| --- | --- |
| 首条任务、后续消息、附件 | 消息及附件记录；创建时是否允许附带首条消息属于之后的接口讨论 |
| 本次交办 ID、发送方、回执对应关系 | 通信／任务记录；发送方不等于父级对话 |
| 团队任务与验收进度 | 团队 WorkItem 及其关联；一条长期对话可以先后参与多次工作 |
| 项目和无项目工作区的根目录 | 项目表或独立工作区记录；对话只保存关系 ID |
| 用户阅读位置和未读状态 | 阅读状态记录；`hasUnread` 是根据最后阅读消息和最新消息得到的投影 |
| 最近执行结果（现有 `lastRunStatus`） | 从 Run 记录读取；描述某次执行结果，不作为另一份对话当前状态 |
| 实际模型、思考、权限与工具快照 | 每次 Run 的 `model_id`、`reasoning_json` 与执行快照；与对话当前偏好分别保留 |
| 聊天历史、压缩摘要、上下文引用 | Timeline 与上下文存储；父级关系本身不决定历史继承 |
| 完整 Agent 指令、技能和工具配置 | Agent 配置及需要的运行绑定／快照；`agentId` 表达使用哪个配置 |
| 缓存命中率、Token 用量、耗时 | 运行计量与汇总投影，不属于创建时由模型填写的属性 |
| 侧边栏是否展开、标签和滚动位置 | 工作区界面状态；关闭预览不应被等同为结束或删除长期 Agent |
| 用户删除及清理进度 | 现有删除生命周期；不以“已完成任务”替代删除事实 |

## 5. 与当前系统的差异边界

| 核对项 | 当前实现 | 本文处理方式 |
| --- | --- | --- |
| 对话身份、父级、项目、Agent、模型选择 | 对话摘要已有相关字段 | 保留现状作为属性盘点依据 |
