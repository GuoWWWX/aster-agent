# 界面迁移与设计系统规范

群聊协调双视图（2026-10-18）：群聊标题栏右上角新增“协调结果”，复用现有 Popover 展示最近 50 条群消息中的分流结果，按新到旧显示原消息、归属 Agent、接收成员、简短选择说明及协调／投递状态。已分流与成员工作完成分开表述，暂停、取消、协调错误和成员错误可见；只读现有群消息记录，不另调模型、不新增存储、不清除群聊未读。浮层仅打开时读取和订阅本群变更，并合并读取期间的重复刷新；关闭或离开群聊即停止，迟到请求不更新已关闭视图。顶部“完整对话”及每条“查看完整过程”打开原有普通侧边协调对话，可定位原消息；原居中头像和消息操作入口保留，群聊、输入框与草稿不替换。结果浮层使用语义 Token，跟随窗口约束宽高，正文独立滚动。

群聊成员过程入口（2026-10-18）：群消息的“查看工作过程”、成员姓名及提及均在本群的既有右侧工作区打开成员对话，主区域保留群聊与草稿。打开请求使用群工作区归属键，不切换主对话、不将群键传入真实对话 API；重复点击复用同一成员标签，能定位时沿用原消息定位，找不到原轮次时仍在侧边打开该成员。

群聊侧边直接复用（2026-10-18）：协调标签就是现有 `RightSidebarWorkspace` 内的普通聊天标签，内部直接传真实 session 给原 `ConversationWorkspace`，保留普通输入框、工具分组、原始参数／结果详情、流式输出、模型重试及错误。删除只读历史专用模式和协调步骤转文本组件，不再提供另一套消息页。标签、加号菜单、关闭／关闭其他／关闭全部、拖动排序、宽度及缓存均使用原实现；快速打开时同步记忆打开标签，防止异步分支加载覆盖刚打开的对话。无窗口浏览器已以实际 Run 记录检查深／浅色 700px 与 320px 侧栏，内容跟随宽度且无右侧空白。

群聊协调头像（2026-10-17）：侧边协调入口从标题栏小图标移到标题栏下、消息滚动区上方的固定居中位置，使用当前输入区归属 Agent 的既有 42px 大头像，保留上传和预设头像。头像下显示简短状态；协调或成员处理中复用 `ModelWorkingIndicator`，仅当前群页可见时挂载动画，空闲／暂停立即静止。头像右侧提供“暂停本群任务”按钮，无任务时禁用；点击头像打开既有普通侧边协调对话。状态区域保留高度，消息、输入框和草稿缓存沿用原行为，窄视图不增加横向滚动。

群聊协调侧栏（2026-10-18）：群聊直接使用普通对话现有 `RightSidebarWorkspace`，顶部归属 Agent 头像及用户消息操作栏“查看协调过程”打开其中的归属 Agent 标签。标签排序、加号菜单、关闭／关闭其他／关闭全部、缓存及 AppShell 宽度拖动均沿用同一实现；不再保留独立的协调侧栏、标签栏或宽度包裹容器。协调内容直接使用真实 session 的普通 `ConversationWorkspace`，保留输入框与完整工具过程。用户原消息靠右，协调过程、实际模型、重试、选中成员及错误靠左，沿用时间、复制和失败提示，失败可沿原消息重试。该视图读取归属 Conversation 的 JSONL，协调 Run 由普通执行核心承载，不写入成员私聊。侧栏按群使用独立打开状态及宽度，不借用负责人的对话状态；原侧边聊天及文件页保持挂载和缓存，隐藏时停用其可见订阅。协调记录隐藏时不读取，返回时无变化复用，有相关事件才补读。普通输入区不新增配置。侧栏蓝色实心点提示“有未读回复”，运行指示仍仅表示相应执行状态。

群聊消息操作（2026-10-17）：群聊与普通对话共用 `ChatMessageMeta`，时间统一使用今天／昨天／日期的既有格式；用户时间、复制及最近消息编辑靠右，成员复制、查看过程及时间靠左，无成员编辑入口。编辑使用同一个普通输入区并可取消，修订保留原始来源。群输入区的 Agent 选择可用，并恢复本群保存的协调 Agent／模型；其他输入区布局、成员头像和缓存策略保持原行为。

浏览器操作标题（2026-10-16）：browser_control 的每种受支持 action 使用具体动词描述，包括查看网页标签列表、后退／前进／刷新／停止加载、移动指针、按下／松开鼠标、拖动和输入文字，避免把不同调用统一显示为“浏览器操作已完成”。未知或历史缺失的动作保留操作类型或明确标注未记录；运行中与已完成使用对应语态，原始调用入口继续保留。

底栏流式计量（2026-10-16）：首字时间收到事件即显示；生成中输入量、已接收输出量和平均速度显示 ≈ 估算，约每秒更新。定时器只更新底栏小组件，不轮询上下文、不触发整段历史重算；工具、审批、重试、结束与卸载停止计时。缓存率保留最近完成请求的实际快照；生成结束恢复完成计量，有服务端新用量时替换。点击明细说明估算范围和实际计量的区别，深浅主题沿用现有语义样式。

后台浏览器（2026-10-16）：后台操作静默登记侧边标签，以“后台”标记说明来源，不自动选中或展开侧栏。用户点击或模型按要求 show 时展示同一页面，保留表单和交互状态；模型截图在操作详情按需读取、可点击放大，加载与失败沿用现有主题样式。后台标签随所属 Run 清理，可见标签保留原生命周期。

“查看页面”一次完成文字、元素和截图读取，图片直接出现在这条操作详情中；模型不再为同一未变化页面追加一条截图调用。单独截图时显示“截取页面／已截取页面”，不使用笼统的“浏览器操作已完成”。

浮层点击与焦点（2026-10-16）：Popover 容器不显示浏览器默认描边，内部控件保留键盘焦点样式。普通 Renderer 点击由 Radix 的外部点击处理，不因原生子窗失焦提前发送 Escape，避免同一次点击先关再开；点击原生网页仍关闭浮层。隐藏子窗产生的失焦和重新获得焦点前的旧通知不作用于新弹框。鼠标按下 Tooltip 触发组件时关闭提示，在鼠标移出再移入前不因移动或焦点恢复重开，按钮操作正常执行；移入提示选字复制的行为保留。

命令耗时（2026-10-16）：收起摘要显示命令、状态及 `12s` 形式的耗时，展开摘要只保留命令及状态；终端卡片标题栏保留 Shell 名称，右侧依次放置状态、耗时和复制按钮。计时在局部组件更新，按实际进程起止时间计算，完成后固定，不因展开收起重置；沿用语义色和既有紧凑间距。

HTML 片段高度回归（2026-10-16）：预览副本为缺少前置 DOCTYPE 的片段补标准模式声明，短组件不再受浏览器兼容模式 320px 初始视口高度影响。用户仍可只给 div/style/script，源码与复制保留原文。

HTML 多方案分页（2026-10-16）：显式多方案交付复用 HTML 预览卡片，在单一外框底部以紧凑居中控制栏呈现“上一项 · 当前页／总数 · 方案名称下拉 · 下一项”。初始第一项，首尾禁用相应翻页按钮；下拉可直接跳转，长名称截断，窄容器内不挤出边界。首次访问方案才创建预览，已访问方案切换时隐藏并复用 iframe 与交互状态。各方案按自身内容自然撑高（520px 为基准，超出不超过基准的 1/3、即整数高度最高 693px 时完整显示，更高时按 520px 内部滚动），源码也按代码长度显示，不强制整组等高；首次切入未缓存项时，加载占位沿用上一项测量高度，完成后按当前内容调整。模型提示保持同组方案预期展示高度一致。测量向上取整前忽略缩放产生的微小浮点误差，避免多出 1px 白缝。缓存沿用对话页面的一小时期限：到期时可视区中的方案继续保留，离开可视区后释放；屏幕外方案到期释放，重新进入可视区时按需重建。对话页面缓存卸载或软件关闭时释放所有预览；侧边浏览器的独立引用不受影响。工具栏只作用于当前页；沿用骨架加载、错误提示、主题及源码无蓝色描边约定。不自动合并普通代码块或改动单页布局。 对话已贴底时，分页卡片的实际尺寸变化同步保持对话贴底：变高向上扩展，变矮让前文下移，分页按钮位置稳定；用户上滑阅读历史时保留滚动位置。

模型工作粒子（2026-10-16）：工作过程标题、模型状态提示、对话标签和目录运行标识使用固定三粒子。推理中循环交织、聚合、环绕与交叉；读取／检索工具使用三点接力，执行工具使用三点环绕，正文输出使用水平波动，审批、等待工具与模型重试使用缓慢呼吸。动作跟随真实 Runtime 事件，完成／失败／取消后移除运行标识，历史工具保留静态类型图标；外层“推理中”标题沿用整轮生命周期。每个文档共用一个动画时钟，逐帧仅更新粒子 DOM；不可见区域、隐藏文档与减少动态效果时停止动画，卸载释放监听和帧请求。按钮请求仍使用细圆环，页面／卡片请求仍使用骨架屏。

最终文件变更卡片（2026-10-15）：标题概括与总增删行数同排，降低标题区高度；默认显示前三个文件，超过三个时底部提供展开入口；展开后同一位置改为“收起变更”，收起后恢复前三个文件，支持反复切换。按钮位于文件列表滚动区域之外，长列表滚动不隐藏收起入口，并提供 aria-expanded 与受控列表关联。

对话细节补充（2026-10-16）：任务清单浮层至少等于摘要卡片宽度，按任务文字增长，通常最大 560px，并受视口左右 10px 边界约束；超过上限自然换行。仅有完成占位的工具行不提供展开入口，原始调用仍从眼睛按钮查看；实际结果、截图、错误与审批详情保留。对话中安全的工作区相对文件链接进入侧边编辑器，HTTP/HTTPS 链接沿用浏览器行为。命令详情的命令与输出分别在所属区域右上角提供悬停／聚焦复制入口，文字可拖选。

任务清单展开（2026-10-16）：开关状态归任务卡片本地所有，点击摘要卡片打开，再点同一摘要卡片收起；外部点击、焦点变化及 Esc 不自动收起。展开立即显示完整向上箭头，收起显示完整向下箭头，不使用旋转过渡，避免绘制降频时停在半途。点击只更新任务浮层，不重新处理对话历史；任务进度更新保留展开状态，移除清单后重新创建默认收起。切离所属对话时隐藏浮层，返回后恢复此前状态；继续使用向上展开和现有尺寸边界。

连续工具块（2026-10-15）：用户手动展开后保持展开，后续工具、摘要、正文与运行终态更新不覆盖该选择。活跃块标题保留最新工具状态或最新思考摘要，没有新工具或新摘要时沿用当前内容；后续助手正文出现或运行结束后才切换为该块的调用汇总。

外层工作过程（2026-10-16）：整轮回答期间保持展开且不能收起，标题固定显示“推理中”；工具完成、模型请求结束和最终正文开始均不提前解锁，纯文本流式回答也使用相同状态。最终输出完成后显示“已处理 + 整轮耗时”，允许自动收起，此后用户可反复展开与收起；自动续跑归入同一可见回合。内部连续工具块继续沿用上述最新活动标题及用户展开选择。贴底时展开外层、工具分组或单项详情，消息区跟随新增高度向上滚动，保留底部正文在输入框上方；用户已上滑阅读历史时保持当前滚动位置。

侧边浏览器浮层与尺寸（2026-10-16）：Windows/Linux 的 Dialog、Popover、Select、Tooltip 和手写菜单通过共享 Provider 将真实 React portal 放入透明原生子窗；网页在浮层打开期间持续显示和运行。子窗沿用父窗口主题、样式和坐标，仅弹框及遮罩区域接收输入；Tooltip 与审批提示不抢键盘焦点。跨文档保留外部点击、Esc、焦点返回和 Tab 循环。拖动侧栏时，在画面帧内合并最新鼠标位置，用临时 CSS 宽度直接更新卡片布局，再测量裁剪到窗口及 overflow 祖先的实际网页矩形，经单向 IPC 调整真实 Chromium 页面；Electron 原生鼠标事件接续网页区域内的拖动，禁止创建整窗输入遮罩。松手时保存最终宽度并释放监听，禁止每次移动都写入全局偏好。不得通过隐藏、重建、导航或截图替换网页来解决浮层遮挡；隐藏侧栏或切离所属对话时仍隐藏原生 View。主窗口和原生浮层窗口均显式关闭 `backgroundThrottling`，避免系统通知或透明子窗遮挡时暂停动画与计时；工作粒子仍按各自 ownerDocument 使用独立帧时钟，保留减少动态效果和不可见粒子的停帧规则。macOS 暂沿用普通 DOM portal。

推理滑块动态效果（2026-10-15）：能量粒子按各供应商旗舰型号及最高档位值判断，不以列表位置或显示名称判断。GPT Sol／Astra 使用 ultra；Claude Opus／Fable／Mythos、DeepSeek Pro、Kimi K3、GLM 5.2／5.3 使用 max；Gemini Pro／Argon 使用 high，Gemini 2.5 Pro 原生预算为 32768；Grok 4.6／4.7 为 xhigh、4.3／4.5 为 high。Qwen Max、MiniMax M3 只有用户明确配置了 max 选项时才按此值显示，目录不为它们补造 effort 档位。兼容供应商前缀和已支持的日期别名；Luna、Terra、Sonnet、Haiku、Flash 等普通型号与较低档位不触发。降低档位时移除 canvas。普通颜色渐进、滑块／列表切换和请求参数保持原有行为，该显示条件不创建参数或改变运行模式。

供应商品牌图标（2026-10-15）：模型配置、推理程度与品牌选择器共用 ProviderLogo。千问使用紫色，Kimi 使用黑底白标，DeepSeek 使用蓝色，MiniMax 使用粉色；OpenAI、xAI 使用黑白标识。Gemini 使用官网四色星形资源，智谱使用 Z.ai 标识，不再使用 Google G 或“智”字占位。彩色资源随应用本地打包，保留品牌配色和固定图标尺寸，浅深主题均由中性边框提供背景区分；用户上传图标不受内置图标更新影响。资源来源见设置模块 brand-assets/README.md。

全局加载状态（2026-10-16）：页面、卡片、对话和 HTML 预览统一使用 LoadingState 柔光骨架屏：矩形、两行占位及加载文字；窄面板、浮层和差异卡片使用紧凑尺寸。按钮、工具栏、列表行和增量历史加载统一使用 Spinner 细圆环，转速为 1 秒一圈，骨架柔光周期为 1.65 秒。两者共用语义颜色、支持浅深主题；系统设置减少动态效果时停止动画。保留真实请求、错误及完成状态，加载结束移除占位；对话工具栏、输入框和最终内容的自然高度保持原有行为。

切页性能（2026-10-17）：群聊预览标签替换后仍按普通对话的缓存策略保留消息、草稿与阅读位置，只有后台相关数据变化才补读。顶部当前标签的可见性检查使用 ResizeObserver 初始通知，等浏览器完成布局后再读取几何位置，不在切页的 React 提交阶段同步触发整页回流；无该 API 时使用下一帧回调并在卸载时取消。

浮层底色（2026-10-15）：深色模式中的项目选择、上下文用量、文件排序、编辑器表格菜单和提示气泡统一使用 `--app-panel`（#191A1C）；浅色模式沿用原有白色底色。浮层内部交互项仍按既有悬停、选中和内容层级配色。

项目目录交互（2026-10-15）：对话在项目内可拖动排序；拖到其他项目文件夹或该项目对话时，使用既有对话项目归属接口移动，并展开目标项目；拖到“临时”分组可移出项目，临时对话可反向拖入项目。临时对话输入框的项目选择入口继续保留。项目文件夹角标以项目已有的双色渐变填充，颜色与顶部项目渐变一致。

## 5. 设计 Token

### 5.1 Token 层级

```text
基础语义 Token
  background / foreground / surface / border / muted / accent / destructive

应用语义 Token
  shell / titlebar / activity-bar / panel / selection / approval / diff / terminal

Feature Token
  仅在确有独立视觉语义时定义，例如 diff-added、agent-running
```

新组件只能使用语义 Token 或现有 Tailwind 语义类。禁止为每个页面重新写一组蓝色、灰色和阴影值。

### 5.2 命名与兼容

- 新 Token 使用 `--app-*` 或明确业务语义，例如 `--app-panel-border`、`--task-running`。
- `--mk-*` 仅作为迁移兼容映射，不能在 Agent 新功能中继续扩散。
- 迁移兼容层集中管理，完成对应模块迁移后删除无引用映射。
- 不用全局 `!important` 覆盖 Tailwind 颜色来实现主题；主题通过 Token 和组件变体完成。

### 5.3 视觉基线

- 默认圆角以 `6px` 和 `8px` 为主，卡片不得超过 `8px`，除非现有控件有明确视觉合同。
- 采用紧凑桌面字号和间距，面板标题不使用页面 Hero 级字体。
- 主要信息靠层级、间距和边框组织，不依赖大阴影、渐变光球或装饰背景。
- 中性背景、表面和边框占据主要视觉面积；强调色只用于主要操作、选中、焦点和少量关键提示。
- 不让紫色或靛蓝成为整个界面的主背景或唯一视觉语言；即使沿用 `md-king` 的现有强调色，也必须映射到语义 Token，并控制使用面积。
- 状态颜色至少区分运行、成功、等待审批、阻塞、失败和取消，不使用同一色相表达所有状态。
- 状态色使用彼此可区分的语义色，并同时配合图标、文字或形状，不能只靠色相传达状态。
- 字体继续以 Geist Variable + 系统中文字体回退为基线。

## 12. CSS 治理

### 12.1 Tailwind 优先

默认用 Tailwind 组合表达样式。**只有命中下列判据之一才允许新建或扩写 CSS 文件**，并在文件头写明命中的是哪一条：

| # | 判据 | 原因 |
| --- | --- | --- |
| 1 | 类名由运行时拼接 | Tailwind JIT 只能静态扫描字面量。`` `mk-cm-h${level}` ``、`` `tone--${x}` `` 这类模板字符串扫不到，改用 Tailwind 需 safelist 穷举全部运行时组合 |
| 2 | 组合选择器、伪类、伪元素、`:has()`、相邻兄弟、属性选择器 | Tailwind 无法表达或需极长的任意值语法 |
| 3 | 定义 CSS 变量供后代级联消费 | Tailwind 无对应能力 |
| 4 | `@keyframes`、`@container`、`@supports` | 需要配置扩展才能在 Tailwind 中表达 |
| 5 | 覆盖第三方库注入的样式 | 与库的内联/高优先级样式对抗，通常需要 `!important` |
| 6 | 从既有项目逐字迁移的视觉合同 | 见 12.2，附加条件严格 |

不满足任一判据时，把样式写在 JSX 的 `className` 里。同一长组合出现三次以上且语义稳定时，提取组件或 CVA variant，而不是新建 CSS 类。

判断依据是**类名如何到达 DOM**，不是"这段样式有多少行"。由 `document.createElement` 手工构建的 DOM（如 CodeMirror Widget 的 `toDOM()`）虽然类名是字面量，但把原子类塞进 `createElement` 会显著降低可读性，可按判据 1 同等对待。

### 12.2 迁移例外

从 `md-king` 等既有项目迁移视觉合同时，允许逐字复制 CSS，但必须同时满足：

- 有可重跑的提取脚本（如 `scripts/extract-md-king-editor-css.mjs`），源项目更新后靠重跑同步，不靠手工补丁。
- 生成文件头部标注"由脚本生成，请勿手工编辑"，并写明与源文件的全部差异。
- 提取脚本带排除名单，防止把源项目的外壳样式（`[data-slot=`、全局 `!important` 覆盖）带进来污染本项目。
- 跨项目设计令牌差异用桥接层解决，不逐条改写规则——逐条意译是视觉漂移的主要来源。

迁移完成后在[md-king 迁移源清单](./10-md-king迁移源清单.md)登记目标路径、差异理由和验证结果。

### 12.3 分层与边界

- `tokens.css` 只放变量，不放页面选择器。
- `base.css` 只放 reset、字体、selection、focus 和基础元素。
- `shell.css` 只放 AppShell、标题栏、活动栏和稳定面板结构。
- Feature 特有样式与 Feature 共置，并用根 `data-feature` 或局部 class 限定。脚本生成的迁移产物可用类名前缀（如 `mk-cm-`）作为命名空间，但不得再加祖先选择器——那会抬高特异性并改变与第三方库样式的覆盖关系。
- 禁止新增大范围颜色兼容选择器、无边界元素选择器和无说明 `!important`。
- 禁止为一个局部问题在全局 CSS 末尾继续叠加补丁；先定位 owner 文件。
- 删除样式前搜索运行时 class、CodeMirror Decoration 和 Portal，避免只看 JSX 静态引用。

### 12.4 不引入 CSS 预处理器

不引入 Sass、Less 或 Stylus。

**官方立场**：Tailwind CSS v4 明确声明"不设计为与 Sass、Less、Stylus 等预处理器配合使用"，并把自身定位为预处理器——"你不该把 Tailwind 和 Sass 一起用，理由和你不会把 Sass 和 Stylus 一起用是一样的"。v4 通过 Lightning CSS 内建了 `@import` 打包、厂商前缀和现代语法转换。

**能力已被原生 CSS 覆盖**：

| 预处理器功能 | v4 中的替代 |
| --- | --- |
| 文件导入 | 内建 `@import` 打包 |
| 变量 | 原生 CSS 自定义属性 |
| 数学函数 | 原生 `min()` / `max()` / `round()` |
| 颜色运算（`darken`/`lighten`） | `color-mix()`，且能作用于 CSS 变量和 `currentcolor` |
| 嵌套 | 原生 CSS 嵌套 |
| 厂商前缀 | Lightning CSS 内建 |

**本项目实测**：对迁移进来的 231 条编辑器规则做重复族归纳，预处理器循环只能省约 6%（3 个族共 15 条），因为绝大多数规则是各不相同的精确数值而非机械重复。

**额外代价**：脚本生成的迁移产物需要多一次"数字序列归纳成循环"的有损转换，并使源项目更新后的重新同步更难。

同理不引入 CSS Modules：Tailwind 的工具类天然带作用域，CSS Modules 解决的问题在这套组合下不存在。

### 12.5 React 样式选型顺序

当前 Web 样式入口直接加载 Tailwind CSS 4 和项目语义 Token，组件布局也已有通过 React `style` 传入运行时尺寸的实践。〔FACT｜`apps/web/src/styles/index.css:1`、`:3`；`apps/web/package.json:57`、`:65`；`apps/web/src/components/layout/app-shell.tsx:120`、`:163`〕

新增或修改 React 组件样式时，按以下顺序选择，不因样式行数多就直接创建 CSS 文件：

| 顺序 | 方案 | 适用范围 | 约束 |
| --- | --- | --- | --- |
| 1 | JSX `className` + Tailwind | 静态布局、间距、颜色、主题、hover/focus、响应式和可枚举状态 | 条件分支必须包含完整类名字面量，禁止运行时拼接 `bg-${tone}` 之类的残缺类名 |
| 2 | 组件或 CVA variant | 同一长类组合出现三次以上，且已形成稳定语义 | 不为单次使用提前抽象 variant |
| 3 | React `style` | 拖拽宽高、菜单坐标、进度百分比、运行时网格列数等无法静态枚举的数值 | 只承载动态几何值或供 CSS 消费的变量，不在 `style` 中重复写静态颜色、间距和主题规则 |
| 4 | 与 Feature 共置的原生 CSS | 命中 12.1 的组合选择器、伪元素、动画、容器查询、级联变量或第三方覆盖 | 只放 Tailwind 不适合表达的部分，不能把整个组件样式重新搬回 CSS |

推荐写法：

```tsx
<aside
  className={collapsed
    ? "hidden"
    : "flex min-h-0 min-w-[220px] border-l border-[var(--app-border)]"}
/>

<div style={{ left: menu.x, top: menu.y }} />
```

禁止以下做法：

- 不在组件中插入字符串形式的 `<style>` 标签。React 不会像 Vue SFC 的 `<style scoped>` 一样自动限定作用域，这会制造重复注入或全局泄漏。
- 不引入 styled-components、Emotion 等运行时 CSS-in-JS。当前主题已由 CSS Variables 和 `data-theme` 驱动，再增加运行时样式系统会重复主题能力，并增加依赖、包体、运行时和调试成本。
- 不用 Sass/SCSS 把原生 CSS 再包一层；预处理器约束和替代能力见 12.4。
- 不为“类名太长”新建无语义 CSS 类。优先整理 JSX、提取真实组件，或在达到复用门槛后使用 CVA。

现有复杂 CSS 不要求一次性机械改写。修改某个组件时，只迁移本次改动直接涉及、且能由 Tailwind 清晰表达的规则；组合选择器、CodeMirror/xterm 样式和已登记的迁移视觉合同继续保留在 owner CSS 文件中。

## 13. 迁移流程

每个 UI 模块按以下顺序迁移：

1. **记录视觉合同**：源文件、视口、light/dark、交互状态和截图。
2. **列出行为合同**：点击、键盘、拖拽、折叠、错误、空状态和性能保护。
3. **确定目标层**：UI Primitive、Layout、Feature 或 Page。
4. **提取最小依赖**：Token、组件和纯函数，不复制整个目录后删除。
5. **替换宿主调用**：统一改为 AgentClient/Port，不保留 Tauri 判断。
6. **按目标结构实现**：可复用视觉，不继承巨型页面和全局 CSS 补丁。
7. **验证行为**：组件测试、键盘、无障碍和错误状态。
8. **验证视觉**：固定视口截图和像素/布局检查。
9. **验证回归**：编辑器、主题、面板、长内容和浏览器降级。
10. **记录迁移清单**：源路径、源 SHA-256、目标路径、差异理由和验证结果。

迁移与产品改造分开审查：先证明视觉和行为基线被保留，再增加团队、任务、审批等 Agent 功能。

## 14. 拆分现有大文件的规则

不能把现有 1,000 至 3,000 行文件直接作为新架构基线。拆分按职责，不按机械行数：

- 页面拆成 Page Composition、Feature Controller、Feature Components。
- 复杂计算或解析移入纯函数模块并补单元测试。
- CodeMirror Extension 按扩展职责拆分，但保持同一状态事务和扩展顺序。
- 样式按 Token、Shell、Feature 分层。
- Dialog、Drawer、Toolbar 和列表项成为局部组件，仅在真实复用时提升共享层。

禁止一边迁移一边全面重写 Markdown 算法。编辑器和预览先保行为，再通过测试保护逐步拆分。

## 15. 无障碍与交互质量

- 所有交互元素可通过键盘到达，焦点顺序与视觉顺序一致。
- Dialog/Dropdown/Tooltip/Select 使用 Radix 行为，不手写不完整的焦点陷阱。
- 图标按钮有可读名称，状态不只用颜色表达。
- 拖拽分隔条有 `role`、方向、aria-label 和键盘替代方式。
- 运行状态变化使用适当 live region，但终端流和 Token 流不能逐字符播报。
- 动画尊重 `prefers-reduced-motion`，不以动画隐藏阻塞或错误。
