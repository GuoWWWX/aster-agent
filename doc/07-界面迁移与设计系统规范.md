## 1. 结论

Agent 项目沿用 `md-king` 当前的布局习惯、视觉密度、编辑器体验和基础组件语言，但不原样复制页面代码和巨型样式文件。迁移目标是：

```text
保留用户已经认可的视觉与交互
  + 按 Agent 产品重新组织信息架构
  + 建立清晰组件层和宿主边界
  + 用测试与截图证明没有退化
```

采用的 UI 标准是 **shadcn/ui `radix-nova` 风格**：Radix Primitives 提供可访问交互，Tailwind CSS 4 和 CSS Variables 提供样式，CVA 管理变体，Lucide 提供图标。shadcn/ui 组件源码归项目所有，因此需要按本项目规范维护，而不是把它当作不可修改的 npm 黑盒。

## 3. 迁移对象分类

### 3.1 保留视觉合同并重新实现

- `AppShell` 整体工作台结构。
- `AppTitlebar` 尺寸、窗口按钮位置和拖拽体验。
- `ActivityBar` 紧凑图标导航。
- 左侧文件/会话面板、中央工作区、右侧上下文面板。
- 面板拖拽、折叠、展开和稳定间距。
- light/dark 主题、字体、圆角、边框、状态颜色和图标风格。

这些模块按新项目组件层重新实现，不复制其中的 Tauri 调用或 md-king 业务状态。

### 3.2 按最小闭包迁移并保护行为

- CodeMirror Markdown 编辑器及定向扩展。
- Markdown 实时渲染、表格、图片、Mermaid、Callout 和链接行为。
- Word 分页预览的纯前端部分。
- 文件树、标签页、文档大纲中仍符合 Agent 工作流的交互。
- 已验证的长文档、可见区渲染、debounce 和分页保护。

行为复杂的编辑器代码先通过现有测试和固定夹具迁移；组件结构改造必须在迁移通过后分批完成，不能在同一步同时改变算法和 UI。

### 3.3 不迁移

- Tauri、Rust、Pandoc、DOCX 转换和 Word/WPS COM 相关页面与调用。
- 模板中心、转换历史、浮窗、托盘等不属于 Agent MVP 的产品页面。
- 为旧页面补丁式追加的全局颜色覆盖和大范围选择器。
- 与 Agent 无关的营销文案、空入口和规划中按钮。

## 4. 目标 UI 分层

```text
apps/web/src/
├─ styles/
│  ├─ tokens.css          # 语义 Token 和 light/dark 值
│  ├─ base.css            # reset、字体和基础可访问性
│  └─ shell.css           # 稳定应用外壳，不放 Feature 细节
├─ components/
│  ├─ ui/                 # shadcn/ui radix-nova 基础组件
│  └─ layout/             # Titlebar、ActivityBar、Panel、AppShell
├─ features/
│  ├─ team/
│  ├─ tasks/
│  ├─ chat/
│  ├─ editor/
│  ├─ diff/
│  ├─ terminal/
│  └─ browser/
├─ pages/                 # 页面组合
└─ runtime/               # AgentClient Adapter
```

规则：

- 基础组件不知道 Team、Task、项目或 Electron。
- Layout 只提供插槽、尺寸和折叠能力。
- Feature 组件拥有业务展示和交互。
- Page 只组合 Feature，不直接处理 IPC 或数据库状态。
- Feature 样式与 Feature 共置；禁止继续把所有新样式写进单一 `index.css`。

## 5. 设计 Token

### 5.1 Token 层级

```text
基础语义 Token
  background / foreground / surface / border / muted / accent / destructive

应用语义 Token
  shell / titlebar / activity-bar / panel / selection / approval / diff / terminal

Feature Token
  仅在确有独立视觉语义时定义，例如 diff-added、agent-running
```

新组件只能使用语义 Token 或现有 Tailwind 语义类。禁止为每个页面重新写一组蓝色、灰色和阴影值。

### 5.2 命名与兼容

- 新 Token 使用 `--app-*` 或明确业务语义，例如 `--app-panel-border`、`--task-running`。
- `--mk-*` 仅作为迁移兼容映射，不能在 Agent 新功能中继续扩散。
- 迁移兼容层集中管理，完成对应模块迁移后删除无引用映射。
- 不用全局 `!important` 覆盖 Tailwind 颜色来实现主题；主题通过 Token 和组件变体完成。

### 5.3 视觉基线

- 默认圆角以 `6px` 和 `8px` 为主，卡片不得超过 `8px`，除非现有控件有明确视觉合同。
- 采用紧凑桌面字号和间距，面板标题不使用页面 Hero 级字体。
- 主要信息靠层级、间距和边框组织，不依赖大阴影、渐变光球或装饰背景。
- 中性背景、表面和边框占据主要视觉面积；强调色只用于主要操作、选中、焦点和少量关键提示。
- 不让紫色或靛蓝成为整个界面的主背景或唯一视觉语言；即使沿用 `md-king` 的现有强调色，也必须映射到语义 Token，并控制使用面积。
- 状态颜色至少区分运行、成功、等待审批、阻塞、失败和取消，不使用同一色相表达所有状态。
- 状态色使用彼此可区分的语义色，并同时配合图标、文字或形状，不能只靠色相传达状态。
- 字体继续以 Geist Variable + 系统中文字体回退为基线。

## 6. 基础组件规范

### 6.1 shadcn/ui 组件所有权

`components/ui` 中的代码属于本项目。可以调整尺寸和变体，但必须：

- 保持 Radix 的键盘、焦点、Portal 和 ARIA 行为。
- 使用 `cn` 合并 class，使用 CVA 管理有稳定语义的 variant/size。
- 保持 `data-slot`，便于样式和测试定位。
- 不在基础组件内读取 Zustand、AgentClient 或业务上下文。
- 修改公共组件时运行所有调用方的组件测试和视觉回归。

### 6.2 按钮与图标

- 工具栏和常见操作优先使用 Lucide 图标。
- Agent 与 Subagent 头像共用协议层稳定图标目录和本地 Lucide 映射；可以使用成组的浅色背景提升辨识度，但必须同时覆盖 light/dark。模型或远端数据不能直接提供可执行 SVG。
- 仅图标按钮必须有 `aria-label` 和 Tooltip。
- 不用写着“关闭”“撤销”“刷新”的圆角文字块替代明确的标准图标。
- 危险操作使用 destructive 变体，但不能只靠颜色表达风险。
- Button 尺寸固定，加载状态不能改变工具栏布局。

### 6.3 表单

- 二元设置使用 Switch/Checkbox。
- 模式切换使用 Tabs/Segmented Control。
- 有限选项使用 Select/Menu。
- 数值使用 Input/Stepper/Slider，明确单位和上下限。
- 验证错误靠近字段显示，并通过统一错误对象提供原因。

### 6.4 卡片与面板

- AppShell 的页面分区不是漂浮卡片，不给每一层都加背景、圆角和阴影。
- Card 只用于重复实体、审批、任务摘要或真正需要边界的工具。
- 禁止 Card 套 Card；内部层级使用 section、separator、list row。
- 面板尺寸使用稳定约束，动态内容不能推动活动栏、标题栏或工具栏跳动。

## 8. Agent 页面规范

### 8.1 第一屏

第一屏直接是可操作的团队工作台，不制作营销首页。用户应能立即看到：当前团队、项目范围、任务输入、运行任务和需要审批的操作。

### 8.2 简单任务

简单任务保持聊天式直达体验，不强迫用户打开任务板或查看组织流程。只有发生委派时才展开 Agent、Task 和分配原因。

### 8.3 复杂任务

- 中央区域显示 Team Lead 的统一过程和最终结论。
- Team/Task 面板显示 Worker、状态、依赖和项目，不把所有子 Agent 原始对话同时铺开。
- 子 Agent 详情按需打开，默认展示摘要、证据和交付物。
- 审批统一进入审批中心，同时在相关任务处显示关联状态。

### 8.4 状态稳定性

- Agent 名称、状态徽标和计时器有固定布局，不因文字变化挤压操作按钮。
- Subagent 对话树和工具结果同时显示其持久名称与专属图标；未配置图标时使用系统稳定回退，不在每次渲染时随机选择。
- 长任务输出、Diff 和消息列表采用虚拟化或分段加载。
- 加载、空、错误、取消、断线恢复都保留稳定容器尺寸。
- 不在 UI 中用假数据或灰色按钮暗示未实现能力已经可用。

## 9. 响应式与窗口行为

- 桌面优先，基准覆盖 `1024 × 680`、`1280 × 800`、`1440 × 900`、`1920 × 1080`。
- 小窗口优先收起右侧上下文区，再收起左侧辅助区；ActivityBar 和主任务输入必须保留。
- 面板尺寸使用 min/max 和持久化值，拖拽不能出现负宽、黑缝或内容重叠。
- 125%、150%、175% Windows 缩放下检查文字、按钮和分隔线。
- 文本允许合理换行；按钮、Badge 和导航项不能溢出父容器。
- 不按 viewport width 动态缩放字体。

## 10. 主题规范

- light/dark 均由同一语义 Token 驱动。
- 新组件必须同时验证 light/dark，不能靠全局 `.dark .text-blue-*` 批量修补。
- 浏览器和 Electron 使用同一主题逻辑。
- 切换主题先更新 UI，再持久化；持久化失败需要回滚并提示。
- CodeMirror、Markdown、Diff、终端和受管浏览器边框必须与应用主题协调，但保留内容自身的语义颜色。

## 11. 宿主与组件边界

现有 `md-king` 标题栏直接调用 Tauri，这是迁移时必须去除的耦合。目标组件只接收能力和回调：

```ts
type AppTitlebarProps = {
  canControlWindow: boolean;
  isMaximized: boolean;
  onMinimize?: () => void;
  onToggleMaximize?: () => void;
  onClose?: () => void;
};
```

窗口状态由 `DesktopAgentClient` 经 Preload 提供；浏览器使用 `MockAgentClient` 返回 `canControlWindow: false`。组件中禁止出现 `isElectron()`、`isTauriEnvironment()`、`window.require` 或原始 IPC channel。

## 12. CSS 治理

### 12.1 Tailwind 优先

默认用 Tailwind 组合表达样式。**只有命中下列判据之一才允许新建或扩写 CSS 文件**，并在文件头写明命中的是哪一条：

| # | 判据 | 原因 |
| --- | --- | --- |
| 1 | 类名由运行时拼接 | Tailwind JIT 只能静态扫描字面量。`` `mk-cm-h${level}` ``、`` `tone--${x}` `` 这类模板字符串扫不到，改用 Tailwind 需 safelist 穷举全部运行时组合 |
| 2 | 组合选择器、伪类、伪元素、`:has()`、相邻兄弟、属性选择器 | Tailwind 无法表达或需极长的任意值语法 |
| 3 | 定义 CSS 变量供后代级联消费 | Tailwind 无对应能力 |
| 4 | `@keyframes`、`@container`、`@supports` | 需要配置扩展才能在 Tailwind 中表达 |
| 5 | 覆盖第三方库注入的样式 | 与库的内联/高优先级样式对抗，通常需要 `!important` |
| 6 | 从既有项目逐字迁移的视觉合同 | 见 12.2，附加条件严格 |

不满足任一判据时，把样式写在 JSX 的 `className` 里。同一长组合出现三次以上且语义稳定时，提取组件或 CVA variant，而不是新建 CSS 类。

判断依据是**类名如何到达 DOM**，不是"这段样式有多少行"。由 `document.createElement` 手工构建的 DOM（如 CodeMirror Widget 的 `toDOM()`）虽然类名是字面量，但把原子类塞进 `createElement` 会显著降低可读性，可按判据 1 同等对待。

### 12.2 迁移例外

从 `md-king` 等既有项目迁移视觉合同时，允许逐字复制 CSS，但必须同时满足：

- 有可重跑的提取脚本（如 `scripts/extract-md-king-editor-css.mjs`），源项目更新后靠重跑同步，不靠手工补丁。
- 生成文件头部标注"由脚本生成，请勿手工编辑"，并写明与源文件的全部差异。
- 提取脚本带排除名单，防止把源项目的外壳样式（`[data-slot=`、全局 `!important` 覆盖）带进来污染本项目。
- 跨项目设计令牌差异用桥接层解决，不逐条改写规则——逐条意译是视觉漂移的主要来源。

迁移完成后在[md-king 迁移源清单](./10-md-king迁移源清单.md)登记目标路径、差异理由和验证结果。

### 12.3 分层与边界

- `tokens.css` 只放变量，不放页面选择器。
- `base.css` 只放 reset、字体、selection、focus 和基础元素。
- `shell.css` 只放 AppShell、标题栏、活动栏和稳定面板结构。
- Feature 特有样式与 Feature 共置，并用根 `data-feature` 或局部 class 限定。脚本生成的迁移产物可用类名前缀（如 `mk-cm-`）作为命名空间，但不得再加祖先选择器——那会抬高特异性并改变与第三方库样式的覆盖关系。
- 禁止新增大范围颜色兼容选择器、无边界元素选择器和无说明 `!important`。
- 禁止为一个局部问题在全局 CSS 末尾继续叠加补丁；先定位 owner 文件。
- 删除样式前搜索运行时 class、CodeMirror Decoration 和 Portal，避免只看 JSX 静态引用。

### 12.4 不引入 CSS 预处理器

不引入 Sass、Less 或 Stylus。

**官方立场**：Tailwind CSS v4 明确声明"不设计为与 Sass、Less、Stylus 等预处理器配合使用"，并把自身定位为预处理器——"你不该把 Tailwind 和 Sass 一起用，理由和你不会把 Sass 和 Stylus 一起用是一样的"。v4 通过 Lightning CSS 内建了 `@import` 打包、厂商前缀和现代语法转换。

**能力已被原生 CSS 覆盖**：

| 预处理器功能 | v4 中的替代 |
| --- | --- |
| 文件导入 | 内建 `@import` 打包 |
| 变量 | 原生 CSS 自定义属性 |
| 数学函数 | 原生 `min()` / `max()` / `round()` |
| 颜色运算（`darken`/`lighten`） | `color-mix()`，且能作用于 CSS 变量和 `currentcolor` |
| 嵌套 | 原生 CSS 嵌套 |
| 厂商前缀 | Lightning CSS 内建 |

**本项目实测**：对迁移进来的 231 条编辑器规则做重复族归纳，预处理器循环只能省约 6%（3 个族共 15 条），因为绝大多数规则是各不相同的精确数值而非机械重复。

**额外代价**：脚本生成的迁移产物需要多一次"数字序列归纳成循环"的有损转换，并使源项目更新后的重新同步更难。

同理不引入 CSS Modules：Tailwind 的工具类天然带作用域，CSS Modules 解决的问题在这套组合下不存在。

## 13. 迁移流程

每个 UI 模块按以下顺序迁移：

1. **记录视觉合同**：源文件、视口、light/dark、交互状态和截图。
2. **列出行为合同**：点击、键盘、拖拽、折叠、错误、空状态和性能保护。
3. **确定目标层**：UI Primitive、Layout、Feature 或 Page。
4. **提取最小依赖**：Token、组件和纯函数，不复制整个目录后删除。
5. **替换宿主调用**：统一改为 AgentClient/Port，不保留 Tauri 判断。
6. **按目标结构实现**：可复用视觉，不继承巨型页面和全局 CSS 补丁。
7. **验证行为**：组件测试、键盘、无障碍和错误状态。
8. **验证视觉**：固定视口截图和像素/布局检查。
9. **验证回归**：编辑器、主题、面板、长内容和浏览器降级。
10. **记录迁移清单**：源路径、源 SHA-256、目标路径、差异理由和验证结果。

迁移与产品改造分开审查：先证明视觉和行为基线被保留，再增加团队、任务、审批等 Agent 功能。

## 14. 拆分现有大文件的规则

不能把现有 1,000 至 3,000 行文件直接作为新架构基线。拆分按职责，不按机械行数：

- 页面拆成 Page Composition、Feature Controller、Feature Components。
- 复杂计算或解析移入纯函数模块并补单元测试。
- CodeMirror Extension 按扩展职责拆分，但保持同一状态事务和扩展顺序。
- 样式按 Token、Shell、Feature 分层。
- Dialog、Drawer、Toolbar 和列表项成为局部组件，仅在真实复用时提升共享层。

禁止一边迁移一边全面重写 Markdown 算法。编辑器和预览先保行为，再通过测试保护逐步拆分。

## 15. 无障碍与交互质量

- 所有交互元素可通过键盘到达，焦点顺序与视觉顺序一致。
- Dialog/Dropdown/Tooltip/Select 使用 Radix 行为，不手写不完整的焦点陷阱。
- 图标按钮有可读名称，状态不只用颜色表达。
- 拖拽分隔条有 `role`、方向、aria-label 和键盘替代方式。
- 运行状态变化使用适当 live region，但终端流和 Token 流不能逐字符播报。
- 动画尊重 `prefers-reduced-motion`，不以动画隐藏阻塞或错误。

## 16. 视觉与行为回归

### 16.1 固定夹具

- AppShell：空状态、面板展开/收起、最小/默认/大窗口。
- 主题：light、dark、system 初始解析。
- Markdown：标题、列表、表格、代码、Mermaid、图片、Callout、长文档。
- Agent：简单任务、三 Worker、等待审批、失败、恢复。
- Diff/终端：空、普通、大内容、截断和 Artifact 跳转。

### 16.2 截图矩阵

### 16.3 验收标准

- 无组件重叠、文本截断、不可解释空白和布局跳动。

- Console 没有 React、Radix、CSS、未处理 Promise 或资源加载错误。
