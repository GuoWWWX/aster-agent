群聊工具修订（2026-10-17）：`read_team_messages` 返回各条公开消息相对于读取成员的 self／member／user 身份；定向派发改为仅通知成员，工具负责读取当前原消息及必要未读背景；通知和完成回执均不复制群正文或群摘要。群归属 Agent 的纯路由调用不注册工具、不运行成员私聊，也不公开事务性过程。`post_team_message` 无权改变群归属 Agent／模型或修改用户消息；公开结论仍由成员显式发送。后台路由失败可继续原消息，完成的公开发送和其他副作用不自动重放。

命令用途备注（2026-10-16）：run_command 可选传 description，建议不超过一句话，按“动作＋实际目标＋重要条件”描述意图，不提前宣告成功。例如 `ping -n 4 www.baidu.com` 对应“Ping 百度，检查网络连通性与延迟”；`mvn -pl order-service -am package -DskipTests` 对应“使用 Maven 打包订单服务（跳过测试）”；`java -jar target/order-service.jar` 配合 service 模式对应“启动订单服务，在后台持续运行”。名称来自用户任务或已核验项目，禁止照搬示例中并不存在的服务名。未传或为空仍可正常执行，摘要兼容显示完整命令。

命令时限与重启恢复（2026-10-16）：run_command 仍使用同一执行器区分 batch 和 service。batch 实时输出，观察窗口结束后可先返回 running 与 commandId，默认执行上限 30 分钟，显式 timeoutMs=null 可关闭时限，供超长构建使用；service 启动后返回，省略时限时持续运行，可查看日志并停止。数值时限仍为 1 秒至 30 分钟。用户要求固定运行时长时，命令应自行按次数或截止时间正常退出，不以无限命令加工具超时实现。应用中断后不重放在途副作用，所属 Run 已结束却仍标为 running 的工具在恢复和历史投影时收敛为失败并显示中断原因；已收到的完成结果与活动 Run 保留。


多方案交付（2026-10-16）：用户需要多版页面或组件进行比较筛选时，优先调用 present_html({pages})，将 2–12 个带 title 的选项合成一张分页卡片。选项支持 kind=code 的内联 html 片段和 kind=file 的已有 path，也可混合；与旧 path 输入互斥。内联内容不要求创建文件、不解析工作区；文件选项逐一按既有读取边界校验，任何一项失败均不交付部分分组。输入字符上限与 Main 的总 UTF-8 字节上限各为 1,000,000；取消前后不返回成功交付。仍沿用 workspace-read 策略、串行执行、Run 完成后投影与既有预览隔离。结果 kind=html_gallery 保存有序 pages，文件只记引用、内联项保存源码供历史恢复。不要自动合并普通多页面项目或无比较需求的内容。

## HTML 最终交付（2026-10-15）

`present_html({path})` 专用于向用户交付已生成的静态 HTML 页面。Agent 先完成文件创建／编辑和验证，再调用此工具，最后给出简短说明；普通 HTML 项目修改不调用。工具按当前对话的项目或临时工作区解析相对路径，复用 HTML 预览入口的 realpath、隐藏目录、符号链接、HTML 后缀、二进制和 1 MB 限制，只校验读取，不写文件、不监听端口、不打开浏览器。遵循 workspace-read 的禁用策略，可在 read_only 模式下读取，顺序执行以保持展示顺序；调用前后检查取消信号。

单文件成功结果记录 `{ok:true,value:{presentation:{kind:"html",path}}}`，沿用现有工具审计与幂等键，失败返回统一工具错误。Renderer 在本轮结束后把成功引用渲染为位于最终文字说明之前的独立交付面板，保留源码／预览切换；底层临时预览仍由既有 html.preview 生命周期管理，使用应用自己的隔离 Node loopback 服务；无需额外运行 Python、http.server 或其他临时服务。项目本身依赖开发服务时才按需启动该项目服务。`browser_control` 仍只接受 HTTP/HTTPS 地址，不接受本地文件路径，也不替模型创建静态预览 URL。模型工具本身不宣告 Run 完成，不修改普通文件 Diff，文件型交付不把完整 HTML 重复写入结果。文件引用按当前内容加载，不保存历史源码快照。

## 用户提问与程序观察入口（2026-10-14）

`request_user_input` 接受 1–3 个含稳定 ID、标题、正文、可选选项的问题，立即完成工具调用，不阻塞其他工作。每个主对话最多保留 10 组待回答问题，同一 Run/ToolCall 重放复用原问题。`wait_for_user_input` 显式等待指定问题，支持 any/all 和最长 10 分钟超时；结果 resolved/timed_out/interrupted，并返回各问题的实际状态（包括 cancelled）。两者没有文件、进程等写入权限，不提高当前执行权限。

回答先写入 ThreadLog，再按 owner/root 两个目标投递。各目标的用户输入与送达回执同一事件提交，恢复只补未送达的目标。模型配置缺失等发送失败保留回答供用户重试，不能静默丢弃。

有选项的问题应给出互斥的短标签和简短说明，并用 `recommended=true` 标明一个 AI 推荐项；用户可取消选择、自定义文字或粘贴图片/文件。回答附件沿用普通上传与模型附件通道，绑定到问题 owner 的回答消息，root 保留文字记录；提交前校验附件归属与草稿状态，回答重试沿用已保存附件并使用原送达回执。

右上角“运行”是 `run_command` 已有生命周期的观察和停止入口；按命令识别 Spring Boot、Maven、Gradle、Node.js、Python、Docker，其他命令用终端图标。服务不会因对话正常完成而停止，用户可明确停止进程树；应用退出沿用工具注册表的清理。侧边终端由既有 PTY 页面管理。最近列表是本次应用运行的有界投影，完整输出仍以原工具记录为准。

点击命令打开右侧只读执行标签，复用原 CommandSession 的 stdout/stderr 缓冲和进程状态，每秒读取有界、脱敏的尾部输出。查看、隐藏和关闭标签不改变命令生命周期；详情中的停止复用进程树终止，并等待退出确认。临时对话和子代理命令遵守原 conversation ownership 范围，读取日志不变成新的模型工具调用。

## 1. 设计目标

工具层负责把模型意图转换为可授权、可观察、可取消和可审计的本机操作。它不是对 Shell 的替代，也不应为了“结构化”把成熟命令行能力拆成大量薄包装。

采用以下边界：

- 常用、结果需要有界、需要专用 UI 的操作使用结构化工具。
- 复杂搜索、Git、构建、测试和项目自带 CLI 继续使用 `run_command`。
- 普通非交互命令默认使用 `run_command`；只有用户明确要求可见/右侧/交互终端，或任务确实需要可持续接管的 PTY 时，才创建持久侧边终端。
- 文件写入必须生成 Diff，并经过当前对话权限策略。
- 长时间操作返回稳定 ID，等待超时只结束本次等待，不中止后台工作。
- 不同领域保留明确的等待工具，不合并成语义模糊的万能 `wait`。

## 2. 当前内置工具清单

## 2.1 多 Tool Call 调度矩阵

模型一轮可以混合返回多个独立 `toolCalls`，但最多 32 个。超过上限时 Runtime 将本轮模型响应归类为 `MODEL_RESPONSE_INVALID`，整批工具均不启动，不能截断后执行前 32 个。这个批量请求不代表所有调用都可以同时执行：Runtime 先由每个 Tool Handler 声明调度策略，再把连续的同类安全调用按有界窗口交给 LangGraph `ToolNode`；结果始终按原始 `toolCallId` 回填，不能按完成先后拼接。

每条 Timeline 工具记录会保留 Runtime 的 `executionMode`（`parallel` 或 `serial`），用于前端显示实际调度结果；它不是模型参数，也不代表同批所有工具都能并行。

`toolCallId` 必须在本轮内唯一，也不能复用当前模型上下文中已经出现过的 ID。`createAgent`/ToolNode 用该 ID 关联完成结果；重复 ID 会让新调用被误判为旧调用。Runtime 在任何新工具启动前拒绝同轮重复；跨轮复用则拒绝该轮新响应，保留此前已经完成的工具事实，并统一映射为 `MODEL_RESPONSE_INVALID`。未知工具不终止整个 Run，而是持久化失败工具行并返回对应失败 `ToolMessage`，让模型下一轮修正工具名。

| 调度组 | 当前工具 | 执行规则 |
| --- | --- | --- |
| 并行只读 | `read_file`、`search_text`、`find_files`、`read_attachment`、`view_attachments`、`web_search`、`list_project_operations`、`list_background_commands`、`list_agent_conversations`、`read_agent_conversation`、`list_subagents`、`get_team_work_item_status`、已激活 Skill 的 `read_skill_reference` | 同一连续组按最多 8 个调用一个窗口交给 `ToolNode` 并行执行；超出部分进入下一窗口，结果独立关联，取消传播到每个调用；`view_attachments` 每次最多回看四个历史附件 |
| 并行命令 | `run_command` | 非 `read_only` 模式下同一连续组的独立命令默认并行，每个窗口最多 4 个进程；依赖前序结果或共享可变状态时传 `parallel=false`；`ask_before_changes` 逐个审批，但已批准的独立命令可以重叠执行 |
| 有序副作用／展示 | `present_html`、`write_file`、`delete_file`、`replace_in_file`、`apply_patch`、持久终端工具、浏览器插件工具、`send_agent_message`、`wait_for_agent_message`、`set_team_collaboration_plan`、`spawn_subagent`、`wait_for_subagents`、`end_subagent`、`submit_team_work_item`、任务清单、`load_skill`、各类停止/等待工具 | 按模型返回顺序执行；审批中断、消息投递、生命周期变更、计划发布、状态消费、团队入箱、终端/浏览器标签确认和 Skill 激活不能并发重排 |

文件变更批次在首个写入或审批前先读取并保存每个调用的 `expectedContent`。同一批对同一文件的后续调用不会以第一个写入后的内容重新生成基线，而是在应用时返回 `FILE_CHANGED` 并作废；模型必须重新 `read_file` 后生成新变更。多个不同文件可以逐个审批和写入，但当前不是多文件原子事务，部分成功后不会自动回滚。

`run_command` 的每次调用都启动一个新的无 Profile、非交互 Shell 进程；进程在命令完成、停止、超时或取消后释放，不维护可复用的 PowerShell/PWSH 进程池，也不在命令之间共享变量、当前目录或环境变更。`mode=batch` 是默认模式，适用于编译、测试、打包、迁移等所有最终会退出的命令：执行期间输出持续进入原工具项，在 `yieldTimeMs`（默认 10 秒、0–30 秒）内退出则返回终态，否则先返回 running 和 commandId，模型可继续独立工作；实际退出前仍保留项目操作锁，省略 `timeoutMs` 时最多运行 30 分钟。`mode=service` 只用于开发服务器、watcher 等预期长期存活的进程：在 `yieldTimeMs` 启动观察窗口内展示日志，随后返回 `commandId` 并释放项目操作锁；省略 `timeoutMs` 时不自动超时，应用退出时统一终止。服务应提供简短 `serviceName`；运行时把它与 `commandId`、启动命令、工作目录、启动时间、超时和 Shell 一起保存在活动命令注册表。`list_background_commands` 只返回当前对话仍在运行的项目，不返回 stdout/stderr；模型遗忘 ID 时先查询，再把准确 ID 交给 `stop_command`；服务启动后继续工作，不自动等待退出或反复轮询，后续操作确需就绪时使用有限 batch 命令检查具体条件。完成、停止、超时或取消的命令立即退出活动列表，不会被下一条命令复用。该注册表属于当前桌面主进程，应用重启后不把历史 PID 重新认领为可控进程。SSH、REPL、密码输入等需要后续交互的命令不进入对话内非交互终端，使用 `terminal_control` 创建的侧边 PTY。侧边终端设置中的 Shell、启动路径和字体只控制可见 PTY；普通命令使用应用受控的默认 Shell，仅复用设置中的输出字符集做 stdout/stderr 解码。PowerShell/PWSH 启动时统一把控制台输入、输出和管道编码设为 UTF-8，避免原生程序输出的中文路径在进入 PowerShell 管道时先被旧代码页破坏。

## 3. 搜索与 ripgrep

`read_file` 支持 `startLine + lineCount`（建议，读取行数）或 `startLine + endLine`（含结束行）。未使用的限制可省略或传 `null`；同时提供时仅接受 `endLine=startLine+lineCount-1`，范围冲突仍报错。都省略时最多 400 行，`startLine` 默认 1。单次最多 400 行、250000 字节，按块扫描到指定行即停止。`nextStartLine` 供续读；未到 EOF 时 `totalLines=null`，不为计数扫描尾部。越过 EOF、范围过大或非 UTF-8 内容返回字段问题。〔FACT｜`apps/desktop/src/main/tools/project-tool-registry.ts`；`read-text-lines.ts`〕

`find_files.pattern` 相对 `path` 指定的目录，例如 `path=src-tauri, pattern=icons/icon.ico`；结果仍返回项目相对路径。`search_text.includeGlobs/excludeGlobs` 明确按项目相对路径匹配。无匹配不能证明已知文件不存在，可直接 `read_file` 核实。非法 glob/正则返回字段错误，不能因文件名含 `workspace` 误报未绑定项目。〔FACT｜`apps/desktop/src/main/tools/ripgrep-search.ts`；`project-tool-registry.ts`〕

`search_text` 和 `find_files` 底层均使用应用随包提供的 ripgrep。目录遍历遵守项目忽略文件和固定的重目录排除规则；`search_text.path` 也支持工作区内的单个文件，显式指定文件时直接搜索该文件。空路径表示工作区根目录，未命中返回成功空结果，路径越界仍被拒绝。`find_files.path` 仍只接受目录。〔FACT｜`apps/desktop/src/main/tools/project-tool-registry.ts`；`ripgrep-search.ts`〕

`search_text` 适合：

- 需要路径、行号和有界摘录的常规搜索；
- 字面量或正则搜索；
- smart/sensitive/insensitive 大小写策略；
- 少量 include/exclude glob。

`run_command` 直接执行 `rg` 适合：

- `-A/-B/-C` 上下文行；
- `-c/-l/--stats` 计数、文件名或统计输出；
- 多个 `-e` 表达式、复杂 glob 和类型过滤；
- 与排序、去重或其他命令形成管道；
- 用户需要查看完整原生命令与终端输出。

桌面命令环境会把内置 ripgrep 目录加入 `PATH`，因此不依赖用户另外安装 `rg`。两种搜索入口是互补关系，不互相禁止。`search_text`/`find_files` 的无匹配是成功空结果；`run_command` 则严格按最终退出码判断，`rg` 无匹配或被截断型管道提前关闭时可能返回非零，即使已经产生 stdout。模型应把预期失败的探测与其他检查拆开，并优先用 `maxResults` 限制结构化搜索，不通过 `Select-Object` 等消费者截断 `rg` 管道。

### 3.1 公共网页搜索

`web_search` 适用于需要当前公共网页信息、但不需要登录态或页面交互的查询。它请求 DuckDuckGo Lite，并使用 `parse5` 解析结构化 HTML，不要求 API Key 或付费搜索服务；输入支持 `query`、`maxResults`、`region` 和 `safeSearch`，请求有 20 秒超时，响应大小、结果数量、标题、摘要和 URL 均有上限。搜索失败、网络不可用或被限流时，工具返回统一错误信封，模型可以调整查询后重试，但 Runtime 不自动重放已经完成的网络请求。

该工具不读取项目文件、不要求临时对话附加工作区，也不承担浏览器导航、点击、登录、下载或页面脚本执行；这些能力仍属于后续受管浏览器工具范围。

### 3.2 临时对话的工作区边界

临时对话的定义是“没有关联项目/工作区”，而不是“不能使用工具”。没有工作区时：

- `run_command`、`list_background_commands` 和 `stop_command` 仍可用，命令在该对话独立的系统临时目录中执行，不能访问其他临时对话的命令会话；
- `web_search`、Agent/Subagent、任务清单和已配置的附件工具仍按各自合同可用；
- `read_file`、`search_text`、`find_files`、文件变更和项目冲突工具需要先附加工作区；
- `read_external_file` 不需要工作区，但读取工作区外文件前必须逐次审批；
- 命令仍受当前权限模式约束：只读模式拒绝副作用命令，询问模式逐次审批，完全访问模式只在隔离临时目录内直接执行。

附加或替换目录后，Runtime 才把文件工具和项目操作协调绑定到该目录；移除目录后，后续临时命令继续使用隔离临时目录，不回退到任意用户目录。

## 4. 生命周期合同

应用退出或主窗口销毁时，统一停止定时调度和活动 Run，清除延迟唤醒，过期未决审批，并等待 Run 持久化终态及 Graph 清理；期间不启动 Queue 或自动回复。随后等待本应用持有的 batch/service 命令进程树与 PTY 进程树终止，释放受管浏览器、待确认标签及 HTML 预览。Windows 仅按注册的 PID 使用进程树终止，POSIX 使用应用创建的独立进程组；不按进程名清理用户独立打开的外部软件。数据库和 Checkpointer 只在工作清理完成后关闭；macOS 重新激活先等待旧窗口清理完成，再创建新窗口。关闭期间复用原 ToolCall 状态，不恢复或重放已开始的副作用。

### 4.0 Tool Call 审计顺序

每个模型 Tool Call 以 `runId + toolCallId` 作为重放幂等键。运行时先追加 `tool_call_requested`，Handler 产生可执行提案后追加一次 `tool_execution_prepared`；需要授权且启用 AI 审批时先追加 `tool_approval_auto_reviewed`。低/中风险自动通过后直接执行且不生成长期规则；需要人工确认时再依次追加 `tool_approval_requested` 和用户的 `tool_approval_decided`。批准决定同时把 Tool 持久状态恢复为 `running` 并发出 `tool.started`，因此审批卡在副作用开始前退出等待态；完成或失败后再追加 `tool_result`。若 Run 在决定前停止、失败或重启中断，则追加 `tool_approval_expired` 并把 Tool 行终态化为 `cancelled`；该卡片不再接收审批。“审批已失效”只用于这种决定前已终止的 Run，不能覆盖已经接受的批准决定。当前执行器一次只处理一个审批 interrupt，因此使用标量 `Command({ resume })` 恢复原 ToolNode；批准后必须由原 `toolCallId` 在原卡片继续执行，不能跳到模型节点重新生成一条相同调用。父 Agent 与 Subagent 的图调用各自建立独立的 LangChain 异步配置上下文，审批断点只能写入所属 Run 的 `thread_id`。LangGraph 重放 ToolNode 时，已完成结果会直接返回，已记录的执行意图也不会重复追加或重新执行副作用。〔FACT｜`apps/desktop/src/main/agent/agent-runtime.ts`；`apps/desktop/src/main/agent/langgraph-executor.ts`；`apps/desktop/src/main/storage/thread-log.ts`〕

这些事件目前写入 ThreadLog 的影子审计链，并被 `EventProjector` 幂等索引；SQLite 的 Timeline/Tool 行仍是现有 UI 业务写入链。因而日志写入失败会被记录为 Main 诊断，不能据此假设 SQLite 业务事实已经可以完全由事件重建。〔FACT｜`apps/desktop/src/main/agent/agent-runtime.ts`；`apps/desktop/src/main/storage/event-projector.ts`〕

### 4.1 即时只读

```text
调用 -> 校验项目边界和参数 -> 执行 -> { ok, value }
```

结果必须有数量、行数、字节数或字符数上限。取消信号应终止仍在运行的 ripgrep 或读取操作。

### 4.2 文件变更

```text
读取当前内容 -> 准备变更和 Diff -> 等待权限审批 ->
检查文件未被外部修改 -> 临时文件写入并原子替换 -> 完成事件
```

拒绝、文件已变化、路径越界和项目操作冲突均作为当前工具失败显示。`apply_patch` 支持单个既有文件的标准 `---/+++` diff，以及 `*** Begin Patch` / `*** Update File: path` / `@@` / `*** End Patch` 格式。Update 块按顺序精确匹配唯一上下文，不模糊猜测；支持行尾定位并保留原文件换行。两种格式均走路径校验、审批和原内容冲突检查。多文件、移动、新建和删除指令不支持；新建和删除使用各自工具。标准 diff 的外层包装和可确定的 hunk 行数允许归一化，上下文不匹配仍报错。

编辑工具提示与 Schema 同步声明支持的格式，不按模型名称分叉。代码修改保留请求范围外的原有行为；Subagent 回传后，主对话按原目标判断验收证据，证据不足时检查相关改动或在同一子对话补充验证，不能仅凭构建通过判定功能完整。

### 4.3 命令任务

```text
准备命令并选择 mode -> 等待权限审批 -> 启动进程
batch/service -> 持续输出 -> 观察窗口内退出则返回终态，否则先返回 running + commandId
read_command_output(commandId, offsets) -> 有界增量日志 + 当前/最终状态（不重新执行）
service -> 在 yieldTimeMs 内观察启动日志 -> 返回 serviceName + commandId
        -> list_background_commands / stop_command
```

`list_background_commands` 是找回当前对话活动 `batch` 和 `service` 的 `commandId` 的只读入口，不替代 ID，也不按模糊服务名直接杀进程。`wait_for_commands` 仅保留内部兼容执行，不再向模型注册；历史等待项不单独展示，也不进入模型历史、召回或新压缩摘要，原始审计仍保留。内部等待超时不停止服务；服务自身配置了超时时才会终止进程树。多个独立 `batch` 命令可在同一轮并行启动，观察窗口结束返回后模型即可继续独立分析；依赖步骤必须用 `read_command_output` 确认所需命令真实退出及退出码；非 `read_only` 模式下默认并行，询问模式先逐条审批，审批通过后进入同一并行窗口，依赖命令显式传 `parallel=false`。有限命令始终保留 batch 模式；提前返回不改变进程模式或执行时限。

`stop_command` 只返回 `commandId/status/completedAt/exitCode/error` 停止回执，不返回命令正文或 stdout/stderr。`completedAt=null` 表示尚未确认进程退出；运行日志保留在原命令项中。停止结果仅显示简洁状态，不嵌套终端日志。

### 4.4 项目冲突

```text
文件变更发现冲突 -> 当前变更请求立即作废，返回 operationId 和占用对话 ->
必要时等待占用操作结束 -> 重新读取文件并生成新的变更
命令发现冲突 -> 当前命令请求立即作废 -> 必要时等待 -> 重新评估项目状态并生成新命令
```

协调器以规范化后的真实工作区根路径识别同一项目，不依赖 conversation/project ID；结构化文件变更再按规范化文件路径互斥，命令默认与项目写操作互斥。同一 Run 中独立命令默认进入并行窗口，`parallel=false` 才降级为串行；不同对话仍不能无感知地同时修改项目。冲突不会排队或重放已基于旧状态生成的参数；写入前还会比较 `expectedContent`，发现文件已变化时返回 `FILE_CHANGED`，要求 `read_file` 后重新生成 Diff。等待工具只用于观察占用操作状态，不能恢复被丢弃的旧请求。

### 4.5 Agent 与 Subagent

主对话与 Subagent 按[协作规则](./05-多Agent团队与任务调度设计.md#37-主对话与-subagent-协作优化)运行：结果持久入队、200 毫秒合并唤醒、可选条件等待、用户停止联动；无总结时按 `conversationId + runId` 读取或搜索原子对话。

Agent 消息和 Subagent 都持久化到独立对话。任意普通对话、团队对话或临时 Subagent 都注册 `list_agent_conversations` 和 `read_agent_conversation`，可按 token 预算查询自己或任意另一条对话；临时 Subagent 不注册 `send_agent_message`、`wait_for_agent_message` 或团队计划工具。`spawn_subagent` 创建一个有边界的首轮任务，不复制父对话的模型消息、压缩 Checkpoint、Timeline 或附件引用，只把 `task` 作为首条模型可见用户输入；父 Agent 必须在任务中显式提供必要背景。每轮完成后子对话保持可复用，父 Agent 通过 `send_agent_message` 启动同一 Conversation 的后续 Run，沿用自身历史和上一轮权限模式；确认满意后调用 `end_subagent` 进入只读，删除只由用户触发。复杂任务的最终回答以简短完成回执开头，用单独一行 Markdown `---` 分隔支持细节，简单任务可以直接短答。Runtime 只把回执或有界短答、来源 Conversation ID，以及本轮内置文件写工具记录的最多 50 个去重文件路径通过隐藏结果自动回传给父 Agent；完整结果保留在子对话且不进入父 Timeline，Shell 间接修改不冒充已知文件清单。旧模型未输出分隔线时继续使用有界截断兜底。父 Agent 正常情况下也不为取回结果主动列出或读取子对话，只在结果明确截断且影响任务，或用户要求审计时按预算读取。Team Lead 与团队成员不使用 Subagent：用户先从模板显式创建 global、project 或 conversation TeamInstance，实例内再复用持久 Team Lead/成员 Conversation；模型交办只选择当前来源可见的 `teamInstanceId`，不能隐式创建另一支团队。Lead 只通过 `send_agent_message` 和 `wait_for_agent_message` 分派、等待和汇总。`send_agent_message(expectReply=true)` 可用 `replyInstruction` 指定完成回执重点；成员以单独一行 Markdown `---` 分隔回执和详细结果，完整最终回答保留在成员 Conversation，Runtime 只向发送方投递分隔线前最多 1000 字符和来源 Conversation ID。`list_agent_conversations` 返回显式运行状态；`read_agent_conversation(maxTokens, query?, beforeSequence?, historyScope?)` 默认查询最新 Checkpoint 已覆盖的原始历史，没有 Checkpoint 时回退到全部历史，显式传 `historyScope=all` 才跨越 Checkpoint 查询整条历史。关键词最少 1 个字符，命中后带回所属完整原始轮次；`pagination.nextBeforeSequence` 用于继续读取更早页，全部结果仍受 Token 预算约束。团队成员消息只能投递给同一持久 TeamInstance 的参与者，且每条任务分派绑定 WorkItem 记录以供审计。

来源主 Agent 交办 WorkItem 后可以继续本对话的其他工作，不自动等待团队，也不把协作投影持续注入每轮请求。`get_team_work_item_status` 允许它稍后按需恢复近期 WorkItem ID，或读取一个 WorkItem 的有界任务计数、参与者运行态、最近输出和结果摘要；查询按来源 Conversation 授权，结果不含完整需求、事件、协作边、节点坐标或成员完整 Timeline。

受管 WorkItem 的 Team Lead 还可调用 `set_team_collaboration_plan`。它先用 `list_agent_conversations` 取得当前参与者 Conversation ID，再在第一次委派前发布完整有向路线；后续变化发布下一版完整修订。模型不能传入 `workItemId`，Main 从调用者所属的运行中 WorkItem 补齐，并要求调用者正是根 Team Lead。计划是软约束：发布失败返回真实工具错误，但没有计划边仍可合法调用 `send_agent_message`，实际偏差会被统一投影标记为 `ad_hoc`。投影只统计方向、类型、已读状态和时间，不把消息正文复制到图中。〔FACT｜`apps/desktop/src/main/agent/agent-communication-tool.ts`；`apps/desktop/src/main/storage/agent-database.ts`〕

`spawn_subagent.icon` 的模型工具 Schema 继续声明受控枚举，Renderer 只映射本地 Lucide 组件，不接收模型提供的任意 SVG、图片 URL 或组件名。执行端将枚举外的可选值归一化为“未提供”，避免装饰参数阻断 Subagent 创建。只有合法的显式图标随子 Conversation 持久化；绑定 Agent Profile 不复制普通头像。没有显式图标时保持 `avatarIcon = null`，Renderer 根据子 Conversation ID 即时生成稳定的 5×5 对称 Identicon。`name` 只负责身份展示，`task` 继续作为实际模型输入且不参与头像哈希。

`wait_for_subagents` 的 `timeoutMs` 可省略，`waitFor` 支持 `any/all`，等待对象固定为调用时的执行轮次。超时或无进展只解除等待，不取消子任务；失败、取消、删除同样解除对应等待。正常审批等待不算卡死。结果通过持久队列合并唤醒；用户主动停止后禁止自动唤醒，直到用户继续。

### 4.6 任务清单

```text
update（不存在则创建，可有多个 running）-> close
```

任务清单只适用于确实需要多步推进的任务。简单任务不应为了调用工具而创建清单。它只投影所属对话的整体进度，不记录某一步由主 Agent、Subagent 或其他执行者处理；凡已被接管并正在推进的步骤都可标记为 `running`，独立步骤允许同时处于 `running`。状态发生实质变化时才更新，并把同一批变化合并到一次完整更新中；能与实际读取、检查或收尾工具同轮调用时，不为清单元数据单独消耗模型轮次。完成后模型可以主动关闭，用户也可以手动关闭。`blocked` 和 `failed` 步骤必须通过 `reason` 提供一条简短原因；其他状态不携带该字段，详细诊断仍归属 Assistant 或工具 Timeline。

### 4.7 Skill 上下文

```text
系统上下文注入 Skill 目录摘要
  -> 模型调用 load_skill(skillId)
  -> Runtime 校验作用域、启用状态、MCP 依赖并读取 SKILL.md
  -> Graph State 保存 id/version/contentHash
  -> 下一轮模型请求临时注入正文
  -> 按需调用 read_skill_reference(skillId, relativePath)
```

Skill 正文是本轮模型输入，不是聊天历史。每个 Skill 必须位于与 Frontmatter `name` 同名的父目录中；Runtime 首次登记时由该名称生成稳定 `skillId`，全局重名使用数字后缀区分，模型只能从当前目录摘要选择 ID，不能猜测文件路径。ContextManager 在历史裁剪前固定预留正文预算，正文实际注入和用量展示使用同一预算；无模型窗口时按 48,000 Token 计算。工具结果只返回加载摘要和哈希；`read_skill_reference` 只允许已激活 Skill 的 `references/`、`templates/` 相对 UTF-8 文本文件，读取前检查字节上限，并拒绝绝对路径、遍历、符号链接、NUL、非法 UTF-8 和超大内容。`custom` Agent 的 `skillIds` 必须统一约束目录、加载、reference 与恢复注入，不能只隐藏目录；`inherit_all` 才继承全部满足作用域的 Skill。`project`/`team` Skill 分别要求项目工作区/团队会话。Skill 内容不能覆盖系统安全规则、项目授权范围或审批策略。Run 结束后 Graph thread 会清理；会话删除任务也会清理对应 threads。

### 4.6 权限授权范围

审批卡提供“允许一次”“本对话允许”和“拒绝”。会话授权由 Runtime 按 conversation 管理，只对完整相同命令或同一工具与相同路径生效；命令中的 `*` 等字符按原始命令正文精确匹配，不解释为权限通配符。卡片不提供模糊命令族或 Agent 永久授权。Agent Profile 中仍可由用户在设置页显式维护 allow 规则，只有该持久规则使用末尾 `*` 前缀语义，且不由一次审批自动生成。持久终端创建和命令使用同一 `run_command` 权限类型；浏览器可见副作用使用独立 `browser_control` 权限类型。选择 AI 帮我审批时，仅低/中风险明确操作自动通过，删除、工作区外读取、破坏性/提权命令和任何不确定情况仍请求用户审批。

### 4.7 工作区终端标签

侧边终端保留原生 Shell 提示符、启动诊断和命令结果；启动回放与实时输出按游标去重，尺寸稳定后再适配，避免 ConPTY 重绘残留。不得通过清空命令前输出或禁用用户 Profile 来隐藏异常。

普通“在终端执行/打印”默认使用 `run_command`，不隐式打开侧边终端或浏览器。`terminal_control` 只填写所选动作的参数；未使用字段可省略或传 `null`，适配要求全部属性存在的模型接口。动作必需字段、未知字段和非空的不适用字段仍严格校验，不接受伪造 ID 或占位命令。

```text
模型调用 terminal_control(action=create, name?) -> Runtime 固定当前 conversation/project ->
准备待批准动作 -> 权限判定/必要时 interrupt 审批 ->
批准后进入项目命令操作协调并创建 PTY -> Main 请求 Renderer 创建标签 ->
Renderer 计算唯一名称并确认 ->
工具结果 { requestedName, resolvedName, nameAdjusted }
```

这条工具链只创建项目右侧的用户可见标签，不写文件、不执行模型传入的 Shell 命令，也不接受模型指定的绝对路径、Shell 或环境变量。普通命令、构建、检查和测试默认走 `run_command`，不会打开可见标签；只有用户明确要求可见/右侧/交互终端，或任务确实需要用户可观察、可接管的持续 PTY 时，模型才调用本工具链。批准前不得创建 PTY 或请求 Renderer 建标签；LangGraph 恢复时复用同一待批准动作，以 `runId + toolCallId` 防止重复创建。标签名称必须是 1 至 120 个字符；若请求名与任一已打开标签重名，Renderer 依次使用 `名称 (1)`、`名称 (2)`，并以确认结果作为模型可见的唯一事实。确认超时或当前会话不再对应请求项目时，工具失败，模型不得假定终端已打开。

`terminal_control action=write` 同样先审批，再在项目命令操作协调边界中向所属 PTY 写入一次并读取有界即时输出；`action=list/read` 只读当前对话拥有的活动终端和有界转录，不审批；`action=close` 先审批，再关闭 PTY 并通知 Renderer 移除对应标签。`yieldTimeMs` 只是即时采样提示，通常省略；超过 5000 毫秒时按 5000 毫秒执行，不因模型给出过大值让整次调用失败。协调记录在发送和即时采样结束后释放，长时间运行的开发服务器继续由 PTY 会话生命周期管理，不能用一个永久项目写锁阻塞用户后续编辑。

外层 PTY 存活与内层 SSH 连接是两个状态。可复用 SSH 必须以不带远程命令的交互式 `ssh [options] user@host` 建立，认证完成且 `terminalContext.kind=ssh_connected` 后，后续服务器命令都传 `expectedContext=ssh`。工具增量检查终端输出；若出现连接关闭、重置、拒绝、超时、域名解析失败、Host Key 校验失败或认证失败，则标记 `ssh_disconnected` 并以 `TERMINAL_CONTEXT_MISMATCH/reconnect_ssh` 拒绝远程投递，避免命令误落到已经恢复的本地 Shell。写入前发现断线时结果明确为 `delivery=not_sent`，重连后可以重试；写入后才发现断线时结果为 `delivery=unknown`，模型必须先核对远端实际状态，不能自动重放可能已有副作用的命令。`ssh host command` 是一次性远程执行，结束后仍属于本地上下文，不能当作持久连接复用。

PTY 与 `terminalId` 只在当前桌面主进程和终端进程存活期间有效，不能从历史消息恢复已经退出或因应用重启丢失的 PTY。用户从界面手动打开的终端不会自动归属当前模型对话，模型不得猜测或复用其 ID；`action=list` 只返回当前应用会话中由 `terminal_control` 为当前对话创建且仍存活的终端。执行或读取遇到失效 ID 时返回稳定的 `TERMINAL_UNAVAILABLE` 和 `recreate_terminal` 恢复指令，模型先 `list` 查找活动终端；没有可用项时再 `create`，不得重复重试旧 ID。

### 4.8 首方浏览器动作

页面查看（2026-10-16）：`action=observe` 在一次调用中返回有界 DOM 文本、元素引用和当前截图；截图作为模型视觉输入，并由同一条工具记录展示。无需为了显示刚查看的页面再调用 screenshot。`action=screenshot` 保留为仅刷新图像、不重取 DOM 的操作，界面明确标为“截取页面”。

`action=open` 可传 `background=true`，直接创建后台渲染会话，静默登记侧边标签，不选择标签、展开侧栏或等待前端确认；默认 false 保持可见浏览器兼容行为。后台可指定 `width`（320–2560，默认 1280）、`height`（240–2160，默认 800），均为 CSS 像素，不跟随用户页面缩放。返回包含 `background`，`list` 同样区分后台与可见会话。截图复用 `action=screenshot` 的模型附件，DOM 观察及交互继续受原工具权限与所属对话约束。后台页面使用临时 partition、无密码 Preload、禁止下载，不改变用户的浏览器登录状态；会话显式关闭或所属 Run 完成／失败／取消后释放，可见标签不随 Run 结束关闭。模型说明与内置 browser-use Skill 要求网页验收优先后台模式，并先验证本地 HTTP 服务可用。

`browser_control` 通过 `action` 区分打开、列出当前对话会话、观察、截图、导航/前进/后退/刷新/停止、点击、移动、按下/释放、拖拽、填写、选择、按键、滚动、等待和关闭。`show` 按用户要求显示已有标签并保留页面状态；`list` 同时发现当前对话的手动标签；`close_tabs` 的 browserIds 关闭选定标签，exceptBrowserIds 保留选定标签并关闭其余，两者都省略时关闭本对话全部标签，禁止同时传入，两阶段审批冻结目标集合。打开、显示、导航与所有可改变页面状态的动作先生成待批准动作，使用同名权限类型；批准前只能解析参数并校验目标会话仍归属当前项目对话。填写/选择内容仍保留在当前 Tool Call 参数和审计记录中，但持久允许规则只保存动作及元素引用，不保存输入正文。`action=list`、`action=observe`、`action=screenshot` 和 `action=wait` 为只读动作，可直接执行。语义操作使用最新元素引用；视觉操作使用最新截图的 CSS 像素坐标并通过 Chromium 原生输入分发执行。截图通过内部模型附件返回，同时保存到对话附件目录；工具结果和 tool_result.attachmentRefs 保存图片引用、尺寸与坐标系，展开详情可查看图片，JSONL 不保存图片字节；模型请求只携带最新浏览器截图字节，避免连续视觉观察撑大上下文。取消信号在批准后执行副作用前再次检查；审批拒绝或应用策略 `unavailable` 时不调用受管浏览器控制器。复杂浏览器任务应先加载 `browser-use` Skill；静态公共资料优先 `web_search`，稳定的非交互网络或项目操作优先 `run_command`。

Subagent 首轮继承创建时的权限模式，后续 Run 继续使用该子对话上一轮冻结的权限模式；父对话的 `once`/`session` 规则不会跨 conversation 复制，显式配置的 Agent allow 规则仍可按绑定 Agent 共享。审批事实始终属于子 Tool/Run，子页面保留完整卡片，父页面只从活动子 Run 的 `awaiting_approval` Tool 派生一个输入框上方的操作入口。两个入口提交同一 `runId + toolId`，先处理后再次提交返回 `APPROVAL_EXPIRED`。

## 5. 统一结果与展示

### 5.1 模型可见工具合同

模型请求只发送工具名、用途描述和输入 JSON Schema。输入 Schema 由执行端的 Zod Schema 使用 `io=input` 自动生成，并移除 provider 无需的 `$schema` 元字段；因此默认值、必填字段、枚举、UUID、长度上限和对象的 `additionalProperties` 与实际执行校验保持同一来源。无法用 JSON Schema 表达的跨字段规则、规范化和安全校验（例如 `read_file` 的 `startLine/endLine` 范围、任务清单阻塞/失败原因、字符串 `trim` 和工作区路径边界）继续由执行端 Zod 或领域校验，并在工具描述或错误结果中说明；能定位到具体字段的规则应通过字段级 issue 返回。Provider 返回的参数先由统一解析器处理；非法 JSON 或非对象参数使用稳定的 `TOOL_ARGUMENTS_INVALID` 错误码和字段问题，不依赖错误文案分类。

工具校验失败时，除现有 `agentError`、`error` 和 `ok=false` 外，模型可获得有界的：

```json
{
  "recovery": {
    "action": "fix_arguments",
    "instruction": "根据 issues 修正本次工具参数后重试；不要重复提交相同参数。",
    "issues": [
      { "code": "invalid_format", "path": ["commandId"], "message": "Invalid UUID" }
    ],
    "retryable": true
  }
}
```

`issues` 最多保留 8 项，字段路径、校验代码和消息均有长度上限。`recovery.retryable=true` 只表示模型可以根据问题修正参数后发起一个新请求；它不等于运行时自动重放，文件、命令和审批等有副作用操作仍必须遵守其原有权限和生命周期。文件版本过期或文件变更发生项目操作冲突时使用 `recovery.action=reread_and_rebuild_change`，明确要求丢弃旧参数、重新读取当前文件并生成新的变更；命令冲突只返回等待和重新评估指引，不伪装成文件恢复。

内置工具成功结果统一使用：

```json
{ "ok": true, "value": {} }
```

模型可见结果允许使用比 UI/本地审计更紧凑的稳定投影：超过长度上限的 Tool Result 从第一次发送给 Provider 起即保留确定性的头部、错误/警告行和尾部，完整原文继续保存在 Timeline/ThreadLog。任务清单工具只返回更新或关闭确认，完整清单由下一轮动态任务上下文提供，避免同一状态在工具结果中重复携带 UUID、时间戳和全部任务正文。

参数校验和非预期执行异常使用统一 AgentError 信封；审批拒绝、命令非零退出和项目操作冲突等预期生命周期结果使用 `{ ok: false }`，并在 `value` 中保留退出码、标准输出、标准错误、超时、截断或占用者信息。经过 LangGraph `ToolNode` 的工具适配器如果抛出非取消、非审批 `interrupt` 异常，Runtime 必须转换为有界的失败 `ToolMessage`，将工具行持久化为 `status=failed` 并发送一次 `tool.completed`；不得把诊断异常吞掉，也不得自动重放该副作用调用。取消和审批中断必须传播给图执行器；如果上游编译图把顶层 `GraphInterrupt` 作为异常抛出，执行边界必须把它归一为同一审批暂停/恢复流程，不能将 Run 标记为内部错误。Subagent 已改为相同成功信封，避免专用 UI 无法解析。

UI 展示规则：

- 命令展示 Shell、完整命令、stdout/stderr、退出状态和 `commandId`。
- 文件变更展示红色删除、绿色新增的 Diff；错误留在同一变更卡内。
- 目录、搜索、附件和跨对话读取使用有界结构化结果。
- 项目占用展示操作内容、占用对话和状态。
- 多工具调用按批次折叠，用户按需展开，不默认铺开所有原始 JSON。
- 当前连续工具组的标题显示最新工具状态或实时推理摘要；后续正文结束该组后，恢复按优先级排列的操作汇总。读取文件／文本附件只展示路径或名称、行／字符范围和状态，正文保留在原始调用详情及模型上下文，不在对话中重复铺开。
- `present_html` 的相同完整路径只在最新成功且已结束的交付位置挂载预览，保留旧工具事实；预览置于最终文字说明之前，本轮文件变更卡片仍置于回复正文后、复制及分叉操作前。临时对话可按所属对话打开侧边浏览器，不要求存在项目；打开失败显示于预览标题的错误图标提示。

## 6. 当前缺口与扩展顺序

### 6.1 下一阶段必须补齐

1. MCP Runtime：当前已有配置、编辑和存储，但桌面能力标记仍为 `mcp: false`，还没有动态发现和执行 MCP 工具。
2. Skill Runtime：已接入 `AgentRuntime + LangGraph`。目录摘要、`load_skill`、正文哈希快照、统一预算的正文临时注入和受控 reference 读取已有自动测试；运行中的 Skill 文件发生变化会拒绝静默恢复。仍未实现 Skill 脚本执行、真正的 MCP Runtime 依赖和 running Run 的自动重放。
3. 多文件补丁事务：一次审批多个文件时，需要批量 Diff、逐文件并发冲突检查、失败回滚和多文件刷新事件，不能直接复用单文件 `PreparedFileChange`。

### 6.2 按需求再增加

- 浏览器文件传输与凭据：当前浏览器插件已提供会话恢复、语义观察、模型可见截图、前进/后退/刷新/停止、真实鼠标点击/移动/按下/释放/拖拽、文字输入、表单填写/选择、键盘、滚动、条件等待和关闭。文件上传、下载产物读取、保存密码/自动填充与外部浏览器登录态接管仍需另行设计边界；不能把用户浏览器的 `WebContentsView` 直接暴露为任意脚本执行环境。
- 持久 PTY 的回收与完成检测：当前模型可读写自己在项目对话中创建的侧边 PTY，创建和命令均已接入统一审批与项目操作协调；普通构建和测试仍优先使用有界、可等待和可取消的后台命令任务。任意交互 Shell 无可靠的跨 Shell 命令完成边界，因此项目操作协调只覆盖命令发送和即时输出采样，不覆盖后台进程的全部存活期；跨对话共享、任意 Shell/工作目录参数及临时对话 PTY 仍未开放。
- Git 专用模型结果：右侧用户 Git 工作区已经提供结构化状态、文件级 Diff 与受限的人工 Git 操作；这些 IPC 只服务用户界面，不成为模型工具。模型仍使用 `run_command` 执行 `git status/diff/log`，需要提交图或可点击 hunk 时再设计独立工具合同。
- 二进制文件写入、移动和复制：明确产品场景后设计审批和预览，当前不通过文本工具伪装支持。

### 6.3 当前不引入

- 不增加 `get_current_directory` 或 `get_project_info`。项目对话已经绑定动态工作目录。
- 不增加 `run_rg`、`run_git`、`run_test` 等 Shell 薄包装。
- 不增加万能 `wait`。命令、Agent 消息、Subagent 和项目冲突的完成条件及返回值不同。
- 不引入向量检索工具替代代码搜索。文件名、文本和符号定位优先使用 ripgrep；达到明确语义检索需求后再评估索引。

### 6.4 外部开源实现的复用边界

- 不直接搬运 PI Agent / Codex 的完整工具运行时：它们分别绑定自己的 TypeScript Harness 与 Rust CLI / Sandbox 生命周期，直接复用会绕开本项目既有的审批、项目锁、Timeline 和 IPC 合同。
- 优先复用已经处于稳定边界的底层库，并保留本项目的适配层：例如 `@vscode/ripgrep` 用于受限搜索、`diff` 用于变更展示、`file-type` / `mammoth` / `unpdf` 用于文件识别与提取。库升级或替换只影响对应 Handler，不改变 `ToolRuntime` 的统一权限和结果合同。
- 新引入第三方工具前先补“Schema、权限、幂等、结果上限、取消、错误信封、测试矩阵”；没有通过该矩阵，不因为开源项目热门而接入生产主链。

## 7. 测试门禁

每次调整工具至少验证：

1. 参数 Schema 与模型看到的 JSON Schema 一致。
2. 项目路径不能越界，忽略规则和结果上限生效。
3. 成功和失败信封能被 Agent Runtime 与 UI 同时解析。
4. 审批拒绝、文件外部变化、命令非零退出和超时显示在原工具卡中。
5. 服务命令启动后直接返回，可查询和停止；普通命令并行执行并等待全部完成，不会串输出或复用错误 ID。
6. 两个对话操作同一项目时能返回占用者，并在等待后重试。
7. Subagent 和 Agent 消息等待超时不会取消后台任务或丢失后续唤醒。
8. Skill 的正文不进入 Timeline；reference 只能读取允许目录的有界文本，文件变化和越界路径返回可恢复错误。

命令提前返回与结果回收（2026-10-16）：`run_command` 的 batch/service 共用启动、流式日志和有界观察机制，`yieldTimeMs` 与执行时限 `timeoutMs` 分离。普通命令默认上限仍为 30 分钟，服务默认不限时；取消与退出仍清理进程树。`read_command_output` 只读当前对话的命令，支持 stdoutOffset/stderrOffset（接上次 nextStdoutOffset/nextStderrOffset）、每流默认 12000/最多 32000 字符、0–30000ms 有界观察；返回 hasMoreOutput、status、completedAt、exitCode、timedOut、truncated。原有每流 200000 字节日志保留上限不变，超过上限明确标记截断；日志不会持续自动注入模型上下文，仅调用返回的有界结果进入上下文。成功读取不另建展示卡片，读取错误仍可见。进程退出以 runtime_activity_updated 更新原 ToolCall 的持久卡片，不追加重复模型 ToolMessage；重启把失去进程会话的 running 收据标为已中断，不重放。模型必须先确认依赖命令退出，不能把 running 当成成功，也不应无意义紧密轮询。

### 2026-10-16 团队上下文与容量工具

`get_team_context` 是团队内的有界只读工具，只有属于实例的 Conversation 才提供；每次 1–20 个任务，可按成员过滤，以 `beforeWorkItemId` 继续分页，总摘要约 16,000 字符。只能读取当前实例，游标和成员不能跨实例；完整证据继续使用 `read_agent_conversation`。

`resize_team_workers` 是串行协调工具，只提供给实例负责人。执行按当前 Run 冻结的 full_access 权限校验，不能用用户后来修改的对话权限提升旧 Run。每岗位 1–8 位，执行工作区配额最多 32；忙碌或仍有待处理消息的成员不可移除。

快速协作继续复用 Queue/Steer、任务清单、Subagent 和 Agent 回执。`list_pending_messages({offset?,limit?})` 分页预览，正文每项最多 1000 字符，不消费。`claim_pending_messages({pendingMessageIds})` 选择 1–5 条唯一来源 ID；后端核对当前 Run 最近用户输入之后存在成功 `spawn_subagent` 或向自有子代理发送独立任务的 `send_agent_message`，失败调用、通知和 Steer 均不算交接。所选 ID 必须全部属于当前对话的待办 Queue，整批验证后才在下一安全模型节点写入消费事实；重复领取、暂停或外部 ID 均不绕过门槛。新输入不撤销旧任务。

`send_agent_message` 保留 `conversationIds` 数组。`expectReply=true` 发给自有 Subagent 时默认 `deliveryMode=queue`，忙碌时保持未消费，不进入当前模型调用，也不归入当前任务回执；空闲或当前 Run 结束后每次启动一项，复用原子代理上下文。显式 `deliveryMode=steer` 用于修改当前任务。通知和其他持久 Agent 仍沿用原投递行为；显式 Queue 仅接受自有 Subagent 的独立任务。所有接收者仍先校验、原子保存，再逐一通知。

## 2026-10-17 持久任务与群聊工具

`list_task_contexts`、`get_task_context` 查询长期任务与分页来源，`update_task_context` 创建/修订并绑定当前 Run，`link_task_context` 记录已有消息证据。模型先查候选，再决定复用或创建；该语义判断不是运行时的确定性分类保证。摘要写入受维护者和修订号约束，成员可补证据而不覆盖负责人结论。

快速协作由主对话维护右上角的持久“任务列表”，委派前为已接收目标查重并登记，收齐回执后更新；`update_task_list` / `close_task_list` 仅维护对话上方的“任务清单”，子代理可按需使用，不代替或重复主任务记录。同 Run 处理多个目标时，模型应明确指定对应原消息来源；显式 source 不再额外关联当前最新的另一条输入。若本 Run 已绑定多项任务，更新其中已有任务但省略 source 时只维护原来源，不猜测最新输入属于哪项任务；单任务 Run 的原默认来源行为保留。Subagent 的 task_result 是隐藏传输回执，不作为不存在的父对话 Timeline 消息关联；原执行对话的最终结果沿 run.finished 关联到任务，回执继续恢复父对话的任务绑定。

团队成员额外获得 `read_team_messages`、`post_team_message`。读取默认最多 3 条、上限 5 条，每条默认 2000 字符；单条按 messageId/offset 继续，明确读取整条时最多 16000 字符。只有实际完整提供且连续的消息推进该成员游标；用户游标独立。任务候选为有界片段，完整目标与证据按需读取。

查询沿用并行读工具策略，修订和公开发言串行执行；成员身份与团队范围从调用上下文解析。同一 Run/ToolCall ID 的重试使用稳定业务键；公开发言提交成功而工具结果丢失时不会新增重复消息。

### post_team_message 的原成果交付（2026-10-18）

沿用原发送工具的串行执行、Run／ToolCall 幂等键和审计。fileReferences 中发布自己的文件只填 {path}，不填 sourceMessageId；转交他人成果填 {sourceMessageId,path}，来源须已在本群显式发布。成功发布后不为关联旧消息再次发布同一文件，replyToId 仅表达回复关系。旧成果无结构化来源时作者补发一次即可，无需读写文件或命令。

负责人核对已有验证材料，默认最终在群里引用成员原文件。禁止仅为交付复制、重写同一成果或重复运行已完成检查；用户要求、缺陷、产物变化与真实集成风险按需处理。来源校验不在事务内读取文件，实际读取／预览仍由既有文件授权端口完成。

后台浏览器键盘验收修复（2026-10-18）：CDP 激活按键保留标准 key／code 与虚拟键码，Enter 的 keyDown 携带回车文本，Electron 的 Space 规范为 DOM 空格；keyUp 不带文本。修复此前原生按钮在后台验收中键盘无反应的误报，避免据此反复改动正确产品。仍使用隐藏浏览器，不聚焦桌面窗口，可见浏览器路径不变。

群发送工具收尾（2026-10-18）：post_team_message 的工具参数可选 continueWork，仅为当前执行控制，不进入公开消息协议。正式回复或委派交接默认在本工具批成功后结束本轮；中间进展确需继续使用工具时显式 true。成功工具结果记录 turnComplete，失败不收尾，允许修正后重试。业务任务完成／验收状态单独维护，不能因本轮结束自动标为已验收。
