命令时限与重启恢复（2026-10-16）：run_command 仍使用同一执行器区分 batch 和 service。batch 实时输出，观察窗口结束后可先返回 running 与 commandId，默认执行上限 30 分钟，显式 timeoutMs=null 可关闭时限，供超长构建使用；service 启动后返回，省略时限时持续运行，可查看日志并停止。数值时限仍为 1 秒至 30 分钟。用户要求固定运行时长时，命令应自行按次数或截止时间正常退出，不以无限命令加工具超时实现。应用中断后不重放在途副作用，所属 Run 已结束却仍标为 running 的工具在恢复和历史投影时收敛为失败并显示中断原因；已收到的完成结果与活动 Run 保留。


HTML 片段尺寸补充（2026-10-16）：缺少有效前置 DOCTYPE 的预览副本自动补 HTML5 DOCTYPE，使短片段按标准模式测量，避免兼容模式的 body.scrollHeight 至少等于 iframe 初始 320px 而留下空白。显式文档类型与作者源码保留，源码查看及复制不增加文档包装。

分页交付（2026-10-16）：present_html 在既有 {path} 之外支持 {pages}，两者必须且只能提供一个。pages 含 2–12 项，每项为 {title,kind:"code",html} 或 {title,kind:"file",path}；title 去首尾空白后为 1–100 字符，文件路径沿用既有边界，内联 HTML 合计不超过 1,000,000 字符且 Main 限制合计 1 MB UTF-8。成功结果为 {ok:true,value:{presentation:{kind:"html_gallery",pages}}}，完整组随 ToolCall 保存，内联项保存源码、文件项仅保存路径，不保存临时 URL；无需新增表或 IPC。每组交付独立保存，仅在该 Run 结束后显示在最终文字说明之前。单文件交付继续按完整路径保留最新成功位置。分页按需加载并在 Renderer 内存中保留已访问项，切页复用 iframe，不持久化临时 URL。各页按自然高度显示（520px 为基准，超出不超过 1/3、即整数高度最高 693px 时完整显示，更高时按 520px 内部滚动），首次加载占位沿用上一页高度，源码按内容撑高，不强制整组等高；缓存使用对话页面的一小时期限，到期仅释放屏幕外项，可见项离屏后再释放，回到可视区按需重建。对话页面缓存卸载或软件关闭一并释放。错误、源码、复制和侧边浏览器操作均属于当前页。

## HTML 预览合同（2026-10-15）

缓存切换补充：隐藏 iframe 与隐藏卡片不发布或采纳尺寸报告；恢复可见、容器宽度变化后由父容器请求重测，避免隐藏时的零宽测量覆盖已保存的自然高度。

展示投影补充：同一对话内，相同完整相对路径只保留最新成功且 Run 已结束的交付面板，新的活跃或失败交付不替代已有成功面板。历史 ToolCall 不删除，不新增持久化字段。HTML 交付在最终文字说明之前显示，本轮文件变更卡片仍在助手正文／附件后、复制和分叉操作前显示。侧边浏览器打开／关闭请求按所属对话的 `projectId ?? conversation.id` 校验，不以当前项目是否存在过滤临时对话；预览操作失败以标题错误图标和悬停／聚焦提示呈现。标题栏以单个播放／代码图标切换源码与预览，切回预览即重新创建快照并释放旧引用，不再提供独立刷新按钮；HTML 源码使用带语法高亮的只读虚拟视图，按内容撑高，最大 520px 且不超过 55dvh，复制始终保留完整原文。打开侧边浏览器先创建隔离空白会话并确认标签显示，再开始页面导航，页面资源不阻塞标签出现；导航失败仍向卡片反馈并关闭标签与会话、释放预览引用。打开请求未结束时按钮显示忙碌且禁止重复点击。

模型目录补充：GPT-6.1 Sol/Astra 内置默认档位加入现有 `custom_effort:ultra`，沿用既有自定义 effort 传输，不扩充协议枚举。仅仍匹配旧默认配置的目录升级，用户修改过的选项保留。Renderer 模型状态缓存更新通知已挂载的选择器，不改变运行中模型快照；上下文 K/M 输入归一为既有整数 Token 字段。

模型通过 `present_html({path})` 显式交付已有 HTML 文件。单文件输入接受一条工作区相对 POSIX html/htm 路径，最长 4096 字符，拒绝 URL、绝对路径、父目录段、多行、查询／片段和额外字段。成功工具结果为 `{ok:true,value:{presentation:{kind:"html",path}}}`，沿用 ToolCall 的持久化、Run 归属、幂等和历史重放，不新增数据库表，文件交付不保存 HTML 正文，各类交付都不保存临时预览 URL。Renderer 仅解析已完成且结果 Schema 有效的 present_html 调用，Run 不再活跃后将展示面板放到该轮最终文字说明之前；无最终正文时仍可跟随工作过程显示。失败、取消、无效结果和普通文件编辑不产生面板。普通 html/htm 代码块在闭合后默认预览，未闭合时保留源码；不再解析 html-preview 文件引用标记。普通 HTML 链接仍由点击触发。

预览 HTTP 文档通过 parse5 Tokenizer 只扫描确定 Doctype／head 插入位置所需的文档前缀，不在 Main 构建整篇 DOM，再注入独立的尺寸上报脚本，保留 Doctype、文档原结构及 `source` 原文。创建 URL 后仍保留加载提示和可切回源码的忙碌按钮，直到当前可见 iframe 首次报告有效尺寸或触发 load；旧 frame 与无效消息不能结束加载状态。沙箱向父窗口发送严格消息 `{type:"html-preview.resize",id,height}`；id 须为当前预览 UUID，height 须为 1–20,000 的整数。Renderer 同时核对 `event.source === iframe.contentWindow` 与不透明 origin `null`，按自然高度展示，不设最小高度，以 520px 为基准：自然高度不超过 520 × 4/3（整数最高 693px）时完整显示，超过则按 520px 内部滚动（未收到报告前 320px）；超长页面在 iframe 内滚动，刷新或卸载拒绝旧 frame 消息。iframe 加载后可用 `{type:"html-preview.measure",id}` 请求重新测量；上报脚本只接受父窗口及匹配 id。嵌入页通过零优先级、置于作者样式之前的 body 默认样式清除浏览器页边距，并以 flow-root 包含子元素外边距；作者显式声明的边距和 display 仍优先，源码与复制原文不变。html/body 使用 border-box，使视口高度包含内边距；测量包含根节点底部外边距，避免真实内容未超上限时出现滚动条；自然高度测量仅临时覆盖根节点的 height/min-height，再恢复原值，避免 100vh 随 iframe 高度形成增长循环；侧边浏览器顶层打开时不启动尺寸上报或调整盒模型。

`html.preview` / `AgentClient.htmlPreview` 接受严格判别联合：`{kind:"file",conversationId,path}`、`{kind:"code",conversationId,html}`、`{kind:"release"|"browser",conversationId,id}`。仅可信主窗口可调用；Main 按对话的项目或临时工作区解析根目录，Renderer 不传根目录。创建返回 `{id,title,url,source}`；释放及打开侧边浏览器返回 null。HTML 限 1 MB，文件后缀须为 html/htm；路径经 realpath 校验，拒绝越界、隐藏路径和符号链接逃逸。

每份预览监听独立的 127.0.0.1 随机端口及随机路径，仅允许 GET/HEAD，返回 no-store、nosniff 和 `sandbox allow-scripts` CSP。只提供入口快照和工作区内允许的静态资源（单个资源最多 10 MB），无目录列表或任意文件读取；代码预览不读取工作区。iframe 不授予 allow-same-origin；侧边浏览器使用临时独立 partition 且无密码 Preload。浏览器打开前保留预览引用，失败或关闭时释放；卡片刷新、卸载及创建请求晚到均释放原引用，应用退出关闭所有监听。预览不进入数据库、不改变消息源文。浏览器 Mock 明确提示本地预览需桌面应用。

推理目录匹配补充（2026-10-15）：供应商可选 sourceUrl 为 HTTP/HTTPS 文档地址；模型规则可选 matchMode 为 exact/glob/regex，旧值缺失时保留 glob。默认目录按具体 API 型号预填；regex 使用固定版本 re2js，在 Schema 校验表达式并在解析时用同一无回溯语义执行。匹配模式在同模型各协议间共用，参数选项仍独立；未知模型不套通用档位。

推理程度目录（2026-10-15）：`model.get_catalog() -> ModelCatalog` 与 `model.save_catalog(ModelCatalog) -> ModelCatalog` 通过受信主窗口、严格 Schema 与现有错误信封读写 `settings.jsonc/modelCatalog`。可选 `reasoningProviders` 保存供应商 id、name、内置 icon、可选 PNG/JPEG/WebP data URL（上传上限 256 KB）与 apiFormats；`reasoningRules` 通过 providerId/modelKey 关联能力分组，可用通配符匹配多个同档位型号，每组在每个 apiFormat 下最多一条规则，分别保存参数选项。视图按版本排序，保存顺序与后匹配优先级不变。完整旧精确默认目录在读取／保存时原子合并为通配分组，编辑过的精确覆盖和自定义后缀保留，删除／重排／修改匹配条件的目录不自动合并；重复读取不重复写入。供应商取消勾选的协议保留规则但不参与目录选项解析；重新勾选恢复。旧版平面规则可读取，在设置页保存时补分组。缺少 reasoningRules 时使用内置规则，显式空数组/空选项不回退通用档位。已有连接供应商模型的显式选项与 Run 快照保留，恢复默认时采用最新目录。目录供应商用于能力分组，不是含密钥的连接供应商。协议校验负责可传输参数类型，具体型号能力由目录维护。详见第 26 篇。
后台浏览器补充（2026-10-15）：模型工具 `browser_control action=open` 接受可选 `background`、`width`、`height`，属于 Main 内部工具合同，不新增 Renderer IPC 或持久配置。后台 open/list 的结果包含 `background=true`，截图沿用内部模型附件通道，并保存受工具记录拥有的图片引用，展开工具详情可查看。后台会话发布带 `background=true` 的标签请求，但不等待 Renderer 确认，也不自动选择标签或展开侧栏；用户打开标签时将同一个 WebContents 挂入侧栏，保留页面状态。仍按 conversationId 与工作区校验归属，Run finally 清理本对话的后台会话并移除标签。`managedBrowserOpen` 可传 conversationId 使手动标签归属当前对话；`list` 包含这些标签，`show` 显示指定标签，`close_tabs` 支持选定、全部及保留指定标签后关闭其余。

本机控制补充（2026-10-14）：`conversations.open` 发布包含已保存摘要的 `conversation.open_requested`，Renderer 切回对话页并选中该项目与对话；事件不写入聊天历史。`control verify --open` 在发送前调用此入口。`models.configure` 沿用 SaveModelConfigurationInput / ModelRuntimeStatus，响应不含密钥；创建可用 `modelSelection` 选择已配置模型，校验失败时不创建对话。详见文档 25。

## 会话提问与后台程序（2026-10-14）

本机 HTTP 同步开放 `user_questions.list/answer`、`approvals.resolve`、`background_commands.list/stop`，复用既有输入及输出 Schema；回答/审批/停止均调用同一个 AgentRuntime，不能直接改写问题状态或绕过审批。`models.status` 返回安全 ModelRuntimeStatus；`conversations.set_permission/rename/archive` 复用已有生命周期用例，保存后广播 conversation.updated。`conversations.set_permission` 同时透传可选的 `coordinationMode`，与普通对话共用快速协作设置及 JSONL 持久化；省略时沿用既有模式。详见文档 25。

- `user_question.list({conversationId}) -> UserQuestion[]`：返回本对话发起的问题及其后代在本主对话展示的问题。
- `user_question.answer({questionId,answers,attachmentIds?}) -> UserQuestion`：必须回答该组全部问题，可附最多 10 个不重复的附件 ID，Main 校验它们属于问题 owner 的未发送草稿。同一份文字和附件可幂等重试，不允许修改已提交的回答；重试省略附件字段时沿用已保存的附件。`deliveryComplete=false` 表示回答已保存但未全部送达，界面提供重试。Question 的可选 `answerAttachmentIds` 保存原附件顺序，旧记录可缺省；owner 输入绑定附件，root 收到文字回答记录。
- 问题选项可含 `recommended?: boolean`，最多一个选项为 true；工具说明要求有建议选项时选一个推荐项，每项 label 用一句简短、完整的话直接表达选择，并省略 description。历史选项的可选 description 仍可读取和显示，旧问题未含推荐字段仍可读取。
- `user_question.mark_viewed({questionId}) -> UserQuestion`：只改变阅读状态，不提交答案。Question 含 owner/display Conversation、Run/ToolCall 来源、1–3 个问题、选项、答案、pending/answered/cancelled 状态及时间戳。
- `background_command.list({conversationId}) -> BackgroundCommand[]`：当前应用运行期间该对话及其后代的最近 50 个命令，运行中优先；返回命令、名称、工作目录、运行时间、状态和退出码，不含输出全文。历史输出保留在原工具记录。
- `background_command.read({conversationId,commandId,maxChars?}) -> BackgroundCommandOutput`：读取相同对话树拥有的命令，包含 command 摘要、stdout/stderr、error、timedOut、truncated。每条流默认取最近 24,000 字符，maxChars 范围 1–64,000；输出先解码、脱敏并去除终端控制符，再截取尾部。只读，不启动或停止命令。Main/Preload 与本机 HTTP 的 `background_commands.read` 共用合同。
- `background_command.stop({conversationId,commandId}) -> BackgroundCommand`：只允许停止该对话树拥有的命令，复用进程树终止并等待退出；侧边 PTY 不属于此列表。
- `user_question.updated` 事件含 Question 与 created/answered/viewed/cancelled 原因；`notification.activated` 含目标 Conversation ID，Renderer 负责导航。

Main/Preload 复用现有受信 sender、Zod DTO 和错误信封。Question 变更写入主对话 ThreadLog；回答通过 `run_queued` 或 `pending_messages_updated` 的 `questionAnswerId` 原子记录送达，检查点保留问题和送达回执，SQLite/内存只是可重建投影。

`stop_command` 成功结果为 `{ok:true,value:{command:{commandId,status,completedAt,exitCode,error}}}`，不含日志、命令正文或终端快照；`completedAt=null` 仅代表停止请求已发出，日志读取与停止分离。

## 1. 目的

本文档定义 `apps/web`、Electron Preload、Agent Runtime、本地工具和存储之间的最小合同。目标是让同一套 React UI 可以运行在浏览器和 Electron 中，同时确保 Renderer 不能绕过权限边界直接访问 Node 能力。

本文档定义的是边界和语义，不要求首个提交一次性实现全部接口。

## 2. 边界原则

设置目录删除（2026-10-14）：`model.delete_provider` 接受 `{providerId}`，返回更新后的 `ModelRuntimeStatus`；删除默认供应商后选择剩余供应商的首个模型，删除最后一个后持久化空 providers 与 null 默认/最近选择，启动不从环境变量复活。`skill.delete_document` 接受已登记的 `{entryPath}`，删除完整 Skill 目录及资源后移除登记，返回 void；仅可信主窗口可调用。Main 拒绝未登记入口、内置 Skill、扫描根目录和入口/根目录符号链接。Skill 文件删除由 UI 显示完整目录并确认后调用；失败保留错误及可重试的登记。

Agent/团队目录删除复用 `saveApplicationSettings`：删除非默认 Agent 时清理所有团队成员引用和成员配置，移除负责人后使用剩余成员或默认 Agent 补足合法负责人；默认 Agent 保留。目录删除不删除已建立的对话或团队实例。

浏览器配置（2026-10-13）：`downloadDirectory` 默认空字符串，表示系统下载目录；自定义目录经 Main 校验绝对路径、目录类型并 canonicalize。`savePasswords` 默认 true，旧配置补默认值，复用原配置保存 IPC。新增无参数 `browser.choose_download_directory`，仅可信主窗口可调用，返回选中的目录或 null，取消不改变配置。改动即时应用到已开标签。

密码捕获与自动填充由浏览器隔离 Preload 和所属 WebContents 交换。Main 校验顶层 frame 身份、参数 Schema 和 HTTPS origin；确认保存后用系统 `safeStorage` 加密整个凭据数组，原子存入 AgentHome 的 `browser-passwords.json`。每个精确 origin 保存最近确认的一组凭据；系统加密不可用（含 Linux basic_text）时不保存。关闭开关停止捕获和填充；清除浏览数据删除凭据文件并清空打开页面的填充缓存。

浏览器设置查看（2026-10-13）：`browser.get_default_download_directory` 无参数，返回 Electron 解析的实际系统下载目录；Renderer 用自定义目录或这个默认值显示当前路径，不将默认路径写死到持久配置。`browser.get_saved_passwords` 无参数，仅返回 `{origin,username}[]`，响应 Schema 禁止携带密码。`browser.reveal_password` 接受 `{origin}`，返回该来源密码或 null；这两项仅可信主窗口顶层 frame 可调用。界面默认遮蔽密码，点击查看后才读取，一次显示一条，隐藏、刷新、清除数据或退出设置页时清掉显示缓存；迟到响应不能恢复已清除的密码。明文不进入日志或 Renderer 持久状态。

外观字号（2026-10-13）：`appearance.uiFontSize` 范围 12–18、默认 13；`chatFontSize` 范围 12–24、默认 13；`codeFontSize` 范围 10–24、默认 11，均为整数 px。旧配置缺字段时补默认值，经现有应用设置保存与变更事件持久化。界面、对话正文和代码编辑器分别即时应用，终端仍使用独立终端配置。恢复默认字号只修改这三个字段。

应用外观配置（2026-10-13）：`ApplicationSettings.appearance.settingsNavigationWidth` 是独立设置菜单宽度，整数范围 200–360，默认 240。旧 JSON／JSONC 配置缺少该字段时，Schema 补默认值并保留其他外观配置。Renderer 经现有 `getApplicationSettings`／`saveApplicationSettings`、变更事件与原子设置存储恢复和保存该值，不新增 IPC，也不借用项目栏宽度。窄容器只限制显示宽度，不回写覆盖保存值；拖动和键盘调整仍受 Schema 范围限制。

主窗口左侧对话删除使用 `conversation.delete_undoable`，参数仍为 `{conversationId}`，返回 void。Main 保存既有删除任务并标记隐藏，但当前进程暂缓清理；`conversation.restore_deleted` 仅允许撤销当前进程持有且未开始清理的任务，原子取消删除标记和任务。重启后不恢复撤销权限，沿用启动清理流程。原 `conversation.delete` 保留即时删除语义，侧边临时聊天生命周期不变。

首字计量：模型 Adapter 从实际 HTTP dispatch 到首个非空正文、推理或工具调用输出块记录 `firstTokenLatencyMs`（非负整数毫秒），不把空事件/usage 当输出。通过 `model.first_token_received` 实时通知并在 `ModelProviderState` 独立持久化；`providerCache.firstTokenLatencyMs` 在新请求开始清空，旧记录/未收到输出为 null，不依赖 Provider 是否上报用量。该值包含网络及服务端排队，不包含本地审批和消息排队；自动重试按实际响应的请求计时，不代表整轮耗时。

缓存显示语义更新（2026-09-09）：底栏仍用“本次命中率／平均命中率”。当前 Runtime 在每次模型请求开始时清空本次用量，未返回用量或被取消时 `providerCache.latest=null`；已返回用量则保留真实值，包括零命中。底栏不以 `lastReportedHitRate` 替代本次值，该字段仅供明细参考；平均值仍按已上报缓存明细的输入 Token 加权，真实零命中照常计入，未知不补零。

底栏实际计量（2026-10-18）：底栏只展示 Provider 实际计量及同一请求的首字／输出耗时，不消费 model.request_started 的 estimatedInputTokens 或根据文字计算 Token。新请求、工具执行和取消不清空最近完整快照；下一次实际用量整体替换。移除估算定时器和 ≈；Token 使用完整整数；命中率最多一位小数，非零且低于 0.1% 显示 <0.1%。没有缓存字段显示“未上报”，真零仍为 0%，不借上次命中率冒充本次。原首字及请求事件继续供其他工作状态使用，无新增 IPC 轮询。

`conversation.get_pending_queue_paused` / `conversation.set_pending_queue_paused` 按对话读取、设置布尔暂停状态；设置参数为 `{conversationId, paused}`，经 Schema 校验。`pending_messages.updated.queuePaused` 同步队列暂停状态；继续仅解除自动消费门禁，不立即启动消息。暂停独立于停止当前 Run。

- `apps/web` 只依赖 `packages/protocol`，不导入 Node、Electron、SQLite、文件系统或 PTY 模块。
- Electron Preload 实现 Desktop Transport，Web 开发模式实现 Mock Transport。
- UI 只调用 `AgentClient`，不判断 `window.__TAURI__`、`window.electron` 或运行平台后直接调用系统 API。
- 命令使用请求/响应语义；长任务、流式消息和工具过程使用事件流。
- 所有跨边界数据都可序列化，并通过 Zod Schema 校验。
- Schema 以 `packages/protocol` 为唯一来源，Renderer 和 Main 不各写一套类型。
- 纯 Renderer、可安全回退且不参与业务事实的界面偏好可以使用 `localStorage`，无需新增 IPC 或 SQLite 字段。左侧对话树以版本化键保存项目、团队、置顶、临时分组，以及项目和团队节点的展开状态；无记录或记录损坏时回退默认值，其中“临时”默认收起。临时 Subagent 不再作为左侧树节点，其查看入口位于父对话标题栏。该状态只影响可见性，不改变当前对话、项目选择、归档或团队业务事实。

## 3. AgentClient

`project.open_directory` 复用 `ProjectReferenceInput`（仅项目 ID）和空响应；Main 校验可信窗口与参数，从 ProjectRegistry 获取目录并确认其真实路径为目录，再调用系统打开目录能力。Renderer 不能提交任意路径或终端命令；Mock 返回桌面应用限制提示。

`pending_messages.updated` 在 Steer 被安全消费时携带 `consumedMessages`，内容是已写入 JSONL 的用户消息。UI 同步插入消息边界并移除待消费显示，不能等历史分页重载后才插入，否则后续工具事件会越过用户消息。消费前使用持久 Pending 记录显示已发送气泡，不参与模型上下文或新段计时；消费时沿用 Pending ID，仅此时开启新段计时。

快速协作显式领取的 Queue 复用同一消费事件和来源 ID，普通对话 Queue/Steer 行为保持不变。`ConversationAgentMessageItem.deliveryMode?: "queue" | "steer"` 是自有子代理独立任务的可选投递标记；旧消息缺少该字段时保持原即时行为。Queue 消息的 JSONL `agent_messages_consumed` 可携带 `queuedMessages: {messageId,modelContent}[]`，只有消费时才进入模型上下文，仍使用现有 Agent 消息、Run、回执和暂停协议，不新增 IPC 或持久 SQLite 队列。

`conversationMarkResultViewed` 经生命周期服务先追加 `conversation_result_viewed`（`payload: {}`），再清除临时投影的 `hasUnreadResult`。事件顺序表示确认之前的结果；之后的新终态仍产生未读。主/侧边对话共用此入口；成功提交后通过现有 `conversation.updated` 广播最新摘要，使侧边栏与对话动态同步已读状态；写入失败返回错误，不提前清除标记或广播。仅确认当前可见对话的入口必须透传 `onlySelected`，不能同时确认尚未查看的关联对话。

### 3.1 模型供应商品牌标识

### 4.1 开发工具工作区合同

- Git 分支字段 `isWorktreeOccupied` 表示被其他 worktree 签出（旧响应缺省表示未知）。Main 从 Git 分支元数据读取，不向界面传递工作区绝对路径；切换前再次校验占用状态，不强制解除占用。

- `git_review.get_snapshot` 接收 `projectId`，先解析包含该项目目录的 Git 仓库根目录，再返回当前分支、本地分支列表、上游、ahead/behind、文件状态、暂存状态和逐文件增删行统计；所有文件路径均相对仓库根目录。`git_review.get_file_diff` 默认只读取用户展开文件的 3 行上下文并返回最多 2 MB 的文本 Diff；IPC 对 `contextLines` 的安全上限仍为 10,000，当前 Renderer 在“已省略未修改内容”处单次最多请求 120 行，其余超长区段继续折叠，项目即使登记在仓库子目录也不能重复拼接路径。Renderer 在当前应用生命周期内按项目共享 Git 快照、同一上下文等级的逐文件 Diff 和在途请求；项目激活时即低优先级加载快照，并按最多 2 个并发预取前 20 个文本 Diff，用户展开同一路径时复用缓存或在途请求，二进制文件不预取。缓存最多保留 4 个最近项目、30 分钟未访问项目和约 32 MB Diff 文本，超限后按 LRU 回收并优先保留当前项目；快照超过 30 秒后在项目重新激活或窗口回焦时后台复核。AI 文件工具完成时，Renderer 只失效事件指定的项目和路径，250 ms 内合并快照刷新并优先重新预取这些路径；显式刷新和成功 Git 操作仍使该项目全部 Diff 失效。Git 审阅栏宽度达到 760px 时树与选中文件 Diff 双栏展示，较窄时仍在文件行下方展示；两种布局都以 hunk 间的省略带表达远处未修改内容。短时间切换标签、对话或页面不得重复请求；应用重启、缓存回收或失效后重新读取。
- `git_review.run_operation` 使用判别联合限制为逐文件/全部暂存与取消暂存、按已选路径批量暂存、按已选路径取消跟踪、创建并切换本地分支、切换已有本地分支、按已选路径提交、`pull --ff-only` 和普通推送。Renderer 的复选框只保存待操作选择，不直接写入 Git；未跟踪文件组的加号会跟踪并暂存已选路径，已跟踪更改组的减号会只从 Git 索引移除已选路径、保留其本地文件；提交会先暂存并仅提交这些唯一的相对路径，保留其他已暂存但未选的文件。创建分支可选传入一个已经由 Main 校验存在的本地分支作为 `startPoint`；未传时仍从当前 HEAD 创建。Renderer 不能传入任意 Git 参数；首次推送只允许为当前分支设置 `origin` 上游。该工作区不提供丢弃修改、删除分支、硬重置或强制推送。
- `terminal.get_configuration/save_configuration` 持久化侧边终端的默认 Shell、每种 Shell 可选的可执行文件绝对路径、字体、字号和行高，以及一次性命令结果的输出解码字符集。默认字体栈优先使用支持 Nerd 图标的等宽字体并回退至 `Segoe UI Emoji`。侧边终端的 Shell、路径和字体设置不改变模型 `run_command` 使用的受控非交互 Shell；只有输出字符集继续用于一次性命令 stdout/stderr 解码。`terminal.session_open/write/resize/close` 管理以项目根目录为工作目录的 PTY。新终端按保存的默认 Shell 启动，优先使用该 Shell 配置的路径；未配置 PWSH 路径时 Main 尝试常见 Windows 安装目录，再回退到 `pwsh.exe`。交互 PTY 必须覆盖继承的 `TERM` 为 `xterm-256color`、提供 `COLORTERM=truecolor`，并清除继承的 `NO_COLOR`，不能把桌面开发进程的 `TERM=dumb` 或禁色设置传给用户 Shell。已经打开的会话不因设置变化而重启；Main 持有进程对象，Renderer 只接收 `terminal.session_event` 的有界输出或退出事件。关闭终端标签必须结束对应 PTY，应用退出和主窗口关闭会统一释放遗留会话。
- `workspace_terminal.open_requested` 是 Main 到 Renderer 的一次性终端标签请求，携带 `requestId`、当前 `conversationId`、已解析的 `projectId`、可空 `requestedName` 和已经由 Main 创建的 PTY 会话。Renderer 只在对应的当前项目会话中挂载这个同一会话，并依据所有已打开的文件、聊天和工具标签计算唯一名称。随后 Renderer 调用 `workspace_terminal.opened`，只回传同一 `requestId` 和严格受限的 `resolvedName`。Main 在收到确认前不完成模型 `terminal_control action=create`，因此结果会同时得到可持续读写的 `terminalId`、原请求名、实际标签名和是否调整；`action=list` 返回当前对话仍存活的模型终端及其 `terminalContext`，`action=write` 写入一条命令，`action=read` 用输出游标读取有界增量。PTY 存活只说明外层本地 Shell 存活，不等于其中的 SSH 子会话仍连接；工具根据增量终端输出跟踪 `local/ssh_connecting/ssh_connected/ssh_disconnected`，远程命令必须声明 `expectedContext=ssh`。检测到连接重置、关闭、拒绝、超时、解析失败、Host Key 失败或认证失败时，工具返回 `TERMINAL_CONTEXT_MISMATCH`，不得把原本发往服务器的命令落到本地 Shell。`action=create/write/close` 先生成无副作用的待批准动作，复用 `command-run` 应用策略、Agent/会话允许规则和 LangGraph interrupt 审批；批准前不得创建 PTY、创建标签、写入命令或关闭会话。批准后的创建/写入进入项目命令操作协调边界；命令发送及即时输出采样结束后释放协调记录，后台长驻 PTY 不长期占用项目写锁。关闭完成后 Main 通过 `workspace_terminal.close_requested` 通知 Renderer 移除对应标签。会话只归属创建它的项目对话；窗口不可用、会话已切换或十秒内未确认时创建失败并关闭已创建 PTY。
- `workspace_browser.open_requested/opened/close_requested` 将模型创建的隔离浏览器会话与 Renderer 侧边标签绑定：Main 先创建受管浏览器，再等待 Renderer 返回去重后的标签名；模型关闭浏览器时 Main 通知 Renderer 同步移除该标签。首方 `agent.browser` 只向新模型请求暴露统一 `browser_control` 工具，具体操作流程由按需加载的 `browser-use` Skill 提供；旧 `browser_*` 名称只保留执行兼容，不再加入新 Run 的工具清单。该工具只允许项目对话操作自己创建的会话，采用“语义元素优先、视觉坐标兜底”的合同：`observe` 返回有界页面文本、视口、元素引用及边界；`screenshot` 将当前可视区作为一次模型图片输入，截图像素与后续指针坐标使用同一 CSS 像素空间；旧截图在出现新截图后只保留文字占位，不重复携带图片字节。点击、移动、按下/释放、拖拽和滚轮通过 Chromium 输入事件执行，不接受任意 JavaScript。浏览器会话仍沿用隔离 Session、无凭据 URL并拒绝权限申请。打开、导航/历史操作、指针、填写、选择、按键、滚动和关闭使用独立 `browser-control` 应用策略，默认 `ask`，并在批准前只解析参数和校验会话归属；观察、截图和等待只返回有界只读状态，不产生审批。浏览器工具不提供读取本地下载文件内容的接口。
- `browser.get_configuration/save_configuration/clear_data` 持久化默认搜索引擎、新浏览器标签的默认缩放比例和下载前询问设置，并清除隔离浏览数据；`managed_browser.open/navigate/command/capture/set_bounds/close` 管理 Electron `WebContentsView`。Renderer 提交地址栏文本、受限浏览器命令、菜单锚点、应用当前深浅色和视图边界；`set_bounds` 使用经具名 Preload 入口发送的单向 IPC。普通窗口变化按动画帧合并最新边界；面板拖动期间按画面帧合并最新鼠标位置，用临时 CSS 宽度更新侧栏，再读取并裁剪布局后的实际网页矩形，同步真实 Chromium 页面；松手时才保存最终宽度并校准边界，避免高频偏好序列化与界面重渲染。Main 将域名、IP、`localhost` 和显式 HTTP/HTTPS 输入解析为导航地址，将其他文本交给用户选择的搜索引擎，并通过 `managed_browser.event` 回传标题、URL、加载、历史与当前缩放状态。新标签默认显示应用自有空白起始页。Main 在页面加载前向 Chromium 设置对应的首选颜色和自动深色策略；HTML 交付经 htmlPreview(browser) 打开的隔离会话只同步首选颜色，显式禁用强制自动深色，未设背景色时使用与 iframe 一致的白底，保留与对话 iframe 相同的网页原色及自带主题 CSS；该规则同样用于后续导航和 DevTools 关闭后的主题恢复，不增加 IPC 参数；应用主题变化时同步浏览器背景、网页渲染和已打开覆盖菜单，已有 HTTP/HTTPS 页面重新加载一次以应用 Chromium 的按页配色。`capture` 只按需返回当前视口的有界 JPEG 快照，不改变原生 View 的可见性；浏览器工具截图另由 Runtime 保存到对话附件目录，工具结果只含引用与尺寸，图片字节不写入 JSONL。缩放、打印、截图、开发者工具、下载记录和清除隔离浏览数据由 Main 执行；`Ctrl + 鼠标滚轮` 的缩放请求同样由原生 `WebContents` 处理并回传状态。浏览器使用隔离 Session，禁用 Node、权限申请和携带 URL 凭据的导航；下载默认进入系统下载目录，也可按设置逐次询问保存位置；关闭标签必须销毁对应 View。
- `conversation.search` 接收 1 到 500 个字符的查询和最多 100 条结果上限，按 JSONL 文件位置直接读取未归档对话的用户、Assistant 与 Agent 消息，不查询 SQLite 消息表或 FTS。检索分批让出事件循环；响应只返回有界命中片段、Conversation/Timeline ID、来源角色、时间和定位所需的归属字段。Renderer 使用 Timeline ID 打开并定位原消息；该接口不能搜索项目文件，也不能绕过归档和删除状态。
- 浏览器页内查找由 Chromium `findInPage` 执行。`managed_browser.command(showFind)` 打开覆盖查找条，后续查询、上一个/下一个与清除选择都留在 Main；原生网页获得焦点时由 `before-input-event` 捕获 `Ctrl+F`，`Ctrl+Shift+F` 则通过 `managed_browser.event(openGlobalSearch)` 通知 Renderer 打开全局对话搜索。覆盖条只保存当前查询和匹配计数，关闭、按 `Esc` 或销毁浏览器标签时必须调用 `stopFindInPage`。
- Windows/Linux 的共享 React 浮层使用同源 native-overlay.html 和固定窗口名建立透明子窗，Main 只允许精确内部 URL，并使用专用沙箱 Preload；该子窗不暴露应用 Bridge。native_overlay.set_regions 仅接受当前子窗主 frame 的严格区域 Schema，按父窗口缩放和内容边界裁剪原生 shape；无区域时隐藏子窗，网页保持可见。私有 resize_pointer 事件把父窗口及原生网页中的鼠标移动、释放位置转换到 Renderer 坐标，前端每帧只处理最新位置；停止拖动、主 Renderer 导航、子窗关闭/崩溃和应用退出时解除监听。blur 通知仅用于点击应用内原生网页后的浮层关闭；页面权限、导航和额外窗口继续受限。`set_regions` 新增可选布尔 `tooltipOnly`，仅提示浮层开启有界光标跟踪；Main 的 `tooltip_pointer` 单向通知使用有限数值 `{x,y}`，允许窗口外负坐标，专用 Preload 严格验证并对称注销。区域外直接释放原生鼠标拦截，选字焦点回到父窗，不等待 DOM 事件或空白点击；普通菜单和弹框沿用原输入语义。macOS 未启用该原生浮层路径。
- 当前活动的对话或工具页不回收；顶部标题栏中仍打开的主对话标签也是明确的缓存保护项，不受普通页面的数量和时限淘汰。关闭主对话标签只解除该页面的缓存保护，不删除 Conversation；关闭当前标签后 Renderer 激活相邻标签，关闭最后一个标签后清空当前主对话选择。除这些保护项外，普通非活动页缓存最多保留 8 个、最长 1 小时。短时间切换时，终端 PTY、浏览器 `WebContentsView`、Git 快照和 Diff 都必须保留；超过数量或时限后，Renderer 卸载非活动页面，主动关闭对应 PTY 或浏览器 View，并在用户再次打开时重新请求 Git、重新启动终端、或从上次 URL 重新加载浏览器。浏览器三点菜单和下载面板由 Main 创建独立、透明、跟随应用主题的覆盖 `WebContentsView` 显示在实时网页上方；打开和关闭覆盖层不得隐藏、截图替换、重载或重建网页 View。

## 5. 命令与事件

侧边 PTY 会话返回 `initialSize`（启动行列数）和 Windows 下的 `windowsPty`（ConPTY / 系统构建号）；实时 `data` 事件携带与转录读取相同的 `nextCursor` 字符游标。Renderer 先按启动尺寸分页回放，再按游标衔接实时输出，最后适配容器；连续布局变化合并后同步 PTY 尺寸，不将控制序列当成普通文本或重复追加历史。

### 5.1 命令

本机控制（2026-10-14）：显式设置 `ASTER_CONTROL_ENABLED=1` 后提供随机端口、Bearer 认证的 `127.0.0.1` HTTP 命令和 SSE 订阅。`LocalControlCommand` 严格限定项目/对话列表、对话创建、Timeline 分页、文本发送和对话停止；不接受工作区、模型或权限覆盖。创建沿用配置 Agent 与新对话设置，发送沿用保存的模型/权限及 Queue/Steer，团队执行树经已有团队指导入口。IPC 与后台调用经组合根发布相同 `ConversationRunEvent`；创建持久化后广播摘要，页面无须重新聚焦即可感知。连接/重连要求快照恢复，当前 SSE 不重放。终端命令、认证、生命周期及远程能力边界见[第 25 篇](./25-本机控制接口与终端调用.md)。

后台验收（2026-10-14）：`control verify` 组合已有 HTTP 命令与 SSE，不增加产品端点。客户端先订阅并验证创建广播，串行等待两轮 Run 的完成与正文增量，最后核对保存的 Timeline；失败、取消、缺失事件/历史或超时均以非零退出码结束。桌面继续订阅同一事件更新列表和已打开的对话，后台命令不强制替用户选中页面或改变既有模型/权限配置。

电脑控制后台验收（2026-10-19）：`computer_control.status/start/stop` 接受严格空输入并复用设置页的同一控制器，返回 `ComputerUseStatus`。入口仅在已显式启用的本机认证接口中开放，不接受权限覆盖或操作参数，不注册为模型工具。启动沿用用户保存的授权与管理员配置、真实 UAC 和握手，失败不自动重试；不会因模型发出首个操作而自动启动。

桌面端同时提供受单实例锁保护的本机命令行触发入口：启动参数
`--aster-send=<JSON>` 接收严格的 `{ conversationId, content, modelId?, providerId? }`，只复用
`AgentRuntime.sendMessage` 的既有权限、队列和事件链路，不接受权限或工作区覆盖字段。该旧入口仅用于本机单向触发，不返回结构化创建/查询结果；完整本机自动化使用第 25 篇接口。远程访问必须另行增加认证和事件补偿协议，不能直接暴露 Electron IPC。

`cancelRun` 接收 `{ conversationId }` 或 `{ runId }`（二选一）。对话级停止覆盖所属嵌套 Subagent、等待、审批和待执行唤醒；主 Run 已结束但子代理仍工作时，输入框仍提供停止入口。停止不会删除历史或影响仅通信过的独立对话。

命令由 UI 发起并等待一次响应，例如创建会话、开始 Run、取消和审批。每个跨进程命令包含：

```ts
type CommandEnvelope<T> = {
  schemaVersion: 1;
  requestId: string;
  command: string;
  payload: T;
};
```

- `requestId` 用于关联响应和避免重复提交。
- 有副作用命令不得因 IPC 重连自动重试。
- Runtime 在执行前再次校验 Schema 和权限，不能只相信 Renderer 已校验。

### 5.2 事件

Agent Runtime 向 UI 推送统一事件：

```ts
type EventEnvelope<TType extends string, TPayload> = {
  schemaVersion: 1;
  eventId: string;
  sessionId: string;
  runId?: string;
  sequence: number;
  timestamp: string;
  type: TType;
  payload: TPayload;
};
```

- `sequence` 在单个 Session 内严格递增，用于恢复后补齐事件。
- UI 按 `eventId` 去重，按 `sequence` 排序。
- 实时事件先推送 UI，持久事件成功写入后才能成为恢复事实。
- UI 重新订阅时携带最后确认的 `sequence`，Runtime 返回缺失事件。
- `conversation.updated` 的 `ConversationSummary.activeRunId` 仅表示当前可取消的模型 Run；`activeSubagentCount` 同时聚合该父对话直属的初始 `queued`/`running` 任务和已完成 Subagent 上新建的活动 Run。UI 在任一字段表示活动时显示“运行中”，但停止按钮只能取消 `activeRunId` 指向的 Run。
- `ConversationSummary.avatarIcon` 是可选的受控 Agent 图标 ID。Subagent 只在创建请求显式提供合法枚举值时写入 `conversations.avatar_icon`；绑定的 Agent Profile 继续提供名称、角色、指令和模型能力，但其普通头像不覆盖 Subagent 的独立视觉身份。非法的可选 `icon` 按未提供处理，不能阻断 Subagent 创建。字段为 `null` 时，Renderer 根据子 Conversation ID 即时生成稳定的 5×5 对称 Identicon，不写图片或新增持久字段。同一 ID 的图案和色调保持一致；Renderer 仍不能执行模型提供的 SVG、URL 或组件名。
- `agent_message.received` 只在可见的跨 Conversation Agent 消息成功持久化后发出，携带完整 `ConversationAgentMessageItem`。已经挂载目标 Conversation 的 Renderer 按 Timeline ID 幂等插入该消息，再接续消费同一 Conversation 的 `run.started`、模型与工具事件；因此父 Agent 的后续消息和接收方处理过程无需关闭、重开侧边标签即可实时显示。仅供 Runtime 回传的私有 `task_result` 不发出该事件，也不能投影为用户可见消息。
- 同一用户请求的自动续跑回答合为一个展示区域，只在最后提供复制/分支操作。各段保留原消息定位 ID，复制包含续跑前后的输出；新用户输入、可见 Agent 消息或失败状态隔开回答。此合并不改写 JSONL、Run 或模型上下文。
- `model.retry_updated` 携带完整 `model_retry` Timeline 项，表示一次语义模型请求正在退避重试、已经恢复或最终失败。同一请求的多次更新复用相同 Timeline ID；一旦产生可见文本或工具调用，不再重放模型请求。

### 5.4 右侧栏项目文件编辑 IPC

右侧栏用户编辑使用与项目工具相同的项目操作锁，但不经过 Agent 权限审批。Preload/Renderer 暴露两个窄接口：

```ts
writeProjectFile({
  projectId: string,
  path: string,                 // 项目根相对 POSIX 路径
  content: string,
  expectedContent: string | null,
}): Promise<ProjectFile>;

readProjectPreviewImage({
  projectId: string,
  sourcePath: string,            // Markdown 文件路径
  path: string,                  // 正文中的原始图片引用
}): Promise<{ mimeType: string; data: string }>;
```

- `writeProjectFile` 在 `ProjectToolRegistry` 内执行，参与文件/命令统一锁；命令或其他项目变更占用时返回 `CONFLICT`（底层 `PROJECT_OPERATION_CONFLICT`）。
- 写入前必须将磁盘当前文本与 `expectedContent` 比较；不一致返回 `FILE_CHANGED`，不得覆盖。成功后返回新的 `ProjectFile`，Renderer 更新下一次保存的预期内容。
- `readProjectPreviewImage` 以 `sourcePath` 所在目录解析相对引用，再执行真实路径边界、符号链接、扩展名和体积校验；远程/data/blob 引用不经此通道，图片以 Base64 data URL 返回。右侧文件工作区直接预览图片时复用该通道，支持 PNG/APNG、JPEG/JFIF、GIF、WebP、BMP、SVG、ICO 和 AVIF，保持 8 MB 上限且只读。
- `ProjectFile.truncated === true` 表示仅返回前 2 MB，UI 必须保持只读，禁止把截断内容写回原文件。
- `fileChange` 事件刷新无脏草稿标签；有脏草稿时只标记外部变更，交由下一次 `expectedContent` 校验处理。

### 5.5 定时任务

`scheduled_task.list/save/delete/run` 通过同一 AgentClient、Preload、Main IPC 边界访问；所有输入和响应使用 `scheduled-task.ts` 的严格 Zod Schema，Main 校验可信主窗口。配置最多 100 项，指令最多 30,000 字；计划为 `once {at}`、`daily {time, timezone}` 或 `weekly {time, timezone, weekdays}`，weekday 为 0（星期日）至 6。时间保存 ISO UTC，重复规则保存 IANA 时区与 HH:mm。

`<ASTER_HOME>/scheduled-tasks.json` 以 version 1 原子保存计划、nextRunAt 和最近 20 次执行。先持久化触发占用及下一次时间，再创建对话；beforeRunScheduled 在模型派发前持久化 Run ID。失败不得自动重发。运行中的计划不可删除；暂停不取消当前执行。重启跳过错过的时间，恢复中断记录并重新计算未来时间，不重放模型调用。完成事件先写状态再转发，周期检查也可从 Runtime 的持久 Run 事实补偿遗漏的完成事件。删除仅删除计划与关联记录，结果对话由既有对话生命周期独立管理。

## 6. Run 状态机

```text
queued
  -> running
      -> waiting_approval
          -> running
          -> blocked
      -> completed
      -> failed
      -> cancelled
      -> interrupted
```

约束：

- 一个 Session 第一阶段最多有一个活动 Run。
- `completed`、`failed`、`cancelled`、`blocked` 和 `interrupted` 是终态。
- 应用异常退出后，原 `running` 和 `waiting_approval` Run 在下次启动时转为 `interrupted`。
- `interrupted` Run 可以由用户发起新的继续请求，但不能从中间自动重放有副作用的工具。
- 状态转换通过存储事务提交，并生成对应事件。
- Run 开始时写入不可变 `modelSnapshot`；Agent 后续修改模型策略不反向改变历史 Run。
- 模型切换只影响下一次模型调用；需要立即切换时先取消当前 Run，再创建新 Run。

## 7. 消息模型

### 7.1 消息复制导出

复制最终 Assistant 回复时，Renderer 按该消息的 `runId` 从 Timeline 选出同一 Run 的 Assistant 回复和工具记录，并按 Timeline 顺序生成 Markdown。命令包含命令行、状态、退出码、stdout 和 stderr；文件工具包含 Diff；读取、搜索和其他工具输出为有界结构化文本。用户消息、隐藏 reasoning、内部工具 JSON、错误实例 ID 和受管绝对路径不进入导出。没有工具记录时仍复制原始 Assistant Markdown。代码块围栏会根据内容中的反引号动态加长，避免破坏 Markdown。

桌面端使用 `clipboard.write_text` IPC 调用 Electron Main 原生剪贴板。请求通过 `clipboardWriteTextIpcArgumentsSchema` 校验，文本上限为 2,000,000 个字符，成功返回 `void`；浏览器 Mock 使用浏览器 Clipboard API。

命令执行详情的命令块与输出区分别提供复制按钮，前者仅复制执行命令，后者复制当前保留的 stdout、stderr 及执行错误文本，均通过 `AgentClient.writeClipboardText` 使用上述宿主剪贴板入口。复制错误单独展示，不改变命令运行状态或输出刷新；对话内命令工具的复制入口沿用命令与输出的合并文本。

Mermaid 图片复制由 Renderer 使用 Clipboard API 写入 `image/png`。Main 仅为当前主窗口及其精确内部覆盖页子窗口的主 Frame 放行 `clipboard-sanitized-write`，请求 URL 必须与对应 WebContents 当前 URL 一致；子 Frame、其他 WebContents 和剪贴板读取权限继续拒绝。隔离浏览器页面沿用自己的权限拒绝策略。

```ts
type Message = {
  id: string;
  sessionId: string;
  runId?: string;
  role: "user" | "assistant" | "system";
  status: "streaming" | "completed" | "failed" | "cancelled";
  createdAt: string;
  completedAt?: string;
  durationMs?: number;
  blocks: ContentBlock[];
};

type ContentBlock =
  | { type: "text"; text: string }
  | { type: "tool_call"; toolCallId: string }
  | { type: "tool_result"; toolCallId: string }
  | { type: "approval"; approvalId: string }
  | { type: "artifact"; artifactId: string; label: string }
  | { type: "summary"; summaryId: string };
```

Reasoning 不按模型名称判断，而按 Adapter 事件语义分流。供应商明确返回的 `kind=content` 是可展示的完整思考内容，并以可选 `reasoningContent` 写入 `conversation_timeline`；Renderer 再按 `runId` 将同一 Run 的完整思考、Assistant 过程说明和工具记录依照 Timeline 顺序投影到一个“工作过程”折叠区。该投影只改变显示结构，不重排或删除持久记录，也不改变后续模型上下文；工具结果返回后产生的新思考继续进入同一过程区，最终 Assistant 回答仍独立显示在其下方。完整思考不拼入 Assistant 正文，也不进入复制结果或 `model_messages.content`。普通 `assistant.delta` 正文若以成对 `<think>` 或 `<thinking>` 标签开头，按兼容接口泄漏的摘要处理而不升级为完整 Reasoning：Renderer 在完成后的历史投影中移除整个标签段，只保留标签后的正常正文，并保持原始 Timeline 不变。`kind=summary` 只作为当前模型请求的实时思考摘要显示在外层“工作过程”折叠标题上；开始工具后标题改为最新工具状态，完整可见思考的内部折叠语义不变；`kind=progress` 表示模型主动给用户看的短进度更新，不等同于思维链。两者都在输出正文、开始工具或 Run 结束后清除，不要求写入 Timeline。未通过供应商接口返回的模型私有推理仍不采集、不展示。

Renderer 显示消息时间时按用户本地日历格式化：当天只显示时分，前一天显示“昨天 + 时分”，同一年较早日期显示“月日 + 时分”，跨年显示完整年月日和时分。Assistant 最终消息的 `completedAt` 与 `durationMs` 是 Timeline 查询根据所属终态 Run 的 `updated_at - created_at` 派生出的只读展示字段；不会重复写入消息正文、模型上下文或 ThreadLog。

模型可见正文与 Reasoning 流必须分开：OpenAI Responses、Anthropic Thinking 和 Gemini Thought Summary 作为 `summary` 事件；OpenAI Chat 兼容端点中明确返回的 `reasoning_content` 默认作为 `content` 事件，但 GPT 数字版本系列（含供应商前缀）通过该兼容端点返回的同名无类型字段按供应商摘要语义归为 `summary`，不得生成持久 `reasoningContent`。供应商明确标注为面向用户的短进度时使用 `progress`。`assistant.reasoning_delta` 携带所属 `messageId`、`modelId`、`kind` 和 `reset`，Renderer 只把 `content` 合并到对应 Assistant Timeline 消息，`summary/progress` 只更新当前请求的临时状态；Renderer 同时过滤历史版本误存的 GPT 摘要。三类事件均不能重复拼入 Assistant 正文。不可读的推理签名、加密内容和工具调用签名只保存在 Provider State 中，不生成可见 Reasoning 事件；Provider State 只在 `apiFormat + baseUrl + modelId` 与当前请求完全匹配时重放。新 LangChain 快照使用版本 2，迁移期继续只读兼容 AI SDK 版本 1 的 `assistantMessage/openAiChatReasoningContent`，新写入不再产生旧格式。

取消 Run 时，已收到的 Assistant 流式文本以 `status=cancelled` 的消息保留；没有收到文本则不创建空的 Assistant Timeline。该消息同时进入模型历史，便于用户继续对话时保留已经看到的内容。

### 7.2 编辑最后一条已发送用户消息

Renderer 通过 `conversation.replace_latest_message` 提交 `ReplaceLatestConversationMessageInput`。该命令只接受非空文本和当前对话最后一条已发送用户消息的 ID，返回新 Run 的 `RunAccepted`。

边界约束：

- Main 必须重新校验消息归属和“最后一条用户消息”条件，不能信任 Renderer 是否正确隐藏编辑按钮。
- 正在运行的原 Run 必须先取消并完成资源清理；替换事务不能与模型、命令或文件 I/O 混在同一个 SQLite 事务中。
- SQLite 事务复用原 Timeline 消息 ID 和附件绑定，更新消息正文、Run ID 与时间，删除旧 Run 在该消息之后的 Timeline/Model Message，并使覆盖该消息的旧 Context Checkpoint 失效。
- 新 Run 记录、用户 Timeline 和模型消息必须在同一事务内建立；事务失败时保留旧消息与旧回答。
- 旧 Run 记录不删除，外部工具副作用不回滚。替换成功后 Renderer 以返回的用户消息更新 Timeline，并通过正常 Run 事件继续接收流式回答。
- 用户未显式选择新 `@对话/@文件` 引用时保留原消息的隐藏引用；显式选择时以新引用集合构造模型输入。

### 7.3 从 Assistant 最终回复创建分支

Renderer 通过 `conversation.fork` 提交 `ForkConversationInput`：

```ts
type ForkConversationInput = {
  conversationId: string;
  throughMessageId?: string;
};
```

- 不传 `throughMessageId` 时，供右侧菜单创建普通侧边聊天；该对话保留 `parentConversationId` 并只在右侧打开，不进入左侧对话树。父对话没有 Context Checkpoint 时复制全部模型消息；存在 Checkpoint 时复制该摘要、作为覆盖边界锚点的最后一条消息，以及边界之后未覆盖的消息。锚点只用于映射新对话 Checkpoint，不会再次发送给模型。
- Runtime 创建 `kind = "subagent"` 的子对话时只保留 `parentConversationId` 作为生命周期关系，不复制父对话的 `model_messages`、Context Checkpoint、Timeline 或附件引用。子对话的第一条模型可见用户输入必须是 `spawn_subagent.task`；需要的父对话事实由调用方显式写入该任务。
- Subagent 初始任务终态为 `completed/failed/cancelled` 时只表示一轮执行结束，Conversation 继续接受父 Agent 的 `send_agent_message` 并创建后续 Run。Main Agent 调用 `end_subagent` 后，任务状态变为 `ended` 且子 Conversation 只读；该状态以 `subagent_task_ended` 进入父 Conversation 的 ThreadLog。用户界面删除才调用 Conversation 删除协议并移除记录，关闭右侧标签不改变生命周期。
- 应用中断后的 Subagent 恢复通知及启动时补发的失败/取消结果携带 `autoWake: false`，仍保存为未读结果，但不单独触发父对话新 Run；正常消息省略该字段，保留自动汇总行为。该标记随消息存入 JSONL，重复启动仍生效，用户后续发消息时可读取这些结果。〔FACT｜`conversation.ts`；`agent-database.ts`；`agent-runtime.ts`〕
- 传入 `throughMessageId` 时，该 ID 必须属于源对话中某个 Run 的最终、已完成 Assistant Timeline 消息；Main 将它映射到对应 `model_messages.sequence`，把该序号及之前的模型消息物化复制到相同项目或临时分组中的同级普通对话。新对话 `parentConversationId = null`，不与源对话建立继承关系。
- 同级分叉标题按源对话当前标题递增为 `源标题 (1)`、`源标题 (2)`；编号在同一项目或临时分组中取已有同名前缀的最大值加一。
- 指定边界后的用户消息、Assistant 消息和工具调用/结果不能进入分支。边界内模型消息引用的附件复制元数据并重映射 ID，其他附件不复制。
- 只有覆盖序号不晚于分支边界的 Context Checkpoint 才能复制到新对话；覆盖到边界之后的摘要不得注入历史分支。
- 同级回复分叉复制截至边界的 `conversation_timeline`，包括用户消息、Assistant 回复、工具过程和 Agent 消息；所有 Timeline ID、Run ID、会话 ID 和附件 ID 必须重映射，使复制后的历史完全属于新对话。源对话和新对话后续独立写入。
- 右侧侧边聊天 Timeline 仍为空，只展示创建侧边聊天之后的新消息。
- Renderer 关闭右侧侧边聊天标签时，使用既有 `deleteConversation({ conversationId })` 删除该子对话；仅在删除成功后移除标签。删除失败时保留标签并在当前工作区显示错误，不能把它降级为“隐藏后可重新打开”的状态。
- Renderer 将普通侧边聊天的 `activeRunId`、运行终态和 `hasUnreadResult` 聚合到左侧父对话状态：任一侧边聊天运行时父项显示运行中；未确认的成功结果显示蓝色圆点，未确认的失败结果显示红色圆点。完成事件不能因父对话或侧边标签当前可见而自动确认；用户点击父对话，或在主对话、任一侧边聊天中点击、输入、发送或执行用户滚动时，Renderer 通过既有 `markConversationResultViewed` 逐项确认这一组普通对话。模型输出造成的自动滚动不能被视为用户确认。

## 8. 工具合同

```ts
  summary: string;
  data?: unknown;
  artifactIds: string[];
  truncated: boolean;
  error?: AgentError;
};
```

- `summary` 是提供给模型和 UI 的有限结果。
- 完整长输出写入 Artifact，并明确 `truncated: true`。
- Tool Result 不能直接包含无法序列化的 Error、Stream、Buffer 或进程对象。
- `conversationToolItem.executionMode`（`parallel`/`serial`）记录 Runtime 对该调用作出的调度决定；字段可选以兼容历史 Timeline 行，不能被 Renderer 反向修改。
- `web_search` 是无需工作区的公共网络只读工具，使用内置免费 DuckDuckGo Provider；结果只包含有界的标题、摘要、域名和 URL，不提供网页交互能力，并受网络可用性和上游限流影响。
- `read_external_file` 只接受绝对路径，主进程在审批前只解析 canonical path、文件类型和大小，不读取正文；该工具即使在 `full_access` 下也必须逐次经过审批，临时对话同样可用。
- 同一项目中的 Agent 文件变更和 `run_command` 进入同一冲突协调边界；读目录、读文件、搜索和文件查找可由同一模型轮并发执行。模型一轮最多返回 32 个、且可以混合不同类型的 `toolCalls`；超过上限时整批在任何工具启动前以不可自动重试的 `MODEL_RUN_LIMIT_REACHED` 失败。Runtime 按 Tool Handler 的调度策略分组，只读并发窗口最多 8 个调用，非 `read_only` 模式下独立命令默认并行、每个窗口最多 4 个进程，`parallel=false` 可显式降级为串行；`ask_before_changes` 仍逐条审批，但已批准的独立命令可以重叠执行；结果按 `toolCallId` 关联，不按完成顺序改变消息顺序。文件变更在首个应用前保存每个调用的 `expectedContent`；后到的旧 Diff 在应用时返回 `FILE_CHANGED` 或项目冲突并作废，不允许覆盖先完成的变更，也不得自动重放。多个不同文件的审批/写入仍是逐文件的非原子批次。

## 9. 审批合同

```ts
type ApprovalRequest = {
  id: string;
  sessionId: string;
  runId: string;
  toolCallId: string;
  kind: "outside_workspace_read" | "file_write" | "apply_patch" | "command" | "browser";
  title: string;
  details: ApprovalDetails;
  createdAt: string;
};

type ApprovalResolution = {
  approvalId: string;
  decision: "approved" | "rejected";
  scope: "once" | "session";
  resolvedAt: string;
};
```

`scope=once` 只放行当前 Tool Call；`scope=session` 写入 Main 进程内按 conversation 维度的精确授权，应用重启后消失。命令按完整命令匹配，文件按工具类型与规范化项目相对路径匹配，不从 `ping`、`npm` 等命令前缀推导整类权限。审批卡不能写入 Agent 永久授权；Agent Profile 的 `permissions.allow` 只允许在设置页显式维护，末尾通配（例如 `mvn package *`）必须由用户主动配置，通配按 token 边界匹配且不匹配 `mvnx`。持久终端创建/命令复用 `run_command` 规则类型，浏览器副作用使用 `browser_control` 规则类型；未命中允许规则的副作用继续审批，当前不维护独立 deny 列表。

`applicationSettings.general.approvalReviewer` 为 `user | auto_review`，与 `defaultPermissionMode` 正交。`auto_review` 仅处理 `ask_before_changes` 原本会询问的操作；只接受严格 JSON 审核结果，低/中风险 `allow` 才直接执行，其余情况回退到用户审批。工作区外读取、删除和确定性高风险命令不会交给模型自动放行。审核事实以 `tool_approval_auto_reviewed` 进入 ThreadLog；自动通过不生成 session grant。

Subagent 首轮继承父 Run 的权限模式，后续 Agent 消息 Run 继承该子 Conversation 最近一次 Run 的冻结权限模式；它不继承父 conversation 的 `once` 或 `session` 授权。Renderer 通过子会话的活动 Run 和 `awaiting_approval` Tool 恢复父对话中的待审批投影，并从已有 `ConversationSummary` 关联来源头像、名称和子 Conversation ID；点击来源在右侧打开原生子对话，不新增审批协议字段。父、子入口都只提交既有的 `approved + scope + runId + toolId`，Main 仍按 Tool 所属 conversation 解析权限主体。过期或已处理的 Tool 审批返回 `APPROVAL_EXPIRED`，不得映射为 `FILE_CHANGED`。

工作区外文件读取是跨边界敏感操作，只支持 `once`，不能保存为会话或 Agent 永久允许；`read_only` 不会扩大写入权限，应用策略 `unavailable` 在 Main 端直接拒绝而不弹审批。

用户在编辑器中亲自点击保存属于直接用户操作，不走 Agent 审批；由模型发起的同一文件写入必须审批。两类操作在事件中使用不同 `actor` 标识。

```ts
type AgentError = {
  id: string;
  code: AgentErrorCode;
  message: string;
  retryable: boolean;
  details?: Record<string, unknown>;
};
```

第一阶段错误码至少包含：

```text
VALIDATION_FAILED
CAPABILITY_UNAVAILABLE
WORKSPACE_REQUIRED
PATH_OUTSIDE_WORKSPACE
FILE_CHANGED
APPROVAL_REJECTED
APPROVAL_EXPIRED
PROCESS_TIMEOUT
PROCESS_CANCELLED
PROCESS_FAILED
MODEL_AUTH_FAILED
MODEL_CONFIGURATION_INVALID
MODEL_RATE_LIMITED
MODEL_TIMEOUT
MODEL_PROVIDER_UNAVAILABLE
MODEL_RESPONSE_INVALID
MODEL_RUN_LIMIT_REACHED
NETWORK_UNAVAILABLE
STORAGE_FAILED
ARTIFACT_NOT_FOUND
PERMISSION_DENIED

```

错误返回用户可读 `message`，日志可以记录内部堆栈，但不能将 API Key、完整环境变量或敏感文件内容放入 `details`。

- `id` 是每次错误实例的 UUID，只用于关联 IPC、Run、工具结果和主进程日志；不拼接到用户可见错误文案。
- 主进程 IPC Handler 统一经过错误边界。错误通过可序列化 Envelope 传输，由 Preload 恢复为 `AgentClientError`；Renderer 不直接展示 Electron 原始异常。
- `run.finished` 保留兼容用的展示字符串，并通过 `agentError` 携带结构化错误；工具失败结果同样包含 `agentError`。
- 模型接口失败时，`details.status` 保存 HTTP 状态，`details.providerMessage` 只保存脱敏、截断后的供应商错误摘要；网络或内部异常可通过 `details.technicalMessage` 显示安全技术摘要。UI 显示这些有限详情，不展示完整响应体、HTML 网关页面或内部堆栈。
- API Key、Bearer Token 和可识别的 `sk-` 密钥在持久化、IPC、工具结果和日志前脱敏。
- 错误按归属渲染：进入自动重试的模型请求由 `model_retry` Timeline 卡片持续展示，工具错误留在对应工具行内，未进入重试的模型请求错误仍作为 Assistant 时间线错误，普通界面操作错误留在当前工作区操作区域。Assistant 错误卡默认只显示分类标题、用户可理解的结论和下一步建议；脱敏后的 HTTP 状态、供应商摘要、网络/内部技术详情放在“查看技术详情”中按需展开，完整响应体、框架排障链接和内部堆栈不得默认暴露。工具调用的原始参数和长结果仍由工具卡片自身控制展开。
- `model_retry` 保存 `attempt/maxAttempts/retryInMs/status/reason`。恢复时原卡片更新为 `completed`；耗尽时更新为 `failed` 并保留最终脱敏 Provider 错误，不再追加“模型响应无法处理”之类的通用重复失败消息。应用重启把仍在执行的 Run 保守标记失败时，同一事务也把该 Run 下遗留的 `retrying` 记录更新为 `failed`、清空 `retryInMs` 并保留原错误，Renderer 不得继续显示倒计时或旋转状态。
- 失败后手动发送的新请求创建新 Run，并重新获得该请求的自动重试次数。Renderer 的 Agent 选择以已持久化的 `ConversationSummary.agentId` 为准，不能让 localStorage 草稿选择或默认 Agent 覆盖它；已绑定对话锁定 Agent 选择，尚未绑定的新对话仍可选择。后续发送及强制压缩沿用同一成员身份，不放宽 Main 拒绝跨 Agent 重绑的约束，也不自动重放已完成工具。
- Renderer 渲染异常由 React Error Boundary 接管；主进程记录未捕获异常、未处理 Promise、Preload 失败和 Renderer 退出。Renderer 异常退出只自动恢复一次，避免重载循环。

第一阶段 SQLite 是主数据源，至少包含：


关键约束：

- 所有 ID 使用应用生成的 UUID。
- 时间统一存 UTC 毫秒或 ISO 字符串，数据库内保持一种格式。
- `events(session_id, sequence)` 建立唯一索引。
- `runs`、`messages`、`tool_calls` 保存当前可查询状态，`events` 保存追加式过程。
- 当前状态与对应事件在同一事务中提交。
- `model_profiles` 只保存非敏感配置和密钥引用，不保存 API Key。
- `model_providers` 保存 Adapter 类型、端点和凭据引用；同名模型通过 `provider_id + model_id` 唯一识别。
- 当前模型配置文件同时保存全局默认模型、最近一次用户手动选择，以及每个模型的 `connectionStatus`、`connectionStatusUpdatedAt`、`lastSuccessfulAt`。它是配置与健康事实源；Renderer/Zustand 不复制第二份可写目录。
- `conversations` 保存当前 `provider_id + model_id + reasoning` 选择快照。新普通对话由 Main 按“最近用户选择 -> 默认模型”解析；侧边对话和 Subagent 创建时复制父 Conversation，之后可独立更新。
- Renderer 切换 Conversation、切换侧边标签或折叠/展开右侧工作区时，必须从目标 Conversation 的选择快照恢复控件；全局最近选择和默认模型只参与新 Conversation 初始化或缺失快照的兼容兜底，不能覆盖已有快照。
- Renderer 可保活当前 Conversation、顶部仍打开的所有主对话标签，以及普通缓存层中一小时内访问过的最多 8 个页面。标题栏标签是缓存保护的可见契约：点击左侧对话会新增或激活唯一标签，运行中的对话标签显示动态状态，关闭标签后该页面重新服从普通缓存淘汰；标签集合只属于当前 Renderer 生命周期，不是 Conversation 持久化事实。该缓存只持有展示实例和只读模型状态快照；归档、删除、项目移除或超时淘汰后重新通过 `AgentClient` 从持久化事实加载，不能把缓存写成第二份业务事实源。多个保活页面共享一个底层 `conversation.run_event` 订阅，再按 `conversationId` 分发。
- `conversation.set_stream_subscriptions` 接受最多 1,000 个 Conversation UUID，空数组表示停止正文订阅。只允许主 Renderer 的可信主 frame 调用；可见对话或实时图按需声明范围，Main 以约 32ms 合并 Assistant 正文、推理和工具输出后推送。未订阅对话只保留 Main 内存中的当前输出快照；运行状态、未读、审批等通知继续送达。重新订阅通过 `reset: true` 替换当前输出，不能把快照追加成重复文本；后台命令快照有界，并在命令终止后释放。
- 缓存中未激活的普通对话和群聊不因输出通知刷新历史，只标记待补齐。重新激活时若没有后台变化，直接复用消息区域、分页和滚动位置；有变化才读取最新历史并合并已有页面，不先清空缓存。正在生成的内容由 Main 快照补齐，最终历史仍以持久化记录为准。
- `conversation.set_model_selection` 只接受已配置的 Provider、模型和已启用思考选项。普通/侧边 Conversation 的用户更新同时刷新最近选择；`subagent` 和受管 Team WorkItem 执行树 Conversation 都不刷新该全局偏好。受管 Team Conversation 的模型/思考更新必须在同一事务中写入当前 Conversation 展示快照和其 WorkItem 的后续 Run 策略；当前 Run 的 `run_model_snapshots` 不可修改。它仍拒绝改项目，且正在运行时的用户输入只能作为同一 Run 的 `steer`。
- `run_model_snapshots` 保存实际模型、选择来源和能力快照，创建后不可修改。
- MCP、Skill 配置按应用、Team、Project 或 Agent 范围启用；它们不能扩张 Task 的项目权限。
- `SkillConfiguration.origin` 为 `system | personal`，旧记录缺失时按个人展示；`scope` 继续表示可用范围。系统安装器标记来源并停用同名、正文一致的旧路径副本，保留 ID、文件和自定义内容。
- Artifact 大内容不保存为 SQLite BLOB。
- 每个 `tasks.project_id` 必填；跨项目 WorkItem 通过多个 Task 表达，不允许一个 Task 绑定多个项目。
- `task_dependencies(task_id, depends_on_task_id)` 建立唯一约束并禁止自依赖。
- 一个 Task 同时最多有一个未过期的 `task_lease`，领取和续租使用事务。
- Team Lead、Agent Thread 和任务调度事件进入同一事件体系，运行状态不能只保存在内存 Store；这里的 Agent Thread 是逻辑对话归属，不对应 OS 线程或进程。

### 11.1 Artifact

```ts
type ArtifactRecord = {

  kind: "terminal_log" | "diff" | "browser_snapshot" | "screenshot" | "tool_output";
```

Artifact 必须位于应用数据目录，数据库只保存相对路径。读取时重新解析绝对路径并确认仍位于 Artifact 根目录，防止路径注入。

### 11.2 ConversationAttachment

```ts
type ConversationAttachment = {
  id: string;
  conversationId: string;
  messageId: string | null;
  source: "project" | "upload";
  kind: "file" | "image";
  name: string;
  mimeType: string;
  sizeBytes: number;
  projectPath: string | null;
  contextTokens: number;
  truncated: boolean;
  createdAt: string;
};
```

- 用户可以通过输入框的附件按钮多选文件，也可以把系统剪贴板中的文件或截图直接粘贴到输入框。文件选择由 Main 原生对话框返回路径；粘贴内容通过有 25 MB 上限的 `conversation.import_attachment_bytes` IPC 传递 Base64 字节，Renderer 不提交本地路径。两种入口都立即复制到 `<ASTER_HOME>/conversations/<conversationId>/attachments/` 并创建尚未绑定消息的草稿引用。发送消息时先把用户消息、Run 快照和附件引用追加到该对话 JSONL，再更新当前进程的临时视图。
- SQLite 的 `conversation_attachments` 保存公开元数据、受管文件路径和可选提取文本路径；`model_messages.attachment_ids_json` 保存有序附件 ID。Renderer 永远不能获得受管绝对路径。需要展示图片时，只能使用 `conversation.read_attachment_preview` 携带当前 `conversationId + attachmentId` 读取已校验为图片的有界 Base64；Main 必须验证附件属于该会话，普通文件不能通过这个接口读取正文。
- 项目内文件和项目外上传文件都保存不可变快照。`source` 和 `projectPath` 只描述快照来源，不改变模型处理方式；项目中未显式添加的文件继续通过工作区工具读取实时内容。
- 图片查看工具现接收 `view_attachments({paths:[...]})`（1–4 项），替代模型侧附件 ID 参数。附件上下文提供 `attachments/<存储文件名>`，其他路径相对工作区；项目同名目录必须加 `./`。新结果 `value.items` 按输入顺序包含 `{attachment:公开附件元数据}` 或 `{image:{projectId,path,mimeType}}`，不包含图片字节和受管绝对路径。Renderer 分别复用附件/项目预览 IPC；模型视觉字节只通过工具的模型附件通道传递。
- 文本、常见代码、PDF 和 DOCX 在 Main 进程提取为 UTF-8 文本。超过 48,000 字符时只注入头 36,000 和尾 12,000 字符，全文由只读工具 `read_attachment(attachment_id, offset, limit)` 分段读取。
- PNG、JPEG、GIF 和 WebP 的字节不写入对话 JSONL。最新用户消息的图片按需读取快照并编码；较早图片保留名称、读取路径、类型和来源，需要回看时调用 `view_attachments({paths:[...]})`，最多四张。视觉字节只进入模型附件通道，Timeline 保存引用，界面通过受控预览 IPC 加载缩略图。各 Provider Adapter 转换为对应多模态内容；不支持视觉时返回真实错误，仅历史图片且请求尚无输出时保留既有的一次元数据降级重试。
- 每条消息最多 10 个附件，单个附件最多 25 MB。发送前草稿可移除；编辑最新已发送用户消息时，可以保留或移除原附件，也可以选择、粘贴新附件。`conversation.replace_latest_message` 接收编辑后的最终有序 `attachmentIds`，只允许引用该消息原附件或本会话当前未绑定草稿；新草稿与替换 Run 在同一 SQLite 事务或同一个 write-ahead `run_replaced` 事实中绑定。被移出消息的旧快照不再进入 Timeline 和模型上下文，但继续作为受管不可变快照保留到会话清理，避免数据库与文件系统之间产生不可恢复的半删除。
- Pending Message 被删除时，其附件不回退成输入框草稿。取消记录继续持久保存并暂时保留附件绑定，作为可重试的文件清理事实；Main 删除无其他附件引用的受管文件后才移除附件行，文件被占用或进程中断时在下次启动继续。旧版本已经解绑为草稿的取消附件按取消消息原始 `attachmentIds` 识别并清理；已经进入模型上下文或绑定正式消息的附件不参与该修复。
- 输入框附件保持单行、等高、横向溢出；已发送消息的正文气泡在上，图片预览或文件卡片以独立附件条显示在正文下方，不嵌入文字气泡。编辑最新用户消息时，编辑器以相同附件条展示当前最终选择，并允许逐项移除或继续添加。
- 创建分叉时形成不可变上下文快照：右侧侧边入口在无 Checkpoint 时复制全部 `model_messages`，有 Checkpoint 时只复制覆盖边界锚点和未覆盖消息并映射摘要；回复分叉入口只复制指定最终 Assistant 回复及之前的消息。仅当最新 `conversation_context_checkpoints` 未覆盖到回复分叉边界之后时才复制摘要，并把 `covered_through_sequence` 映射到新对话消息序号。
- 回复分叉使用普通 `agent` 身份、`parentConversationId = null` 并复制源对话当时的 Agent 配置；右侧侧边聊天使用普通 `agent` 身份和源对话 `parentConversationId`；任务 Subagent 使用 `subagent` 身份并必须有对应任务生命周期记录。
- 回复 Fork 将边界内的可见 Timeline 写入同级新对话，Renderer 立即显示分叉前历史；右侧侧边聊天仍不复制 Timeline。源对话后续消息不自动同步。分叉只复制快照内模型消息实际引用的附件元数据，并同时重映射附件 ID、附件所属消息 ID 和 Timeline ID；底层不可变文件快照可以共享。
- 清理文件前必须查询 SQLite 引用；删除父对话、子对话或归档到期都不能删掉仍被其他对话引用的快照。
- 删除会话时先在一个 SQLite 事务中创建 `conversation_deletion_tasks`，保存根会话、整棵会话树、受管文件路径、状态、重试次数和最后错误，同时把相关会话标记为 `deletion_pending`。待删会话不再出现在列表、Agent 发现或临时工作区恢复中。
- `conversation_deletion_tasks` 不使用指向 `conversations` 的级联外键，确保进程退出、文件占用或数据库收尾失败时恢复事实仍然存在。任务可以处于 `pending`、`running` 或 `failed`，启动和每日归档清理都会重试未完成任务。
- 文件清理只删除任务记录的受管路径。判断共享引用时忽略待删会话，但保留任何正常会话仍引用的快照；`ENOENT` 按已完成处理。会话树对应的 ThreadLog JSONL 同样在任务内删除，缺失按已完成处理；文件完成后，删除会话树和任务记录在同一个 SQLite 事务内提交。
- 会话删除任务在文件清理成功后还会删除对应 Run 的 LangGraph Checkpoint thread；Checkpoint 数据库暂时独立于业务库，删除失败会让原清理任务保持 `failed` 并在启动/定时任务中重试，不能只删除业务会话行。
- 手动删除和归档 30 天到期删除必须调用同一个会话删除 Use Case，不能直接执行 `DELETE FROM conversations` 后再补删文件。

## 12. 模型上下文合同

`ContextBuilder` 的输出由以下部分组成：

```ts
type ModelContext = {
  systemInstructions: string;
  workspaceContext: WorkspaceContext;
  conversationSummary?: StructuredSummary;
  recentMessages: ModelMessage[];
  relevantArtifacts: ArtifactExcerpt[];
  availableTools: ModelToolDefinition[];
  estimatedInputTokens: number;
  estimatedAttachmentTokens: number;
  inputBudget: number;
};
```

`getConversationContextUsage` 除总输入、压缩阈值和输出预留外，还返回 Skill 目录、活动任务清单和 Skill 正文预留的独立 Token 估算。Renderer 区分“实际输入”和“预留容量”；Skill 正文预留不计入已使用输入，工具 Schema 属于实际输入。可选 `providerCache` 来自 Provider 实际用量。Runtime 的 `latest` 与首字、速度来自最近一次已完成且上报用量的同一持久化 ProviderState，等待、失败、取消或下一响应没有用量时保留完整快照；新用量没有缓存字段时 `latest.hitRate=null`。底栏命中率分组显示“本次 / 平均”，无障碍标签保留完整名称，尚无用量显示 `--`，缓存字段未上报显示“未上报”，不借用 `lastReportedHitRate`；后者仅供明细参考。`cumulative` 从 JSONL 有效用量汇总，只包含最近已上报请求所属的 `apiFormat + baseUrl + modelId` 缓存池，按 `sum(cachedInputTokens) / sum(inputTokens)` 加权，真实零命中照常计入、未知不补零。页面刷新失败或新请求开始不清空实际快照，不显示流式估算；应用重启仍从 JSONL 恢复最近上报的完整计量。当前 MCP Runtime 尚未实现，因此不存在可发送的 MCP Tool Schema。

`providerCache.outputTokensPerSecond` 为可选、可空的非负有限数。Adapter 用单调时钟记录 `ModelProviderState.generationDurationMs`（首个正文、思考或工具输出到响应结束），Runtime 仅将同一响应的服务端 `usage.outputTokens` 除以正耗时；等待、取消、缺少实际 Token 或耗时为零时返回 null。旧记录无该字段仍可读取，不执行数据回填。

- Skill 目录摘要作为系统上下文的一部分发送；模型调用 `load_skill` 后，`SKILL.md` 正文由 Runtime 临时注入下一轮模型请求，不新增聊天 Timeline/用户消息。Graph State 只保存 Skill 的 `id/version/contentHash`，恢复或压缩后重新读取正文并校验哈希；内容变化时 Run 失败并要求重新加载。Agent 为 `custom` 能力范围时，其 `skillIds` 同时约束目录、加载、reference 和恢复注入；`inherit_all` 才继承全部满足作用域的已启用 Skill。
- `read_skill_reference` 的 `path` 必须是已激活 Skill 下 `references/` 或 `templates/` 的相对路径。Main 端拒绝绝对路径、`..`、符号链接、NUL、非法 UTF-8 和超大文件，并在读取前执行字节上限检查；Skill 文档不能扩大权限或绕过审批。`team` 作用域只在带 `teamId` 的团队会话生效。
- LangGraph Checkpoint 的 `thread_id` 使用应用生成的 Run ID。`checkpoint_ns` 由 LangGraph 为 Middleware、ToolNode 和嵌套图组合生成，允许最长 8,192 字符，不能套用普通标识符的 512 字符上限；它仍只作为 SQLite 预编译语句参数使用。应用重启只自动恢复尚未进入模型/工具节点的 `queued` Run；已经处于 `running` 的 Run 按可能发生外部副作用处理为失败，不自动重放。恢复不会创建重复用户消息。

- 当前 Run、未完成审批和明确用户约束不可被摘要替代。
- 当前 active 任务清单是独立的临时运行上下文块。它在每次模型请求前刷新，并以不落盘的 `user` 消息追加到稳定历史和当前 Run 消息之后，避免任务状态变化使 Provider 的整段历史前缀缓存失效；它不进入 Timeline，也不写回 LangGraph 消息。每项包含 `title`、`status` 和可选 `reason`；`reason` 仅用于 `blocked`、`failed` 的简短、可展示解释，最长 600 字符。同一清单允许多个任务同时为 `running`，只表示所属对话正在并行推进这些工作，不包含执行者或 Subagent 绑定。已有不含 `reason` 的持久化清单读取为 `null`，以保持兼容。
- Tool Schema、输出预留、安全余量和 Skill 正文保留预算先从模型窗口中扣除。启用 Skill Runtime 时，ContextManager 预留 `max(1024, min(12000, floor(effectiveContextWindow * 0.12)))` Token；没有模型窗口时按 48,000 Token 计算。Skill 正文实际注入和用量估算使用同一预算，正文仍不进入 Timeline。
- 模型窗口、最大输出和输出预留来自本次 Run 的 Model Profile 快照；用户修改配置只影响后续模型调用。
- 旧工具输出先裁剪或 Artifact 化，再摘要对话。
- 文本附件按实际注入的标题和预览估算 Token；图片按文件大小在 1,024 至 8,192 Token 之间保守估算并计入图片说明。Provider 返回精确用量后可用于校准，但不能依赖所有厂商都返回图片 Token。
- 压缩顺序是先裁剪旧工具输出，再合并较早完整轮次的隐藏摘要，最近两轮尽量原样保留。轮次摘要使用动态门槛：只有一种有效来源时单项软上限约 448 tokens；用户/Assistant/工具来源越多，单项门槛逐级收紧，最低约 320 tokens，同时整轮总量不得超过当前单项门槛的两倍。小幅位于边界内的内容仍直接本地封装，不额外调用模型；越过单项或整轮门槛才生成一次短模型摘要。本地封装的单字段最多保留 720 个归一化字符。摘要用来源标签区分普通用户、Steer、其他 Agent、Assistant 与工具。进入摘要的附件保留附件 ID、名称、类型、来源、项目相对路径、读取状态和截断状态，不把图片 Base64 放进摘要。
- 自动达到阈值和用户发送 `/compact` 都进入同一增量压缩流程。`/compact` 可在未达到阈值时主动压缩符合条件的较早完整轮次；压缩运行状态以 Timeline-only 的 `compact_context` Runtime Activity 记录，不生成模型可见的 ToolMessage。Renderer 将它显示为带压缩图标的居中说明分割线，运行中显示流光和实时耗时，完成后显示“已压缩”和最终耗时；实际处理条数仅在悬停提示中提供。
- 发送前计算本轮最低预算。如果本轮内容自身仍超过压缩阈值，不创建 Run、不绑定草稿附件，并向对话区返回可操作错误；用户可减少附件或调整模型上下文/压缩阈值后重试。
- 每轮隐藏摘要写入 `conversation_turn_summaries` 并记录 `run_id` 与覆盖终点；它是可由原始记录再生成的 SQLite 加速数据。正式压缩结果写入 `conversation_context_checkpoints`，覆盖序号只能前进。
- `conversation_turn_summaries` 必须由独立的前向迁移创建，不能只追加到已经执行过的初始建库脚本；现有版本 19 数据库启动时通过版本 20 补建该表和覆盖边界索引，避免真实用户库因缺表导致摘要生成和压缩失败。
- 摘要失败不能删除原始消息；自动压缩最多缩小一次完整旧前缀重试，手动强制压缩可继续逐级缩小，但始终保留当前任务、压缩期间新到输入和最近保护轮次。失败后的强制重试入口只显示图标，操作含义和真实失败信息通过悬停提示提供。用户停止手动压缩时，已落盘 Checkpoint 保持有效，活动显示为“已暂停”；期间的 Queue、Steer 和 Agent 输入继续等待，不因 Run 结束而自动放行。用户点击继续压缩图标或再次发送 `/compact` 后从最新覆盖边界续做，压缩完成才按 Steer 优先、Queue 其次的既有顺序交给模型。

## 13. 密钥与配置

> 当前应用配置已统一为 `settings.jsonc`，支持注释、明文 Key 并保留编辑格式；迁移与安全边界见[第 24 篇](./24-Aster目录结构与JSONC配置.md)。

- `protocol_adapters` 表示已安装的对话协议实现；`provider_endpoints` 保存用户选择的协议 Adapter、Base URL、可选请求路径和凭据引用。
- `model_profiles` 保存模型 ID、别名、角色、能力、上下文窗口、输入/输出上限和配置来源。
- API Key 由 Electron Main 读取和保存到 `settings.jsonc.providers[].apiKey`；`safeStorage` 仅用于首次导入旧加密凭据。旧目录已有 JSONC 优先迁移，已有 `providers`（包括空数组）不被旧密文或环境变量覆盖，解密失败不弹启动警告。
- Preload 仅在供应商设置中通过受校验的接口读取单个 API Key，不把 Key 放入模型列表、运行快照或事件流。
- Renderer 提交新 Key 后，Main 原子修改 JSONC 对应字段并保留用户注释；读取失败提示检查配置，不误报为系统解密失败。
- 日志序列化器对 `authorization`、`apiKey`、`token` 和常见密钥格式做统一脱敏。
- MCP Token、敏感环境变量和远程授权凭据使用同一凭据引用机制，不写入 Server JSON 或 SQLite。
- Agent 的模型继承、固定、自动选择和用户动态修改规则以[模型接入、MCP、Skill 与 Agent 对话设计](./08-模型接入、MCP、Skill与Agent对话设计.md)为准。
- 管理数据根目录由 Main 解析：`ASTER_HOME` > `AGENT_HOME` > 用户选择 > `<os.homedir()>/.aster`。用户选择保存在稳定的 `appData/aster-agent/storage-location.json` 启动指针；`application_settings.get_storage_location`、`application_settings.choose_storage_location`、`application_settings.reset_storage_location` 只返回当前路径、重启后路径、默认路径、来源及是否需重启，不向 Renderer 暴露数据库内容。选择和恢复默认不移动、复制或删除现有数据，重启后生效。环境变量存在时选择接口只读。显式配置管理目录时，Electron `userData` 使用 `<ASTER_HOME>/electron-profile`。
- 当前 `ThreadLog v1` 位于 `<ASTER_HOME>/conversations/<conversationId>/conversation.jsonl`；所有 Conversation 创建时即写入属性事件，消息、Run、工具、审批、压缩、任务和 Agent 协作过程继续追加到同一日志。首次升级先导出并验证旧 SQLite 会话，再删除 `db.sqlite` 中的 Conversation、Timeline、Run、消息和搜索表。列表及部分状态仍用进程内 SQLite `TEMP` 投影，任务清单、事件索引和游标使用内存 Map；时间线分页及搜索直接读 JSONL，不建立 SQLite FTS。`ContextCompiler` 按位置读取 Checkpoint 未覆盖正文，旧历史检索和供应商用量也不查询 SQL。Renderer 只通过 Main IPC 请求按页数据。附件引用记录公开元数据，受管文件位于 Conversation 目录，由 Main 解析路径；二进制不写入 JSONL。〔FACT｜`thread-log.ts`；`context-compiler.ts`；`agent-database.ts`〕

## 14. 版本与兼容

- 所有持久事件和跨进程 Envelope 包含 `schemaVersion`。
- SQLite 使用只向前执行的版本化 Migration。
- Preload API 暴露 `apiVersion`，Web UI 启动时检查兼容性。
- 不在第一阶段支持任意旧版数据库；开发期结构变更通过 Migration 或明确重建测试数据库。
- 会话导出格式与内部数据库 Schema 分开版本化，避免数据库调整破坏导入导出。

关键约束：

- 所有团队事件包含 `teamId`；任务事件同时包含 `workItemId`、`taskId` 和 `projectId`。
- `TaskListView` 是 `tasks`、依赖和事件的查询投影，不单独维护另一份 Todo 状态。
- AI 创建或修改任务列表时递增 `revision` 并保存理由；已完成 Task 重新打开必须产生显式事件并保留原完成证据。
- 创建 Task 不触发 Agent 创建；是否委派由 TeamSupervisor 独立决策。
- `routing.decided` 保存候选集合、过滤原因、选中 Agent 和简短分配理由。
- Agent 间消息的 `actor` 不能是 `user`，也不能携带用户审批凭据。
- Agent 结果通过有界回执和来源 Conversation/Artifact 引用回传，不复制整个执行对话；持久 Agent 以 Markdown `---` 分隔回执和详细结果，自动回执只取分隔线前最多 1000 字符。临时 Subagent 的复杂最终回答同样以分隔线区分最多 2000 字符的完成回执和子对话内的支持细节，简单短答直接回传；结果消息额外包含 `fileChanges[]`，最多 50 项，只收集本轮成功的 `write_file/replace_in_file/delete_file/apply_patch` 路径并按路径去重，不推断 Shell 间接修改。完整回答由调用方按 `maxTokens` 主动读取，已知核验目标可附带最长 500 字符的 `query` 进行相关消息检索。
- 同一 Team 的事件需要团队级单调序号；单 Session 事件序号继续保留，用于局部恢复和渲染。
- 自动扩容达到并发、实例、时间或 Token 上限时发送事件并排队，不通过重试绕过限制。

## Skill 创建与系统只读（2026-10-19）

复用 createSkillDocument：CreateSkillDocumentInput 可选 content（最多 200,000 字符）表示完整 SKILL.md，name 决定目录；省略时保留 UI 的空白模板流程。模型 create_skill 仅接受 content，不接受外部根目录，使用现有 SkillRuntime/ToolHandler、串行执行及 write_file 审批动作；只读拒绝，审批前不创建文件。相同个人内容重试返回原记录，存在不同内容或系统同名目录时拒绝覆盖。创建后立即登记个人来源供设置和后续目录发现。

ConfigurationWorkspaceDirectoryListing 与 ConfigurationWorkspaceFile 增加可选 readOnly，旧数据省略兼容；Main 对系统技能整个目录返回 true，普通文件 isProtected 仍只表达入口不可删除。系统文件可读，所有增删改均拒绝，别名指向系统目录也保持只读。skill.save_document 拒绝系统目录，IntegrationConfigurationStore 对已登记系统条目只允许 enabled 改变，不能通过移除 origin 或条目绕过只读。


## 显式对话审批模式（2026-10-19）

ConversationPermissionMode 新增 request_approval 与 auto_review；full_access 继续使用。read_only 与 ask_before_changes 保留读取／恢复兼容，旧 ask_before_changes 沿现有全局 approvalReviewer 默认。新选择显式覆盖该默认，审批不再通过全局开关影响所有已选择对话。保存、Run 快照、成员通信和后台发送使用同一 Protocol 类型；发送省略权限字段时使用已保存模式。submit_team_work_item 保留显式新模式，不提升为完全访问，旧询问模式的团队交办行为继续兼容。web_search 加入可审批工具类别，搜索动作在参数校验后、网络访问前沿既有 approved_action 流程确认；完全访问与旧只读搜索沿原执行路径。
