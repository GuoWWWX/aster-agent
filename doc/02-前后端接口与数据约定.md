# 前后端接口与数据约定

> 文档状态：开工基线  
> 更新时间：2026-08-27
> 关联文档：[第一阶段需求与验收标准](./01-第一阶段需求与验收标准.md)、[模型接入、MCP、Skill 与 Agent 对话设计](./08-模型接入、MCP、Skill与Agent对话设计.md)

## 1. 目的

本文档定义 `apps/web`、Electron Preload、Agent Runtime、本地工具和存储之间的最小合同。目标是让同一套 React UI 可以运行在浏览器和 Electron 中，同时确保 Renderer 不能绕过权限边界直接访问 Node 能力。

本文档定义的是边界和语义，不要求首个提交一次性实现全部接口。

## 2. 边界原则

- `apps/web` 只依赖 `packages/protocol`，不导入 Node、Electron、SQLite、文件系统或 PTY 模块。
- Electron Preload 实现 Desktop Transport，Web 开发模式实现 Mock Transport。
- UI 只调用 `AgentClient`，不判断 `window.__TAURI__`、`window.electron` 或运行平台后直接调用系统 API。
- 命令使用请求/响应语义；长任务、流式消息和工具过程使用事件流。
- 所有跨边界数据都可序列化，并通过 Zod Schema 校验。
- Schema 以 `packages/protocol` 为唯一来源，Renderer 和 Main 不各写一套类型。

接口按实现环境分为：

| 实现 | 使用位置 | 能力 |
| --- | --- | --- |
| `DesktopAgentClient` | Electron Renderer | 通过 Preload IPC 调用完整本机 Runtime |
| `MockAgentClient` | Vite 浏览器开发 | 固定夹具和模拟事件，不访问本机系统 |

### 3.1 模型供应商品牌标识

`SaveModelConfigurationInput.providerIcon?: ModelProviderIcon` 与 `ModelProfile.providerIcon?: ModelProviderIcon` 用于供应商展示，不参与模型请求或凭据认证。Desktop 凭据配置以 Provider 维度持久化该字段，缺失的历史配置等价于 `auto`；Renderer 在 `auto` 时从供应商名称生成 1 至 2 个字符，其他值使用本地打包的品牌图标或中转站字母标识。可选值由 `modelProviderIconSchema` 统一校验，避免 Renderer 与 Main 各自维护不兼容的名称集合。

第一阶段实现前两个。`WebAgentClient` 只保留接口位置，不写空壳功能和假成功返回。

### 3.2 Plugin Catalog IPC

Desktop Preload 使用 `plugin.list` 和 `plugin.set_enabled` 两个窄 IPC。`PluginCatalogEntry` 只暴露 `id`、名称、版本、内容哈希、启用状态和更新时间；受管包的绝对目录、manifest 原文与任何本机路径均不跨 Renderer 边界。启停只更新 Catalog 状态，影响后续新建 Run 的 Plugin 快照，不中断或重写运行中的 Run。〔FACT｜`packages/protocol/src/plugin.ts`；`apps/desktop/src/main/ipc/register-main-ipc.ts`〕

## 4. CapabilitySet

UI 不能根据平台字符串猜测能力，应读取 Runtime 返回的能力集合：

```ts
export type CapabilitySet = {
  mode: "desktop" | "web" | "mock";
  workspace: boolean;
  fileWrite: boolean;
  process: boolean;
  pty: boolean;
  git: boolean;
  managedBrowser: boolean;
  mcp: boolean;
  skills: boolean;
  docxConversion: boolean;
};
```

不可用能力在 UI 中不显示操作入口，或以真实禁用状态呈现；不能点击后才返回“尚未实现”。

## 5. 命令与事件

### 5.1 命令

命令由 UI 发起并等待一次响应，例如创建会话、开始 Run、取消和审批。每个跨进程命令包含：

```ts
type CommandEnvelope<T> = {
  schemaVersion: 1;
  requestId: string;
  command: string;
  payload: T;
};
```

- `requestId` 用于关联响应和避免重复提交。
- 有副作用命令不得因 IPC 重连自动重试。
- Runtime 在执行前再次校验 Schema 和权限，不能只相信 Renderer 已校验。

### 5.2 事件

Agent Runtime 向 UI 推送统一事件：

```ts
type EventEnvelope<TType extends string, TPayload> = {
  schemaVersion: 1;
  eventId: string;
  sessionId: string;
  runId?: string;
  sequence: number;
  timestamp: string;
  type: TType;
  payload: TPayload;
};
```

- `sequence` 在单个 Session 内严格递增，用于恢复后补齐事件。
- UI 按 `eventId` 去重，按 `sequence` 排序。
- 实时事件先推送 UI，持久事件成功写入后才能成为恢复事实。
- UI 重新订阅时携带最后确认的 `sequence`，Runtime 返回缺失事件。
- `conversation.updated` 的 `ConversationSummary.activeRunId` 仅表示当前可取消的模型 Run；`activeSubagentCount` 由 `subagent_tasks` 中该父对话直属的 `queued`/`running` 任务实时聚合。UI 在任一字段表示活动时显示“运行中”，但停止按钮只能取消 `activeRunId` 指向的 Run。
- `ConversationSummary.avatarIcon` 是可选的受控 Agent 图标 ID。Subagent 创建时把解析后的图标写入 `conversations.avatar_icon` 并通过该字段投影到 Renderer；旧 Conversation 可以缺省为 `null`。Renderer 只按协议枚举映射本地 Lucide 组件，不能执行模型提供的 SVG、URL 或组件名。
- `model.request_retrying` 表示本轮尚未产生可见文本或工具调用，Runtime 正在对可安全重放的网络错误、限流、服务端错误或空响应执行退避重试；一旦产生文本或工具调用，不再重放模型请求。

### 5.3 第一阶段事件类型

```text
session.created
session.renamed
run.started
run.status_changed
message.created
message.delta
message.completed
tool.requested
approval.requested
approval.resolved
tool.started
tool.output
tool.completed
tool.failed
summary.created
artifact.created
agent.model_selected
agent.model_changed
mcp.connection_changed
mcp.capabilities_changed
skill.enabled

```

`message.delta` 和 `tool.output` 是高频事件。UI 可以逐块显示，但存储层按时间或大小合并写入，不能每个 Token 或每个字符单独提交事务。

### 5.4 右侧栏项目文件编辑 IPC

右侧栏用户编辑使用与项目工具相同的项目操作锁，但不经过 Agent 权限审批。Preload/Renderer 暴露两个窄接口：

```ts
writeProjectFile({
  projectId: string,
  path: string,                 // 项目根相对 POSIX 路径
  content: string,
  expectedContent: string | null,
}): Promise<ProjectFile>;

readProjectPreviewImage({
  projectId: string,
  sourcePath: string,            // Markdown 文件路径
  path: string,                  // 正文中的原始图片引用
}): Promise<{ mimeType: string; data: string }>;
```

- `writeProjectFile` 在 `ProjectToolRegistry` 内执行，参与文件/命令统一锁；命令或其他项目变更占用时返回 `CONFLICT`（底层 `PROJECT_OPERATION_CONFLICT`）。
- 写入前必须将磁盘当前文本与 `expectedContent` 比较；不一致返回 `FILE_CHANGED`，不得覆盖。成功后返回新的 `ProjectFile`，Renderer 更新下一次保存的预期内容。
- `readProjectPreviewImage` 以 `sourcePath` 所在目录解析相对引用，再执行真实路径边界、符号链接、扩展名和体积校验；远程/data/blob 引用不经此通道，图片以 Base64 data URL 返回。
- `ProjectFile.truncated === true` 表示仅返回前 2 MB，UI 必须保持只读，禁止把截断内容写回原文件。
- `fileChange` 事件刷新无脏草稿标签；有脏草稿时只标记外部变更，交由下一次 `expectedContent` 校验处理。

## 6. Run 状态机

```text
queued
  -> running
      -> waiting_approval
          -> running
          -> blocked
      -> completed
      -> failed
      -> cancelled
      -> interrupted
```

约束：

- 一个 Session 第一阶段最多有一个活动 Run。
- `completed`、`failed`、`cancelled`、`blocked` 和 `interrupted` 是终态。
- 应用异常退出后，原 `running` 和 `waiting_approval` Run 在下次启动时转为 `interrupted`。
- `interrupted` Run 可以由用户发起新的继续请求，但不能从中间自动重放有副作用的工具。
- 状态转换通过存储事务提交，并生成对应事件。
- Run 开始时写入不可变 `modelSnapshot`；Agent 后续修改模型策略不反向改变历史 Run。
- 模型切换只影响下一次模型调用；需要立即切换时先取消当前 Run，再创建新 Run。

## 7. 消息模型

### 7.1 消息复制导出

复制最终 Assistant 回复时，Renderer 按该消息的 `runId` 从 Timeline 选出同一 Run 的 Assistant 回复和工具记录，并按 Timeline 顺序生成 Markdown。命令包含命令行、状态、退出码、stdout 和 stderr；文件工具包含 Diff；读取、搜索和其他工具输出为有界结构化文本。用户消息、隐藏 reasoning、内部工具 JSON、错误实例 ID 和受管绝对路径不进入导出。没有工具记录时仍复制原始 Assistant Markdown。代码块围栏会根据内容中的反引号动态加长，避免破坏 Markdown。

桌面端使用 `clipboard.write_text` IPC 调用 Electron Main 原生剪贴板。请求通过 `clipboardWriteTextIpcArgumentsSchema` 校验，文本上限为 2,000,000 个字符，成功返回 `void`；浏览器 Mock 使用浏览器 Clipboard API。

```ts
type Message = {
  id: string;
  sessionId: string;
  runId?: string;
  role: "user" | "assistant" | "system";
  status: "streaming" | "completed" | "failed" | "cancelled";
  createdAt: string;
  completedAt?: string;
  durationMs?: number;
  blocks: ContentBlock[];
};

type ContentBlock =
  | { type: "text"; text: string }
  | { type: "tool_call"; toolCallId: string }
  | { type: "tool_result"; toolCallId: string }
  | { type: "approval"; approvalId: string }
  | { type: "artifact"; artifactId: string; label: string }
  | { type: "summary"; summaryId: string };
```

第一阶段不将模型私有推理内容作为普通消息持久化或展示。只记录供应商明确返回、适合用户查看的摘要或状态文本。

Renderer 显示消息时间时按用户本地日历格式化：当天只显示时分，前一天显示“昨天 + 时分”，同一年较早日期显示“月日 + 时分”，跨年显示完整年月日和时分。Assistant 最终消息的 `completedAt` 与 `durationMs` 是 Timeline 查询根据所属终态 Run 的 `updated_at - created_at` 派生出的只读展示字段；不会重复写入消息正文、模型上下文或 ThreadLog。

模型可见正文与 Reasoning 流必须分开：OpenAI Responses 和 Anthropic Thinking 作为 `summary` 事件，OpenAI Chat/Gemini Thinking 作为 `content` 事件，均不能重复拼入 Assistant 正文。Provider State 只在 `apiFormat + baseUrl + modelId` 与当前请求完全匹配时重放；新 LangChain 快照使用版本 2，迁移期继续只读兼容 AI SDK 版本 1 的 `assistantMessage/openAiChatReasoningContent`，新写入不再产生旧格式。

取消 Run 时，已收到的 Assistant 流式文本以 `status=cancelled` 的消息保留；没有收到文本则不创建空的 Assistant Timeline。该消息同时进入模型历史，便于用户继续对话时保留已经看到的内容。

### 7.2 编辑最后一条已发送用户消息

Renderer 通过 `conversation.replace_latest_message` 提交 `ReplaceLatestConversationMessageInput`。该命令只接受非空文本和当前对话最后一条已发送用户消息的 ID，返回新 Run 的 `RunAccepted`。

边界约束：

- Main 必须重新校验消息归属和“最后一条用户消息”条件，不能信任 Renderer 是否正确隐藏编辑按钮。
- 正在运行的原 Run 必须先取消并完成资源清理；替换事务不能与模型、命令或文件 I/O 混在同一个 SQLite 事务中。
- SQLite 事务复用原 Timeline 消息 ID 和附件绑定，更新消息正文、Run ID 与时间，删除旧 Run 在该消息之后的 Timeline/Model Message，并使覆盖该消息的旧 Context Checkpoint 失效。
- 新 Run 记录、用户 Timeline 和模型消息必须在同一事务内建立；事务失败时保留旧消息与旧回答。
- 旧 Run 记录不删除，外部工具副作用不回滚。替换成功后 Renderer 以返回的用户消息更新 Timeline，并通过正常 Run 事件继续接收流式回答。
- 用户未显式选择新 `@对话/@文件` 引用时保留原消息的隐藏引用；显式选择时以新引用集合构造模型输入。

### 7.3 从 Assistant 最终回复创建分支

Renderer 通过 `conversation.fork` 提交 `ForkConversationInput`：

```ts
type ForkConversationInput = {
  conversationId: string;
  throughMessageId?: string;
};
```

- 不传 `throughMessageId` 时，供右侧菜单创建普通侧边聊天；该对话保留 `parentConversationId` 并只在右侧打开，不进入左侧对话树。父对话没有 Context Checkpoint 时复制全部模型消息；存在 Checkpoint 时复制该摘要、作为覆盖边界锚点的最后一条消息，以及边界之后未覆盖的消息。锚点只用于映射新对话 Checkpoint，不会再次发送给模型。
- 传入 `throughMessageId` 时，该 ID 必须属于源对话中某个 Run 的最终、已完成 Assistant Timeline 消息；Main 将它映射到对应 `model_messages.sequence`，把该序号及之前的模型消息物化复制到相同项目或临时分组中的同级普通对话。新对话 `parentConversationId = null`，不与源对话建立继承关系。
- 同级分叉标题按源对话当前标题递增为 `源标题 (1)`、`源标题 (2)`；编号在同一项目或临时分组中取已有同名前缀的最大值加一。
- 指定边界后的用户消息、Assistant 消息和工具调用/结果不能进入分支。边界内模型消息引用的附件复制元数据并重映射 ID，其他附件不复制。
- 只有覆盖序号不晚于分支边界的 Context Checkpoint 才能复制到新对话；覆盖到边界之后的摘要不得注入历史分支。
- 同级回复分叉复制截至边界的 `conversation_timeline`，包括用户消息、Assistant 回复、工具过程和 Agent 消息；所有 Timeline ID、Run ID、会话 ID 和附件 ID 必须重映射，使复制后的历史完全属于新对话。源对话和新对话后续独立写入。
- 右侧侧边聊天 Timeline 仍为空，只展示创建侧边聊天之后的新消息。
- Renderer 关闭右侧侧边聊天标签时，使用既有 `deleteConversation({ conversationId })` 删除该子对话；仅在删除成功后移除标签。删除失败时保留标签并在当前工作区显示错误，不能把它降级为“隐藏后可重新打开”的状态。
- Renderer 将普通侧边聊天的 `activeRunId`、运行终态和 `hasUnreadResult` 聚合到左侧父对话状态：任一侧边聊天运行时父项显示运行中；未确认的成功结果显示蓝色圆点，未确认的失败结果显示红色圆点。完成事件不能因父对话或侧边标签当前可见而自动确认；用户点击父对话，或在主对话、任一侧边聊天中点击、输入、发送或执行用户滚动时，Renderer 通过既有 `markConversationResultViewed` 逐项确认这一组普通对话。模型输出造成的自动滚动不能被视为用户确认。

## 8. 工具合同

### 8.1 ToolDefinition

```ts
type ToolDefinition = {
  name: string;
  description: string;
  inputSchema: JsonSchema;
  permission: "read" | "write" | "execute" | "network";
  timeoutMs: number;
  cancellable: boolean;
  resultPolicy: "inline" | "truncate" | "artifact";
};
```

### 8.2 ToolCall

```ts
type ToolCall = {
  id: string;
  sessionId: string;
  runId: string;
  name: string;
  arguments: unknown;
  workspaceId: string;
  status: "requested" | "waiting_approval" | "running" | "completed" | "failed" | "cancelled";
};
```

`workspaceId` 由 Runtime 根据 `sessionId` 解析，不能由模型指定。项目会话解析为项目根目录；临时对话可以没有 `workspaceId`，这不代表没有工具能力：`run_command` 使用按会话隔离的系统临时目录，`web_search` 和 Agent/任务/附件工具不依赖工作区。只有用户通过系统目录选择器显式附加目录后，临时对话才获得文件工具所需的工作区；文件工具参数统一使用相对于该根目录的 POSIX 路径。

### 8.3 ToolResult

```ts
type ToolResult = {
  toolCallId: string;
  status: "completed" | "failed" | "cancelled";
  summary: string;
  data?: unknown;
  artifactIds: string[];
  truncated: boolean;
  error?: AgentError;
};
```

- `summary` 是提供给模型和 UI 的有限结果。
- 完整长输出写入 Artifact，并明确 `truncated: true`。
- Tool Result 不能直接包含无法序列化的 Error、Stream、Buffer 或进程对象。
- `conversationToolItem.executionMode`（`parallel`/`serial`）记录 Runtime 对该调用作出的调度决定；字段可选以兼容历史 Timeline 行，不能被 Renderer 反向修改。
- `web_search` 是无需工作区的公共网络只读工具，使用内置免费 DuckDuckGo Provider；结果只包含有界的标题、摘要、域名和 URL，不提供网页交互能力，并受网络可用性和上游限流影响。
- `read_external_file` 只接受绝对路径，主进程在审批前只解析 canonical path、文件类型和大小，不读取正文；该工具即使在 `full_access` 下也必须逐次经过审批，临时对话同样可用。
- 同一项目中的 Agent 文件变更和 `run_command` 进入同一冲突协调边界；读目录、读文件、搜索和文件查找可由同一模型轮并发执行。模型一轮最多返回 32 个、且可以混合不同类型的 `toolCalls`；超过上限时整批在任何工具启动前以 `MODEL_RESPONSE_INVALID` 失败。Runtime 按 Tool Handler 的调度策略分组，只读并发窗口最多 8 个调用，非 `read_only` 模式下独立命令默认并行、每个窗口最多 4 个进程，`parallel=false` 可显式降级为串行；`ask_before_changes` 仍逐条审批，但已批准的独立命令可以重叠执行；结果按 `toolCallId` 关联，不按完成顺序改变消息顺序。文件变更在首个应用前保存每个调用的 `expectedContent`；后到的旧 Diff 在应用时返回 `FILE_CHANGED` 或项目冲突并作废，不允许覆盖先完成的变更，也不得自动重放。多个不同文件的审批/写入仍是逐文件的非原子批次。

## 9. 审批合同

```ts
type ApprovalRequest = {
  id: string;
  sessionId: string;
  runId: string;
  toolCallId: string;
  kind: "outside_workspace_read" | "file_write" | "apply_patch" | "command";
  title: string;
  details: ApprovalDetails;
  createdAt: string;
};

type ApprovalResolution = {
  approvalId: string;
  decision: "approved" | "rejected";
  scope: "once" | "session" | "agent";
  resolvedAt: string;
};
```

`scope=once` 只放行当前 Tool Call；`scope=session` 写入 Main 进程内按 conversation 维度的会话授权，应用重启后消失；`scope=agent` 写入当前会话绑定 Agent 的 `permissions.allow`。命令允许规则支持精确命令和末尾通配（例如 `mvn package *`），通配只按 token 边界匹配，不匹配 `mvnx`；文件规则按工具和项目相对路径匹配。未命中允许规则的副作用继续审批，当前不维护独立 deny 列表。

Subagent 继承父 Run 的权限模式，不继承父 conversation 的 `once` 或 `session` 授权。Renderer 通过子会话的活动 Run 和 `awaiting_approval` Tool 恢复父对话中的待审批投影；父、子入口都只提交既有的 `approved + scope + runId + toolId`，Main 仍按 Tool 所属 conversation 解析权限主体。过期或已处理的 Tool 审批返回 `APPROVAL_EXPIRED`，不得映射为 `FILE_CHANGED`。

工作区外文件读取是跨边界敏感操作，只支持 `once`，不能保存为会话或 Agent 永久允许；`read_only` 不会扩大写入权限，应用策略 `unavailable` 在 Main 端直接拒绝而不弹审批。

用户在编辑器中亲自点击保存属于直接用户操作，不走 Agent 审批；由模型发起的同一文件写入必须审批。两类操作在事件中使用不同 `actor` 标识。

## 10. 统一错误

```ts
type AgentError = {
  id: string;
  code: AgentErrorCode;
  message: string;
  retryable: boolean;
  details?: Record<string, unknown>;
};
```

第一阶段错误码至少包含：

```text
VALIDATION_FAILED
CAPABILITY_UNAVAILABLE
WORKSPACE_REQUIRED
PATH_OUTSIDE_WORKSPACE
FILE_CHANGED
APPROVAL_REJECTED
APPROVAL_EXPIRED
PROCESS_TIMEOUT
PROCESS_CANCELLED
PROCESS_FAILED
MODEL_AUTH_FAILED
MODEL_CONFIGURATION_INVALID
MODEL_RATE_LIMITED
MODEL_TIMEOUT
MODEL_PROVIDER_UNAVAILABLE
MODEL_RESPONSE_INVALID
NETWORK_UNAVAILABLE
STORAGE_FAILED
ARTIFACT_NOT_FOUND
PERMISSION_DENIED
CONFLICT
IPC_FAILED
INTERNAL_ERROR
```

错误返回用户可读 `message`，日志可以记录内部堆栈，但不能将 API Key、完整环境变量或敏感文件内容放入 `details`。

- `id` 是每次错误实例的 UUID，只用于关联 IPC、Run、工具结果和主进程日志；不拼接到用户可见错误文案。
- 主进程 IPC Handler 统一经过错误边界。错误通过可序列化 Envelope 传输，由 Preload 恢复为 `AgentClientError`；Renderer 不直接展示 Electron 原始异常。
- `run.finished` 保留兼容用的展示字符串，并通过 `agentError` 携带结构化错误；工具失败结果同样包含 `agentError`。
- 模型接口失败时，`details.status` 保存 HTTP 状态，`details.providerMessage` 只保存脱敏、截断后的供应商错误摘要；网络或内部异常可通过 `details.technicalMessage` 显示安全技术摘要。UI 显示这些有限详情，不展示完整响应体、HTML 网关页面或内部堆栈。
- API Key、Bearer Token 和可识别的 `sk-` 密钥在持久化、IPC、工具结果和日志前脱敏。
- 错误按归属渲染：模型请求错误作为 Assistant 时间线中的 md-king 风格静态引用块，工具错误留在对应工具行内，普通界面操作错误留在当前工作区操作区域；分类标题和脱敏后的 HTTP 状态、供应商摘要、网络/内部技术详情或工具输出直接显示。工具调用的原始参数和长结果仍由工具卡片自身控制展开。
- `model.request_retrying` 可携带脱敏 `reason`，用于显示“正在重新连接”的可折叠详情；重试结束后不再额外创建无归属的悬浮错误卡片。
- Renderer 渲染异常由 React Error Boundary 接管；主进程记录未捕获异常、未处理 Promise、Preload 失败和 Renderer 退出。Renderer 异常退出只自动恢复一次，避免重载循环。

第一阶段 SQLite 是主数据源，至少包含：

```text

team_projects
work_items

task_dependencies
agent_profiles
agent_instances
agent_threads
delegations
agent_messages
task_leases
sessions
runs

content_blocks
events
tool_calls
approvals

model_providers

conversation_attachments
conversation_deletion_tasks
mcp_servers
mcp_capabilities
skills
agent_skills

```

关键约束：

- 所有 ID 使用应用生成的 UUID。
- 时间统一存 UTC 毫秒或 ISO 字符串，数据库内保持一种格式。
- `events(session_id, sequence)` 建立唯一索引。
- `runs`、`messages`、`tool_calls` 保存当前可查询状态，`events` 保存追加式过程。
- 当前状态与对应事件在同一事务中提交。
- `model_profiles` 只保存非敏感配置和密钥引用，不保存 API Key。
- `model_providers` 保存 Adapter 类型、端点和凭据引用；同名模型通过 `provider_id + model_id` 唯一识别。
- 当前模型配置文件同时保存全局默认模型、最近一次用户手动选择，以及每个模型的 `connectionStatus`、`connectionStatusUpdatedAt`、`lastSuccessfulAt`。它是配置与健康事实源；Renderer/Zustand 不复制第二份可写目录。
- `conversations` 保存当前 `provider_id + model_id + reasoning` 选择快照。新普通对话由 Main 按“最近用户选择 -> 默认模型”解析；侧边对话和 Subagent 创建时复制父 Conversation，之后可独立更新。
- Renderer 切换 Conversation、切换侧边标签或折叠/展开右侧工作区时，必须从目标 Conversation 的选择快照恢复控件；全局最近选择和默认模型只参与新 Conversation 初始化或缺失快照的兼容兜底，不能覆盖已有快照。
- Renderer 可保活一小时内访问过的 Conversation 页面，并在当前应用生命周期内至少保留最近三个页面。该缓存只持有展示实例和只读模型状态快照；归档、删除、项目移除或超时淘汰后重新通过 `AgentClient` 从持久化事实加载，不能把缓存写成第二份业务事实源。多个保活页面共享一个底层 `conversation.run_event` 订阅，再按 `conversationId` 分发。
- `conversation.set_model_selection` 只接受已配置的 Provider、模型和已启用思考选项。普通/侧边 Conversation 的用户更新同时刷新最近选择；`subagent` 和受管 Team WorkItem 执行树 Conversation 都不刷新该全局偏好。受管 Team Conversation 的模型/思考更新必须在同一事务中写入当前 Conversation 展示快照和其 WorkItem 的后续 Run 策略；当前 Run 的 `run_model_snapshots` 不可修改。它仍拒绝改项目，且正在运行时的用户输入只能作为同一 Run 的 `steer`。
- `run_model_snapshots` 保存实际模型、选择来源和能力快照，创建后不可修改。
- MCP、Skill 配置按应用、Team、Project 或 Agent 范围启用；它们不能扩张 Task 的项目权限。
- Artifact 大内容不保存为 SQLite BLOB。
- 每个 `tasks.project_id` 必填；跨项目 WorkItem 通过多个 Task 表达，不允许一个 Task 绑定多个项目。
- `task_dependencies(task_id, depends_on_task_id)` 建立唯一约束并禁止自依赖。
- 一个 Task 同时最多有一个未过期的 `task_lease`，领取和续租使用事务。
- Team Lead、Agent Thread 和任务调度事件进入同一事件体系，运行状态不能只保存在内存 Store；这里的 Agent Thread 是逻辑对话归属，不对应 OS 线程或进程。

### 11.1 Artifact

```ts
type ArtifactRecord = {
  id: string;
  sessionId: string;
  runId?: string;
  kind: "terminal_log" | "diff" | "browser_snapshot" | "screenshot" | "tool_output";
  relativePath: string;
  mimeType: string;
  byteSize: number;
  sha256: string;
  createdAt: string;
};
```

Artifact 必须位于应用数据目录，数据库只保存相对路径。读取时重新解析绝对路径并确认仍位于 Artifact 根目录，防止路径注入。

### 11.2 ConversationAttachment

```ts
type ConversationAttachment = {
  id: string;
  conversationId: string;
  messageId: string | null;
  source: "project" | "upload";
  kind: "file" | "image";
  name: string;
  mimeType: string;
  sizeBytes: number;
  projectPath: string | null;
  contextTokens: number;
  truncated: boolean;
  createdAt: string;
};
```

- 文件选择完成后立即复制到 `userData/conversation-files/<conversationId>/` 并创建 `messageId = null` 的持久草稿。发送消息时，创建 Run、用户消息、模型消息和附件绑定在同一 SQLite 事务内提交。
- SQLite 的 `conversation_attachments` 保存公开元数据、受管文件路径和可选提取文本路径；`model_messages.attachment_ids_json` 保存有序附件 ID。Renderer 只能获得公开元数据，不能获得受管绝对路径或图片 Base64。
- 项目内文件和项目外上传文件都保存不可变快照。`source` 和 `projectPath` 只描述快照来源，不改变模型处理方式；项目中未显式添加的文件继续通过工作区工具读取实时内容。
- 文本、常见代码、PDF 和 DOCX 在 Main 进程提取为 UTF-8 文本。超过 48,000 字符时只注入头 36,000 和尾 12,000 字符，全文由只读工具 `read_attachment(attachment_id, offset, limit)` 分段读取。
- PNG、JPEG、GIF 和 WebP 不写入 SQLite 或模型消息 JSON；只在实际构造模型请求时读取快照并编码。OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini Adapter 分别转换为各自的多模态内容块。
- 每条消息最多 10 个附件，单个附件最多 25 MB。草稿可移除；已发送附件不可从消息中单独删除。
- 创建分叉时形成不可变上下文快照：右侧侧边入口在无 Checkpoint 时复制全部 `model_messages`，有 Checkpoint 时只复制覆盖边界锚点和未覆盖消息并映射摘要；回复分叉入口只复制指定最终 Assistant 回复及之前的消息。仅当最新 `conversation_context_checkpoints` 未覆盖到回复分叉边界之后时才复制摘要，并把 `covered_through_sequence` 映射到新对话消息序号。
- 回复分叉使用普通 `agent` 身份、`parentConversationId = null` 并复制源对话当时的 Agent 配置；右侧侧边聊天使用普通 `agent` 身份和源对话 `parentConversationId`；任务 Subagent 使用 `subagent` 身份并必须有对应任务生命周期记录。
- 回复 Fork 将边界内的可见 Timeline 写入同级新对话，Renderer 立即显示分叉前历史；右侧侧边聊天仍不复制 Timeline。源对话后续消息不自动同步。分叉只复制快照内模型消息实际引用的附件元数据，并同时重映射附件 ID、附件所属消息 ID 和 Timeline ID；底层不可变文件快照可以共享。
- 清理文件前必须查询 SQLite 引用；删除父对话、子对话或归档到期都不能删掉仍被其他对话引用的快照。
- 删除会话时先在一个 SQLite 事务中创建 `conversation_deletion_tasks`，保存根会话、整棵会话树、受管文件路径、状态、重试次数和最后错误，同时把相关会话标记为 `deletion_pending`。待删会话不再出现在列表、Agent 发现或临时工作区恢复中。
- `conversation_deletion_tasks` 不使用指向 `conversations` 的级联外键，确保进程退出、文件占用或数据库收尾失败时恢复事实仍然存在。任务可以处于 `pending`、`running` 或 `failed`，启动和每日归档清理都会重试未完成任务。
- 文件清理只删除任务记录的受管路径。判断共享引用时忽略待删会话，但保留任何正常会话仍引用的快照；`ENOENT` 按已完成处理。会话树对应的 ThreadLog JSONL 同样在任务内删除，缺失按已完成处理；文件完成后，删除会话树和任务记录在同一个 SQLite 事务内提交。
- 会话删除任务在文件清理成功后还会删除对应 Run 的 LangGraph Checkpoint thread；Checkpoint 数据库暂时独立于业务库，删除失败会让原清理任务保持 `failed` 并在启动/定时任务中重试，不能只删除业务会话行。
- 手动删除和归档 30 天到期删除必须调用同一个会话删除 Use Case，不能直接执行 `DELETE FROM conversations` 后再补删文件。

## 12. 模型上下文合同

`ContextBuilder` 的输出由以下部分组成：

```ts
type ModelContext = {
  systemInstructions: string;
  workspaceContext: WorkspaceContext;
  conversationSummary?: StructuredSummary;
  recentMessages: ModelMessage[];
  relevantArtifacts: ArtifactExcerpt[];
  availableTools: ModelToolDefinition[];
  estimatedInputTokens: number;
  estimatedAttachmentTokens: number;
  inputBudget: number;
};
```

`getConversationContextUsage` 除总输入、压缩阈值和输出预留外，还返回 Skill 目录、活动任务清单和 Skill 正文预留的独立 Token 估算。Renderer 用这些字段区分“实际输入”和“预留容量”；Skill 正文预留不能计入已使用输入，工具 Schema 仍属于实际发送的系统能力上下文。当前 MCP Runtime 尚未实现，因此不存在可发送的 MCP Tool Schema。

- Skill 目录摘要作为系统上下文的一部分发送；模型调用 `load_skill` 后，`SKILL.md` 正文由 Runtime 临时注入下一轮模型请求，不新增聊天 Timeline/用户消息。Graph State 只保存 Skill 的 `id/version/contentHash`，恢复或压缩后重新读取正文并校验哈希；内容变化时 Run 失败并要求重新加载。Agent 为 `custom` 能力范围时，其 `skillIds` 同时约束目录、加载、reference 和恢复注入；`inherit_all` 才继承全部满足作用域的已启用 Skill。
- `read_skill_reference` 的 `path` 必须是已激活 Skill 下 `references/` 或 `templates/` 的相对路径。Main 端拒绝绝对路径、`..`、符号链接、NUL、非法 UTF-8 和超大文件，并在读取前执行字节上限检查；Skill 文档不能扩大权限或绕过审批。`team` 作用域只在带 `teamId` 的团队会话生效。
- LangGraph Checkpoint 的 `thread_id` 使用应用生成的 Run ID。应用重启只自动恢复尚未进入模型/工具节点的 `queued` Run；已经处于 `running` 的 Run 按可能发生外部副作用处理为失败，不自动重放。恢复不会创建重复用户消息。

- 当前 Run、未完成审批和明确用户约束不可被摘要替代。
- 当前 active 任务清单是独立的动态系统块。每项包含 `title`、`status` 和可选 `reason`；`reason` 仅用于 `blocked`、`failed` 的简短、可展示解释，最长 600 字符。已有不含 `reason` 的持久化清单读取为 `null`，以保持兼容。
- Tool Schema、输出预留、安全余量和 Skill 正文保留预算先从模型窗口中扣除。启用 Skill Runtime 时，ContextManager 预留 `max(1024, min(12000, floor(effectiveContextWindow * 0.12)))` Token；没有模型窗口时按 48,000 Token 计算。Skill 正文实际注入和用量估算使用同一预算，正文仍不进入 Timeline。
- 模型窗口、最大输出和输出预留来自本次 Run 的 Model Profile 快照；用户修改配置只影响后续模型调用。
- 旧工具输出先裁剪或 Artifact 化，再摘要对话。
- 文本附件按实际注入的标题和预览估算 Token；图片按文件大小在 1,024 至 8,192 Token 之间保守估算并计入图片说明。Provider 返回精确用量后可用于校准，但不能依赖所有厂商都返回图片 Token。
- 压缩顺序是先裁剪旧工具输出，再摘要较早完整轮次，最近两轮尽量原样保留。进入摘要的附件保留附件 ID、名称、类型、来源、项目相对路径、读取状态和截断状态，不把图片 Base64 放进摘要。
- 发送前计算本轮最低预算。如果本轮内容自身仍超过压缩阈值，不创建 Run、不绑定草稿附件，并向对话区返回可操作错误；用户可减少附件或调整模型上下文/压缩阈值后重试。
- 摘要写入 `summaries` 并记录覆盖的起止 `sequence`。
- 摘要失败不能删除原始消息；可以缩小本轮上下文或向用户报告阻塞。

## 13. 密钥与配置

- `protocol_adapters` 表示已安装的对话协议实现；`provider_endpoints` 保存用户选择的协议 Adapter、Base URL、可选请求路径和凭据引用。
- `model_profiles` 保存模型 ID、别名、角色、能力、上下文窗口、输入/输出上限和配置来源。
- API Key 由 Electron Main 使用 `safeStorage` 加密后写入独立凭据文件。
- Preload 不提供读取明文 Key 的接口，只提供保存、删除和连接测试命令。
- Renderer 提交新 Key 后，Main 完成加密并立即清理可控内存引用。
- 日志序列化器对 `authorization`、`apiKey`、`token` 和常见密钥格式做统一脱敏。
- MCP Token、敏感环境变量和远程授权凭据使用同一凭据引用机制，不写入 Server JSON 或 SQLite。
- Agent 的模型继承、固定、自动选择和用户动态修改规则以[模型接入、MCP、Skill 与 Agent 对话设计](./08-模型接入、MCP、Skill与Agent对话设计.md)为准。
- Agent 管理数据根目录由 Main 解析：优先绝对路径环境变量 `AGENT_HOME`，否则为 `<os.homedir()>/.agent`；首次迁移仅复制既有 `userData` 下的 Agent 数据，不移动或删除旧数据。Renderer 不接收管理目录绝对路径，也不能直接读取凭据、数据库或 JSONL。
- 当前 `ThreadLog v1` 位于 `<AGENT_HOME>/conversations/<conversationId>.jsonl`。仅创建普通空 Conversation 时不创建文件；首次模型可见输入、Subagent 的首个任务输入，或有模型消息/Run/Timeline/Checkpoint 的旧 Conversation 迁移时才创建。空侧边分支为了恢复父子关系仍保留极小关系日志；侧边聊天的 JSONL 属于临时会话数据，关闭标签触发可恢复删除任务并一并移除。已迁移的普通 Run、Queue / Steer、工具、Checkpoint 和终态会先追加 JSONL，再由 `EventProjector` 幂等物化 SQLite；SQLite 仍承担列表、Timeline、Run、FTS 和跨对话关系查询。`ContextCompiler` 在存在且可读取的日志时从其重放模型消息与 Checkpoint；若运行中遇到不可读日志，当前请求安全降级到 SQLite 历史，启动时会把原文件改名为 `.corrupt-*` 保留、清空其派生投影游标，并由 SQLite 快照重建新的 JSONL。Renderer 不能直接扫描 JSONL，仍只能经过 IPC 查询 SQLite 投影。附件引用只记录公开元数据，由 Main 的 `AttachmentStore` 解析受管路径，绝对路径和二进制不会进入 IPC 或日志。`EventProjector` 投影合同独立版本化。

## 14. 版本与兼容

- 所有持久事件和跨进程 Envelope 包含 `schemaVersion`。
- SQLite 使用只向前执行的版本化 Migration。
- Preload API 暴露 `apiVersion`，Web UI 启动时检查兼容性。
- 不在第一阶段支持任意旧版数据库；开发期结构变更通过 Migration 或明确重建测试数据库。
- 会话导出格式与内部数据库 Schema 分开版本化，避免数据库调整破坏导入导出。

关键约束：

- 所有团队事件包含 `teamId`；任务事件同时包含 `workItemId`、`taskId` 和 `projectId`。
- `TaskListView` 是 `tasks`、依赖和事件的查询投影，不单独维护另一份 Todo 状态。
- AI 创建或修改任务列表时递增 `revision` 并保存理由；已完成 Task 重新打开必须产生显式事件并保留原完成证据。
- 创建 Task 不触发 Agent 创建；是否委派由 TeamSupervisor 独立决策。
- `routing.decided` 保存候选集合、过滤原因、选中 Agent 和简短分配理由。
- Agent 间消息的 `actor` 不能是 `user`，也不能携带用户审批凭据。
- Agent 结果通过结构化摘要和 Artifact 引用回传，不复制整个子会话。
- 同一 Team 的事件需要团队级单调序号；单 Session 事件序号继续保留，用于局部恢复和渲染。
- 自动扩容达到并发、实例、时间或 Token 上限时发送事件并排队，不通过重试绕过限制。

当前第一条生产竖切已经实现 `team.work_item.list/get_execution/submit/update/update_permission/request_rework/accept`，以及模型可见的 `submit_team_work_item`。后者只能在同一项目、未归档且未受管的主 Conversation 中出现；模型只有在用户 `@团队` 或明确要求交办时才应调用它，参数中的 `teamId` 必须来自当前运行时团队目录。工具将当前 Conversation ID、当前模型/推理强度和权限模式冻结并传给 `submit`；`submit` 再持久化可选 `sourceConversationId`，Main 验证来源和项目一致。Renderer 的团队看板不创建 WorkItem，输入框也没有直投下拉。同一 `sourceConversationId + teamId` 复用一个项目绑定的 `team_lead` 执行 Conversation，并在其下保留配置成员的 `agent` Conversation；每个 WorkItem 独立审计、验收并在该执行根上串行调度。模型/工具循环仍由现有 AgentRuntime 执行，Team Lead 只可用持久 `send_agent_message` / `wait_for_agent_message` 协作，不能为团队成员调用 `spawn_subagent`。暂停团队允许提交但不启动 Run；应用设置将团队恢复启用后重新检查队列。`update` 只接受尚未被 Team Lead 领取的 `queued` WorkItem，在同一事务更新标题和需求并追加审计事件；`update_permission` 可用于任何未终态 WorkItem，原子更新其后续 Run 策略并追加审计事件，当前 Run 与已经展示的审批保持创建时的不可变快照。Conversation 的活动任务清单直接作为 WorkItem 任务投影。根 Run 结束后，只有持久成员没有排队或运行中的 Run，且 Team Lead 已消费已送达的成员结果，WorkItem 才进入 `waiting_user`；否则保持 `running` 并等待自动汇总 Run。自动汇总始终复用提交时冻结的模型和推理强度，以及当时 WorkItem 已保存的权限模式；配置不能恢复时将 WorkItem 标记为阻塞，不能静默回退到全局默认模型；已进入终态的 WorkItem 也不能被迟到消息重新启动。用户返工会在同一 Conversation 创建新 Run；`accept` 必须提交并覆盖全部验收条件，验收事实与完成状态一起持久化。Git 提交、PR 和合并尚未纳入 `accept`，Renderer 当前只能确认完成，不能伪造未执行的收尾动作。

`team.work_item.get_execution` 是按一个 WorkItem 读取的只读执行谱系接口：根节点为该 WorkItem 绑定的持久 Team Lead Conversation，成员来自 `team_member_conversations` 关系；每一次由持久 Agent 消息触发的成员任务保存在 `team_work_item_member_assignments`。返回每个实际参与者的 Conversation 快照、持久化 Agent 身份快照、最近任务分派状态和深度。普通侧边对话虽然也可能有 Conversation 父子关系，但没有 Team 成员关系或分派事实，绝不能被列作团队执行成员；该接口不创建第二份成员状态或缓存。根 Conversation 会在首个 Run 入队前绑定到 WorkItem；应用重启时，进行中的 WorkItem 会阻塞，绝不自动重放文件、命令或网络副作用。

**团队页与对话树的 Renderer 合同**：团队页只显示 WorkItem 的需求、阶段、任务、验收/返工动作，以及实际成员和团队状态；不得在中间区域嵌入成员的 Timeline、工具卡或第二份聊天页面。同一来源主 Conversation 下复用一个 `team_lead` Conversation，持久成员显示为其下的协作层级；左侧项目导航把该对话关系展平。团队页或左侧成员点击必须保持来源主 Conversation 为中间主面板，并在右侧打开对应成员的完整 Tab：该 Tab 必须保留输入框、待发送消息、停止和审批操作。`conversation.send_message` 收到受管执行谱系 Conversation 时，Main 不会走普通新 Run 路径，而是经 `TeamWorkItemRuntime` 验证当前 WorkItem/Run 后以 `deliveryMode = steer` 投递，忽略 Renderer 提供的 Agent、模型和推理；权限由持久化 WorkItem 策略决定，当前 Run 使用其启动快照，后续 Run 才会读取用户更新后的权限。成员不在运行时拒绝发送，提示从 WorkItem 的返工/验收动作继续。Run 终止时 Main 将所有遗留 `awaiting_approval` Tool 行持久化为 `cancelled`，Renderer 不显示审批按钮。团队成员不能替换主对话或移除主输入框。〔FACT｜`apps/desktop/src/main/teams/team-work-item-runtime.ts`；`apps/desktop/src/main/agent/agent-runtime.ts`；`apps/desktop/src/main/ipc/register-main-ipc.ts`；`apps/web/src/features/projects/project-navigator.tsx`；`apps/web/src/features/workspace/right-sidebar-workspace.tsx`〕
