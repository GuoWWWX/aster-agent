# 开工准备与首批任务清单

> 文档状态：首批工程骨架、项目会话导航与文件树已完成  
> 更新时间：2026-08-15

## 1. 结论

产品目标、MVP 边界、技术选型、模块关系、接口方向、数据存储和迁移顺序已经足够支撑开工。现在不需要继续编写泛化架构文档，也不需要先设计插件市场、完整 Web Server 或远程执行体系。

首个代码批次只验证三件事：

1. pnpm Monorepo 的基础结构能够稳定构建。
2. `md-king` 的应用外壳能以最小闭包迁入新的 React UI。
3. 同一 React UI 能在普通浏览器和安全配置的 Electron 中运行。

模型、SQLite、Shell、完整编辑器、Agent Loop 和多 Agent 调度都不进入本批次。

### 1.1 本次实施记录

已完成：

- Git `main`、pnpm workspace、严格 TypeScript、ESLint 和根级质量门禁。
- `packages/protocol` 的能力、运行时、窗口状态、集中 IPC 和 Zod Schema。
- `apps/web` 的 Mock `AgentClient`、AppShell、标题栏、活动栏与最小三栏工作台。
- `apps/desktop` 的 Electron Main、Preload、来源校验、窗口控制和安全策略。
- Web 与 Electron 的实际启动验证；Electron Renderer 无 `process`、`require`，仅暴露受控 Bridge。

验证命令：`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 均已通过。浏览器在 `1024 x 680` 视口完成 light/dark 和面板收起验证；Electron 实测最大化与还原 IPC。

### 1.2 交付前复审记录

- 修复 `320 x 568` 窄屏标题栏横向溢出：品牌文字在该断点收起，窗口与面板控制仍完整可用。
- Electron 仅允许预期页面导航；重定向与无法解析的 URL 同样拒绝，权限请求、权限查询和 WebView 均默认禁止。
- Electron 最小窗口高度与 `AppShell` 的 `680px` 布局下限已统一；开发服务器固定为本机 `127.0.0.1:5173`，端口冲突会明确失败而不会连接到其他服务。
- 浏览器已验证 `320 x 568`、`1280 x 800`、`1440 x 900` 的无横向溢出状态，以及窄屏面板和 light/dark 切换；控制台没有运行时错误。
- 新构建的 Electron 生产态已确认加载 `apps/web/dist/index.html`。本轮复审后再次通过 `pnpm lint`、`pnpm typecheck`、`pnpm test` 和 `pnpm build`。

### 1.3 项目会话导航与文件树增量

布局职责参照 Codex / Cos X：左侧管理项目和会话，右侧只显示当前项目的真实文件。没有复制 `md-king` 的 Vault 业务状态：

- 桌面端通过系统目录选择器添加项目；左侧每个项目是一个会话分组，不是文件树。
- 用户可在当前项目下新建和切换会话；这一批会话仅保存在 React 内存中，Agent Runtime 与 SQLite 接入后替换为真实会话仓储。
- 右侧目录按展开动作读取；根目录和每个子目录最多显示 1000 项，目录优先排序。
- Renderer 只能传递已登记的项目 ID 与相对路径；Electron Main 对项目根、路径穿越和真实路径越界进行校验。
- 浏览器 Mock 仅展示固定夹具，不访问用户本机文件；项目添加按钮明确只在桌面端可用。
- 当前项目注册表只保存在 Electron 进程内。SQLite 持久化、文件打开、写入、重命名、删除和拖拽不属于这一小批次。

## 2. 明确假设

- 目标仓库初始化分支使用 `main`。
- 提交标题采用现有项目风格：`feat:`、`fix:`、`docs:` 等类型前缀，后接中文说明。
- 首批开发只面向 Windows，代码边界不主动阻断后续 macOS/Linux 支持。
- `apps/web` 是唯一 React UI；Electron 不维护第二套页面。
- 浏览器开发模式使用 `MockAgentClient`，不会访问本机文件或伪造系统操作成功。
- 原 `md-king` 仓库只作为迁移来源，本项目的实现过程不修改它。

如果后续改变其中任一项，应先更新本清单和对应架构文档，再调整代码。

## 3. md-king 迁移基线

当前检查结果：

```text

```

因此迁移源不能只使用 `HEAD` 内容。默认以**开始迁移时源目录中的实际工作区文件**为准，原因是未提交内容包含近期完成的 UI、编辑和渲染改动。

执行规则：

1. 开始复制前再次记录分支、HEAD 和 `git status --short`。
2. 只复制首批 UI 所需的最小文件闭包，不复制整个仓库。
3. 对实际复制的源文件记录源路径和 SHA-256，作为迁移追溯清单。
4. 不在源仓库整理、暂存、提交或回退任何现有改动。
5. 若迁移期间源文件继续变化，以清单中的哈希为本批次基线，不静默混入后续变化。

## 4. 首批目标目录

首批完成后只要求形成以下结构：

```text
Agent/
├─ apps/
│  ├─ web/                  # React/Vite UI 与 MockAgentClient
│  └─ desktop/              # Electron Main、Preload 和桌面启动入口
├─ packages/
│  └─ protocol/             # 首批只放宿主能力与最小 IPC 类型
├─ doc/
├─ package.json
├─ pnpm-workspace.yaml
├─ pnpm-lock.yaml
├─ tsconfig.base.json
├─ .gitignore
├─ .npmrc                   # Electron 官方二进制镜像配置
└─ .node-version
```

不创建 `agent-core`、`storage`、`local-tools` 和 `browser-runtime` 空目录；到对应代码批次再建立。

## 5. 首批任务与验证

1. 初始化 Git、根 pnpm workspace、TypeScript、ESLint 和 EditorConfig 基础配置。  
   **验证：** `git branch --show-current` 为 `main`，`pnpm install` 成功，根脚本能发现三个 workspace；构造一次违规跨层 import 时 `pnpm lint` 能阻止。

2. 创建最小 `apps/web`，建立 `AgentClient`、`MockAgentClient` 和 capability 查询。  
   **验证：** Vite 浏览器页面能启动；Mock 明确返回不支持本机文件、Shell 和窗口控制。

3. 按[界面迁移与设计系统规范](./07-界面迁移与设计系统规范.md)提取 `md-king` 的语义 Token，并重新实现 AppShell、标题栏、活动栏和最小面板布局。  
   **验证：** 与源项目使用相同视口和主题截图对比；布局、主题切换和面板收起没有明显退化；目标组件不含 Tauri 和旧业务状态。

4. 创建最小 `apps/desktop`，通过 Preload 暴露版本、capability 和窗口控制。  
   **验证：** Electron 加载同一 `apps/web`；启用 `contextIsolation`、关闭 `nodeIntegration`，Renderer 不能直接调用 Node API。

5. 建立根级 Lint、类型检查、测试和构建命令。  
   **验证：** `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。

6. 做浏览器与 Electron 启动冒烟。  
   **验证：** 普通浏览器无 Electron 全局对象时不报错；Electron 窗口按钮通过 Preload 生效；控制台无未处理异常。

## 6. 首批 UI 边界

首屏沿用 `md-king` 桌面工作台，不在首批设计完整 Agent 页面：

```text
标题栏：应用标题、主题和 Electron 窗口控制
活动栏：保留现有视觉，提供 Agent 入口占位
左侧栏：项目分组、会话列表与新建会话
中央区：当前项目会话；未创建时显示新建会话入口
右侧区：当前项目的只读文件树与文件筛选
```

文件树只用于证明受控工作区读取；不提前实现文件打开、写入、Diff、终端、浏览器或完整 Markdown 编辑器。项目与会话的真实持久化在 SQLite 批次实现。

## 7. 完成定义

首批代码只有同时满足以下条件才算完成：

- 浏览器和 Electron 使用同一个 `apps/web` 构建产物。
- Renderer 没有 `@tauri-apps/*` import，也不能直接访问 Node.js。
- `AgentClient` 是 UI 获取宿主能力的唯一入口。
- 迁移代码保留 `md-king` 视觉和交互，不进行无关重构或主要依赖升级。
- UI 外壳按新分层实现，没有复制完整 `index.css`、巨型页面或散落宿主判断。
- 代码遵守[前后端模块与编码规范](./06-前后端模块与编码规范.md)，模块依赖由 ESLint 自动检查。
- 根级类型检查、测试和构建通过。
- 浏览器和 Electron 截图验证完成，页面无明显错位、溢出或空白。
- 迁移源清单完整，原 `md-king` 工作区未被修改。
- pnpm 对安装脚本仅显式允许 `electron` 和 `esbuild`；Electron 使用项目级官方镜像配置，不依赖机器环境中的镜像变量。
- 本批次不包含模型、数据库、Shell 或后续空模块。
- 本批次不实现 Team、WorkItem、Task 或 Subagent，只为后续协议保留类型演进空间。
