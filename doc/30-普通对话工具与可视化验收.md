# 普通对话工具与可视化验收

## 简单规范

1. 常用操作直接给出短说明和强类型参数；复杂操作先给用途与关键限制，详细流程按需加载 Skill。同一会话已读且未变的说明、文件和结果不重复读取。
2. 先理解本轮意图与可观察验收条件，再执行；关键发现或验证节点简短说明。只在状态实际改变时更新任务／执行清单，不为了流程增加步骤。
3. 命令回执不是结束：沿同一 commandId 和增量偏移读到退出状态；后台服务只检查就绪，不重复启动。独立操作在原执行器支持的范围内批量执行，共享文件修改及审批仍有序。
4. 可视化结果要检查实际像素及必要交互。动画至少检查同一版本的两个相位、接触点和联动关系；修复后只重验受影响部分。最终只交付一个预览或原文件引用。
5. 工具失败按结构化错误修正参数、来源或环境，不能原样重复失败调用，也不能把未验证说成通过。

Windows PowerShell 的原生命令参数转发可能丢失 node -e／解释器 -c 中的嵌套引号；复杂脚本优先使用字面量 here-string 管道到解释器标准输入或已有脚本文件。真实快速排序验收曾复现该问题，不能把一次恢复成功算作无失败调用。

## 工具划分

〔FACT｜AgentRuntime 注册表、agent-tool-scope.ts、prompt-assets.ts〕普通项目对话基线提供 42 个工具；其他身份继续复用既有身份过滤、Schema、Handler、审批和执行核心，不把全部工具开放给所有身份。

| 范围 | 入口 | 提供方式与理由 |
| --- | --- | --- |
| 文件、检索 | read_file、write_file、replace_in_file、apply_patch、delete_file、find_files、search_text、read_external_file | 常用且操作短，直接保留参数、范围和冲突说明。读／改／删权限及结果不同，不合成不透明的总入口 |
| 有限命令与运行状态 | run_command、read_command_output、list_background_commands、stop_command、list_project_operations、wait_for_project_operation | 直接保留类型化合同；默认值自动处理，无需重复确认或重启命令 |
| 交互终端 | terminal_control | 已有 action 枚举复用 create/list/write/read/close。直接给用途、ID 和 SSH 安全边界；细节用 terminal-use。模型参数不再暴露 columns、rows、yieldTimeMs；旧运行时输入仍兼容 |
| 浏览器、桌面 | browser_control、computer_use | 沿现有动作枚举和权限。browser-use 按需提供 DOM 引用、坐标、交互流程；首层保留 observe 已含截图、后台优先和资源归属，避免重复截图或盲点 |
| 附件 | read_attachment、view_attachments | 元数据与真实视觉输入分开；图片查看细节复用 image-view，已有像素不重复加载 |
| 检索、可视化交付 | web_search、present_html | 搜索合同直接给出；present_html 用 action=inspect/present 复用同一来源和沙箱，ui-verification 提供质量与动画验收流程 |
| Skill | load_skill、read_skill_reference | 目录仅名称、描述和引用，完整正文按需加载；补充 terminal-use、ui-verification，保留 browser-use/image-view/code-review/debugging |
| 持久任务列表 | list_task_contexts、get_task_context、update_task_context、link_task_context | 直接保留来源、修订号和完成权限；沿现有一个更新入口，不另加第二轮“确认完成”调用 |
| 局部执行清单 | update_task_list、close_task_list | 与持久目标分开，低频更新；简单问答无需创建 |
| Agent 协作 | list_models、list_agent_conversations、read_agent_conversation、send_agent_message、wait_for_agent_message、spawn_subagent、list_subagents、wait_for_subagents、end_subagent | 普通对话可按需委派。已有数组收件人复用；消息、派生和生命周期权限不同，不强行合并。只取有界证据，不重做子代理成果 |
| 受管任务 | get_team_work_item_status、submit_team_work_item | 沿原任务生命周期与身份范围，不用普通执行清单替代验收 |

参数少的目标是减少模型不必要的选择，不是移除校验或把所有参数变成自由文本。独立动作有不同权限／取消／恢复语义时保留原入口。没有引入第二套工具执行循环、动态插件框架或新的上下文数据库。

## 提示词和缓存

〔FACT｜base-system.md、prompt-assets.ts〕基础规则改为简短英语，用户回复仍默认简体中文；按实际工具过滤不适用段落。群聊专属段落保持原文，群聊功能不在本轮重做。浏览器和终端的细节只在激活 Skill 后进入上下文。关键权限、冲突恢复、真实来源和命令终态不能只藏在说明文档里。

参考测量采用 js-tiktoken o200k_base，不代表所有模型的真实计费分词器。四组等义短规则英语为 28/35/27/30 Token，中文为 32/39/33/36；据此选择本项目的精简英语规则，不推导“英语在任何模型都更省”。规范化后的普通对话核心提示由 4,226 降到 1,804 Token；完整请求还含工具、项目规则、Skill 目录和历史，应以实际 Provider 用量为准。

〔FACT｜2026-10-19 普通对话基线实测〕local gpt-6.1-sol、中等思考的两轮短问答：第一轮 input=22,759、cached=0，第二轮 input=22,783、cached=22,656，暖请求约 99.4%。两轮均无工具调用。缓存保存稳定前缀，不是把相似问题的答案缓存下来；第一轮、模型／工具／配置变化和压缩后重新形成前缀时可能较低。本轮不改缓存计数、不承诺命中率，也不通过额外请求填充缓存。

## 组件预览与截图合同

〔FACT｜protocol/html-preview.ts、HtmlPreviewServer、compilePreviewSource〕完整闭合的 html/htm、react/jsx/tsx、vue 围栏复用 HtmlPreviewCard／Scope 的预览、源码、复制与侧边浏览器入口。流式未闭合代码仍按源码显示。React 支持默认导出组件或裸 JSX；Vue 支持 template、script/script setup、TypeScript 和 CSS/scoped。本地编译并内联运行库，不依赖 CDN 或自动安装依赖。

片段只允许内置 React／Vue 运行库导入。项目相对导入、Node 模块、远程模块、Vue 外部 src、自定义块及样式预处理器需要真实项目环境；不能自动转成静态假页面掩盖编译失败。现有相对 HTML 文件交付不变，React/Vue 项目文件不是一个通用项目构建器。

`present_html` 保留原工具名及旧 path/pages 输入，新增：

```json
{"action":"inspect","language":"react","code":"export default function App(){return <button>示例</button>}","width":1280,"height":800,"frames":1}
```

- action=inspect：使用原隔离预览服务和后台受管浏览器，返回文本观察及 1–3 张模型可读图片，不创建最终交付卡。动画可设 frames 和 intervalMs，同一页面取样。可选 actions 数组复用受管浏览器的 click(x,y)／key(key)；仅 12 步以内，坐标须在视口内，键仅常规交互键，不接受脚本／快捷键修饰符。每次检查从初始状态开始，执行动作后观察实际状态，不假定动作必然成功。
- 结束、失败或取消均释放浏览器及预览引用，不返回已失效 URL、browserId 或 DOM elementId，避免模型再打开已关闭的临时页面。isolated 模式保留作者配色；隐藏窗口发生交互后，先刷新一次可能过期的画面，再取正式证据帧，预热图片不发送给模型或写附件。无交互检查不增加该步骤，不唤起桌面窗口。
- action=present（默认）：沿旧文件／多方案展示或新增内联代码卡交付；不重复截图。
- 截图继续使用现有附件格式、预算与保存入口；全部相位写入 tool_result.attachmentRefs，工具结果仅元数据，JSONL 无 Base64。历史图片仍按现有引用与预算恢复／重读，不复制到新的文件体系。
- 预览依旧 loopback 独立来源、sandbox allow-scripts，无应用 Bridge，工作区文件边界和原 CSP 保持。编译过程只生成浏览器脚本，不在 Main 执行用户组件。
- esbuild 原生程序及对应运行库按已有 ASAR 解包路径方式处理；原生／打包验证需实际编译，不能只验证开发环境。

截图是验收证据，不自动证明交互正确，必须核对动作后的实际状态；不得把一个静态画面说成动画或交互已经通过。

片段交互使用上述有界 actions；运行中的完整项目交互仍由 browser_control 处理。组件源码编译错误沿 ToolArgumentsError 返回 VALIDATION_FAILED、code 字段、行列与有界源码提示、fix_arguments 恢复说明；不是软件内部故障，不应原样重试。打包路径／二进制等真正的内部错误保留原分类。

## 验收记录（2026-10-19）

- 原数据目录、原项目及 local gpt-6.1-sol／中等思考，普通对话通过后台接口验收，不操作用户窗口。两轮短问答均只返回“你好”，无工具调用；最终第一轮实际 input=20,280（原 22,759，减少 10.9%），第二轮 input=20,304、cached=20,096（约 99.0%）。这是该样本的结果，不是通用节省／命中承诺。
- 快速排序四组数组在一次有限 Node.js 命令中全部通过；没有无意义任务／清单、子代理或文件操作。首轮曾因 Windows PowerShell 引号转发失败，修正指引后新对话一次成功，失败记录保留。
- React 计数／重置、Vue 待机／运行、原生 HTML/SVG 鹈鹕骑车通过真实模型与独立后台浏览器检查。React 5 次、Vue 6 次、最终 HTML 5 次工具执行均无失败；各只交付一个结果。最终 HTML 检查含多相位、窄屏和键盘暂停；独立检查再次验证三组交互、动画三个不同相位、暂停稳定／键盘继续、桌面及 390px 无横向溢出和运行错误、无外部依赖请求。
- 额外截图小样例连续 Tab／Enter／Space 后，两张正式图片及文本均为 2，白色配色保持。模型收到真实图片；正式附件独立落盘，JSONL 未包含图片 Base64。多相位截图复用原工具详情，检查不会被误当成最终交付卡。
- 另保留组件语法错误、失效临时网址和隐藏窗口截图滞后的发现记录：分别用结构化源码纠错、移除过期入口／同工具有界交互、交互后刷新过期画面处理。不把模型最初生成的语法错误或中断的实验当作无错误通过。
- JSX／TSX、Vue script setup／Options API／scoped CSS 的真实渲染、点击、320px 窄宽度，以及原预览卡的深浅主题和源码切换均检查。源码格式化后的 React 最终交付另外以实际产物重验，不冒称字节与先前检查完全相同。
- 原生及解包验证实际执行 React bundling、Vue SFC 编译和运行库 bundling，同时保留原 PTY、ripgrep、Renderer 检查；不是仅确认依赖安装成功。
- 最终自动回归：Desktop 1,375、Web 1,142、Protocol 245、脚本 19，共 2,781 项通过；lint、类型检查、构建、原生及解包验证通过。既有 jsdom Canvas 未实现提示不作为视觉证据，真实视觉与交互另用上述后台浏览器验证。

## 参考与取舍

- [OpenCode Skills](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/skills.mdx)：沿名称／描述目录与按需正文，不预先注入全部手册。
- [OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)：使用清晰类型、减少模型不必选择的参数，合并天然同时执行的操作；不盲目把不同生命周期合并。
- [OpenAI Tool Search](https://developers.openai.com/api/docs/guides/tools-tool-search)、[Anthropic Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)：支持延迟加载和程序化批次的方向。本项目多协议适配尚不能统一使用厂商原生 Tool Search，本轮优先收窄身份、精简首层并延迟手册，避免新增跨协议发现框架。
- [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)：保持工具定义／顺序及基础说明稳定，变化内容放后；改短前缀与维护前缀稳定性同时考虑。
